Lutasin ang maximum independent set na problema na mas marami ang variable kaysa sa qubit gamit ang SQOA Solver ng JIJ

tala

Ang IBM Quantum® Functions ay isang beta feature na available lang sa mga user ng IBM Quantum Premium Plan, Flex Plan, at On-Prem (sa pamamagitan ng IBM Quantum Platform API) Plan. Maaaring magbago ang mga beta feature.

Tantiya sa paggamit: 10 segundo sa isang Heron r2 processor. (TANDAAN: Tantiya lang ito. Maaaring iba ang runtime mo.)

Background​

Ipinapakita ng tutorial na ito kung paano gamitin ang SQOA Solver ng JIJ para lutasin ang isang maximum independent set (MIS) na problema na mas marami ang binary variable kaysa sa bilang ng qubit ng napiling QPU. Ang mga pangunahing hakbang ay: mag-load ng MIS instance mula sa Quantum Optimization Benchmarking Library (QOBLIB) [1], buuin ito sa quadratic unconstrained binary optimization (QUBO) form gamit ang qiskit-addon-opt-mapper, isumite ito sa SQOA Solver para patakbuhin sa isang IBM® QPU, at i-validate ang ibinalik na solusyon.

Ang maximum independent set na problema​

Ang independent set ay isang subset ng mga node sa isang graph kung saan walang dalawang napiling node na may pinagsasaluhang edge. Ang maximum independent set (MIS) ay isang independent set na may pinakamaraming posibleng node. Kabilang sa mga aplikasyon ng MIS ang scheduling, resource allocation, at network design.

Ang MIS ay NP-hard. Sa isang exhaustive search, dumodoble ang bilang ng mga subset na kailangang isaalang-alang sa bawat dagdag na node, kaya hindi praktikal ang pamamaraang ito kahit sa mga graph na katamtaman ang laki. Kasama ang MIS sa sampung klase ng problema ng QOBLIB, kaya isa itong kapaki-pakinabang na benchmark para suriin ang mga quantum optimization workflow sa totoong hardware.

Mathematical formulation​

Sa isang undirected graph na G=(V,E)G = (V, E)G=(V,E), magtalaga ng binary variable na xvx_vxv​ sa bawat node na vvv:

  • xv=1x_v = 1xv​=1 kung napili ang node na vvv.

  • xv=0x_v = 0xv​=0 otherwise.

Ang binary linear formulation ay ina-maximize ang bilang ng mga napiling node habang pinipigilang mapili ang magkabilang dulo ng alinmang edge:

max⁡x∑v∈Vxvsubject toxv+xw≤1∀(v,w)∈E,xv∈{0,1}∀v∈V.\begin{aligned} \max_{x} \quad & \sum_{v \in V} x_v \\ \text{subject to} \quad & x_v + x_w \leq 1 && \forall (v,w) \in E, \\ & x_v \in \{0,1\} && \forall v \in V. \end{aligned}xmax​subject to​v∈V∑​xv​xv​+xw​≤1xv​∈{0,1}​​∀(v,w)∈E,∀v∈V.​

Binibilang ng objective ang mga napiling node. Sama-sama, tinitiyak ng mga edge constraint na bumubuo ng independent set ang mga napiling node.

Ginagamit ng tutorial na ito ang binary unconstrained formulation ng QOBLIB, na pinapalitan ng mga quadratic penalty ang mga edge constraint:

max⁡x∈{0,1}∣V∣∑v∈Vxv−2∑(v,w)∈Exvxw.\max_{x \in \{0,1\}^{|V|}} \quad \sum_{v \in V} x_v - 2 \sum_{(v,w) \in E} x_v x_w.x∈{0,1}∣V∣max​v∈V∑​xv​−2(v,w)∈E∑​xv​xw​.

Tuwing napili ang magkabilang dulo ng isang edge, binabawasan ng ikalawang term ang objective ng dalawa. Dahil sa penalty na ito, mas hindi paborable ang magkasalungat na pagpili kaysa sa pagpili ng isa lang sa mga dulo. Ang resultang objective ay isang QUBO, na siyang input format na tinatanggap ng SQOA Solver.

Bakit gagamitin ang SQOA Solver?​

Maraming quantum optimization approach ang nagtatalaga ng isang qubit sa bawat binary variable, kaya ang kapasidad ng quantum hardware ay direktang maaaring maglimita sa laki ng problema. Pinagsasama ng SQOA Solver ang ilang reduction at hybrid-computing technique para pagaanin ang limitasyong ito:

  • Kaya nitong harapin ang mga problemang mas marami ang binary variable kaysa sa bilang ng qubit ng QPU. Ang presolve ay naglalapat ng mga reduction rule na kayang mag-fix ng mga variable at pasimplehin ang natitirang QUBO habang pinapanatili ang kahit isang optimal na solusyon. Ayon sa karanasan, maaari ring gawing mas sparse ng presolve ang natitirang QUBO, na nakakatulong sa QRAC-based na encoding na sumusunod dito.

    Pagkatapos, gumagamit ang solver ng QRAC-based na encoding na hinango mula sa Quantum Random Access Optimization (QRAO) [3] para katawanin ang maraming variable (hanggang tatlo) na walang direktang QUBO interaction sa iisang qubit.

    Nakadepende sa estruktura ng problema ang mga reduction mula sa presolve at encoding. Halimbawa, sa tutorial na ito, 67 qubit lang ang ginagamit ng isang problemang may 200 variable.

  • Maaari itong mas hindi sensitibo sa hardware noise. Ginagamit ng sample-based quantum diagonalization [4], [5] ang QPU para mag-sample ng mga bitstring pero classical ang paggawa ng diagonalization. Iniiwasan nito ang paulit-ulit na QPU evaluation para sa mga update ng variational parameter at maaaring bawasan ang epekto ng noise sa optimization workflow.

  • Ina-automate nito ang workflow mula presolve hanggang post-processing. Magbibigay ka ng wastong naka-format na QUBO instance at pipili ng backend. Pagkatapos, awtomatikong patatakbuhin ng SQOA Solver ang buong workflow. Naglalapat ito ng presolve, imamapa ang mga classical variable sa isang relaxed na quantum problem, bubuuin at ita-transpile ang mga sampling circuit, magsasagawa ng quantum sampling at classical diagonalization, magro-round at magre-refine ng assignment, at muling bubuuin at susuriin ang classical na solusyon.

Setup​

Una, i-import ang mga kinakailangang package at tool.

Tinatanggap ng SQOA Solver ang isang QUBO na problema bilang coefficient dictionary sa tuple-string format na ginagamit ng mga optimization function ng IBM®. Magdefine ng helper function na kino-convert ang QUBO na ibinalik ng OptimizationProblemToQubo sa format na ito.

Laging minimization na problema ang ibinabalik ng converter, na tugma sa kung paano tinatrato ng SQOA Solver ang isang dictionary na problema. Gumagamit ang mga key ng mga variable index ng QUBO, at bawat variable ay may linear entry, kahit zero ang coefficient, para masaklaw ng ibinalik na solusyon ang lahat ng variable.

def to_problem_dict(qubo: OptimizationProblem) -> dict[str, float]:
    """Convert a QUBO from OptimizationProblemToQubo to the SQOA Solver dictionary format."""
    objective = qubo.objective
    payload = {"()": objective.constant}
    # Keep every variable in the problem, even with a zero linear coefficient.
    payload.update({f"({i},)": 0.0 for i in range(qubo.get_num_vars())})
    for i, coefficient in objective.linear.to_dict().items():
        payload[f"({i},)"] += coefficient
    for (i, j), coefficient in objective.quadratic.to_dict().items():
        # Fold a binary diagonal term x_i * x_i = x_i into the linear term.
        key = f"({i},)" if i == j else f"({i}, {j})"
        payload[key] = payload.get(key, 0.0) + coefficient
    return {key: float(value) for key, value in payload.items()}

Hakbang 1: I-map ang mga classical input sa isang quantum na problema​

Tinatanggap ng SQOA Solver ang isang QUBO na problema at ginagawa ang quantum mapping sa loob ng function. Sa tutorial na ito, magda-download ka ng MIS instance mula sa QOBLIB at bubuuin ito bilang QUBO gamit ang qiskit-addon-opt-mapper. Saklaw ng hakbang na ito ang mga sumusunod:

  • Kumonekta sa SQOA Solver.

  • Unawain ang SQOA framework.

  • I-load ang problem instance.

  • Buuin ang QUBO at i-convert ito para sa pagsusumite.

Unawain ang SQOA framework​

Pinagsasama ng Sampling-based Quantum Optimization Algorithm with Quantum Relaxation (SQOA-QR) [2] ang Quantum Random Access Optimization (QRAO) at sample-based quantum diagonalization:

  1.     kung saan ang III ay ang identity operator, itinatalaga ng f(i)f(i)f(i) ang variable na iii sa isang qubit at sa isa sa XXX, YYY, o ZZZ, at ang ki∈{1,2,3}k_i \in \{1,2,3\}ki​∈{1,2,3} ay ang bilang ng mga variable na naka-map sa parehong qubit ng iii.     Ang mga variable na nagbabahagi ng qubit ay itinatalaga ng magkakaibang noncommuting na Pauli observable. Ang mga variable na may interaction sa QUBO ay inilalagay sa magkakaibang qubit, habang ang mga variable na walang direktang QUBO interaction ay maaaring magbahagi ng qubit. Kaya nakadepende sa estruktura ng problema ang pagbawas sa bilang ng qubit.

  2. Quantum sampling: Nagsa-sample ang isang quantum processor ng mga bitstring mula sa mga circuit na dinisenyo para tuklasin ang mga low-energy state ng relaxed Hamiltonian.

  3. Sample-based diagonalization: Ipinoproject ng solver ang relaxed Hamiltonian sa subspace na sakop ng mga basis state na nakuha mula sa mga na-sample na bitstring at dina-diagonalize ang na-project na Hamiltonian nang classical [4], [5]. Para sa isang nakapirming set ng mga na-sample na bitstring, hayaang ang Sr\mathcal{S}_rSr​ ay ang subspace na sakop ng rrr magkakaibang basis state, kaya dim⁡(Sr)≤r\dim(\mathcal{S}_r) \leq rdim(Sr​)≤r. Ang tinatayang ground-state energy nito ay:

    Er=min⁡∣ψ⟩∈Sr⟨ψ∣ψ⟩=1⟨ψ∣H~∣ψ⟩,Sr⊆Sr′⟹Eexact≤Er′≤Er(r′≥r),E_r = \min_{\substack{|\psi\rangle \in \mathcal{S}_r \\ \langle\psi|\psi\rangle=1}} \langle\psi|\widetilde{H}|\psi\rangle, \qquad \mathcal{S}_r \subseteq \mathcal{S}_{r'} \Longrightarrow E_{\mathrm{exact}} \leq E_{r'} \leq E_r \quad (r' \geq r),Er​=∣ψ⟩∈Sr​⟨ψ∣ψ⟩=1​min​⟨ψ∣H∣ψ⟩,Sr​⊆Sr′​⟹Eexact​≤Er′​≤Er​(r′≥r),

    kung saan ang EexactE_{\mathrm{exact}}Eexact​ ay ang ground-state energy ng buong relaxed Hamiltonian. Kaya, hindi maaaring pataasin ng mas malaking pinanatiling subspace ang tinatayang ground-state energy.

    Ipinapalagay ng pagkakasunod-sunod na ito ang parehong sampling result at tungkol ito sa energy ng relaxed Hamiltonian bago mag-rounding. Hindi nito teoretikal na ginagarantiyahan ang mas mahusay na ibinalik na classical na solusyon. Gayunpaman, sa QRAO, heuristikong inaasahan na ang mas mababang-energy na state ay magbibigay ng mas mahusay na classical na solusyon.

  4. Rounding: Ang relaxed state na nakuha mula sa diagonalization ay kino-convert sa isang classical na binary assignment.

Binabalutan ng SQOA Solver ang framework na ito ng classical processing. Bago ang quantum mapping, naglalapat ang presolve ng mga reduction rule na kayang mag-fix ng mga variable at pasimplehin ang natitirang QUBO habang pinapanatili ang kahit isang optimal na solusyon. Pagkatapos ng diagonalization at rounding, nire-refine ng isang classical local search ang assignment, at binubuo muli at sinusuri ng OMMX ang kumpletong solusyon.

I-load ang instance​

Ipinamamahagi ng QOBLIB ang bawat MIS instance bilang graph sa DIMACS .gph format, isang line-based na format kung saan ang linyang nagsisimula sa p ay nagbibigay ng bilang ng mga node at edge at ang bawat linyang nagsisimula sa e ay nagdedefine ng isang edge.

Naglalathala rin ang QOBLIB ng optimal o best-known na reference solution para sa bawat instance. Dina-download ng mga sumusunod na function ang dalawa mula sa QOBLIB repository. Nagsisimula sa 1 ang pag-label ng DIMACS sa mga node, kaya nire-relabel ang graph para magsimula sa 0.

Kung gusto mong magsimula sa sarili mong graph, laktawan ang download at buuin ang problema mula sa iyong NetworkX graph sa parehong paraan.

QOBLIB_URL = "https://raw.githubusercontent.com/ZIB-AOPT/QOBLIB/refs/heads/main/07-independentset"

def fetch_qoblib_graph(name: str) -> nx.Graph:
    """Download a QOBLIB independent-set instance as a NetworkX graph."""
    with urllib.request.urlopen(
        f"{QOBLIB_URL}/instances/{name}.gph"
    ) as response:
        lines = response.read().decode().splitlines()
    graph = nx.Graph()
    for fields in map(str.split, lines):
        if fields and fields[0] == "p":
            # Header: p edge <number of nodes> <number of edges>
            graph.add_nodes_from(range(int(fields[2])))
        elif fields and fields[0] == "e":
            # DIMACS labels nodes from 1; relabel them to start from 0.
            graph.add_edge(int(fields[1]) - 1, int(fields[2]) - 1)
    return graph

def fetch_reference_objective(name: str) -> float:
    """Read the objective value of the QOBLIB reference solution."""
    with urllib.request.urlopen(
        f"{QOBLIB_URL}/solutions/{name}.opt.sol"
    ) as response:
        for line in response.read().decode().splitlines():
            if line.startswith("# Objective value"):
                return float(line.split("=")[1])
    raise ValueError(f"No objective value found for {name}.")

Buuin ang QUBO​

Buuin ang binary linear formulation mula sa seksyong Background bilang isang OptimizationProblem na may isang binary variable kada node, isang objective na bumibilang sa mga napiling node, at isang constraint kada edge. Pagkatapos, i-convert ito gamit ang OptimizationProblemToQubo.

Sa penalty weight na 2, pinapalitan ng converter ang bawat edge constraint ng penalty term na 2xvxw2 x_v x_w2xv​xw​ at ginagawang minimization ang maximization, kaya ang na-convert na problema ay ang binary unconstrained formulation ng QOBLIB na may baligtad na sign. Ang mga variable index ng QUBO ay ang mga label ng node ng graph. Ang IndependentSet application class sa qiskit_addon_opt_mapper.applications ay bumubuo ng parehong constrained model gamit ang IndependentSet(G).to_optimization_problem().

Panghuli, i-convert ang QUBO sa dictionary format gamit ang to_problem_dict(). Dahil binary QUBO ang problema, idineklara ng request sa Hakbang 2 ang variable domain nito bilang "binary". Ginagawa ng function ang presolve, quantum mapping, at circuit construction pagkatapos ng pagsusumite.

mis = OptimizationProblem(INSTANCE_NAME)
mis.binary_var_list(G.number_of_nodes(), name="x")
mis.maximize(linear={v: 1 for v in G.nodes})
for u, v in G.edges:
    mis.linear_constraint({u: 1, v: 1}, "<=", 1)

converter = OptimizationProblemToQubo(penalty=2)
qubo = converter.convert(mis)
problem_dict = to_problem_dict(qubo)

Hakbang 2: I-optimize ang problema para sa pagpapatakbo sa quantum hardware​

Ginagawa ng SQOA Solver ang quantum mapping at paghahanda ng hardware sa loob ng function. Una nitong inilalapat ang presolve sa QUBO, tapos imamapa ang natitirang mga variable sa isang relaxed Hamiltonian gamit ang QRAC-based na encoding.

Para sa quantum sampling, bumubuo ito ng mga circuit batay sa relaxed Hamiltonian at tina-transpile ang mga ito para sa napiling backend. Nakadepende sa problema ang pagbawas sa laki ng problema at bilang ng qubit mula sa presolve at encoding, kaya i-configure ang solver nang hindi ipinapalagay ang nakapirming reduction factor.

I-configure ang mga input ng solver​

Nangangailangan ang SQOA Solver ng dalawang input:

  • problem, ang dictionary mula sa Hakbang 1.

  • variable_type, na "binary" para sa QUBO na ito.

Tumatanggap din ito ng dalawang opsyonal na input:

  • Pinipili ng backend_name ang QPU. Kapag hindi ito ibinigay o None, pinipili ng function ang pinakakaunting abalang operational na QPU na ma-a-access ng iyong instance.

  • Ang options ay isang dictionary na kumokontrol sa sampling budget (shots), sa classical seed (seed), sa paggamit ng session (session), sa classical local search (postprocessing_level), at sa mga job tag (job_tags). Kung dadagdagan mo ang shots, maaaring gumanda ang sampling statistics.

Pinipili ng argument na function_size ("S", "M", o "L") ang mga computing resource para sa job at direktang ipinapasa sa solver.run(), sa labas ng options. Kalkulahin ito mula sa problema bago magsumite, tulad ng ipinapakita sa susunod na seksyon.

Para sa lahat ng input, sa mga default na halaga nito, at sa mga validation rule, tingnan ang API reference.

Tahasang pinangalanan ng tutorial na ito ang backend, ginagamit ang mga default na halaga para sa shots, session, at postprocessing_level, at itinatakda ang classical seed. Ipunin ang mga input sa isang dictionary para maipasa mo ang mga ito sa solver.run() sa Hakbang 3.

# ibm_fez has 156 qubits
backend_name = (
    "ibm_fez"  # Omit this key or pass None for automatic selection.

sqoa_input = {
    "problem": problem_dict,
    "variable_type": "binary",
    "backend_name": backend_name,

    "seed": 42,
    "session": False,
    "postprocessing_level": 1,

Kalkulahin ang laki ng function​

Nakadepende ang laki ng function sa bilang ng mga variable sa QUBO at sa density nito, ang bahagi ng mga pares ng variable na nag-i-interact. Para sa pamantayan ng bawat laki, tingnan ang Function sizes sa SQOA Solver guide. Ginagawa ng sumusunod na calculator ang parehong kalkulasyon ng function, nang hindi nagsa-submit ng job.

# Calculate the function size a problem needs, before submitting it.
# calculate_function_size(problem) returns "S", "M", or "L" and submits
# nothing. The size comes from the number of variables and how densely
# they interact.

from collections.abc import Iterator
from itertools import combinations
from typing import Any, Literal

from qiskit_addon_opt_mapper.problems import OptimizationProblem

Size = Literal["S", "M", "L"]
_ORDER = {"S": 0, "M": 1, "L": 2}

# Limits are provided by IBM
_SMALL_NUMVARS, _SMALL_DENSITY = 50, 0.1
_MEDIUM_NUMVARS, _MEDIUM_DENSITY = 100, 0.25

def calculate_function_size(problem: Any, **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") needed to run ``problem``."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def to_optimization_problem(problem: Any) -> OptimizationProblem:
    """Convert SQOA input into an ``OptimizationProblem``.

    Accept an OMMX ``Instance`` directly, or a dictionary containing a coefficient
    dictionary as ``problem`` and ``"binary"`` or ``"spin"`` as ``variable_type``.
    Convert to a binary minimization problem with consecutive variable IDs from zero.
    Leave the input instance unchanged.
    Return an existing ``OptimizationProblem`` unchanged.
    """
    if isinstance(problem, OptimizationProblem):
        return problem
    import ast
    import math
    import re

    from ommx.v1 import DecisionVariable, Instance, Kind

    _TERM_ID = r"(?:0|[1-9][0-9]*)"
    _TERM_SPACE = r"[ \t\r\n]*"
    _TERM_KEY_PATTERN = (
        rf"^\({_TERM_SPACE}(?:{_TERM_ID}{_TERM_SPACE},"
        rf"{_TERM_SPACE}(?:{_TERM_ID}{_TERM_SPACE}(?:,{_TERM_SPACE})?)?)?\)(?![\s\S])"
    )

    def _term_ids(key: str) -> tuple[int, ...]:
        if (
            not isinstance(key, str)
            or re.fullmatch(_TERM_KEY_PATTERN, key) is None
        ):
            raise ValueError("invalid term key")
        ids = ast.literal_eval(key)
        if len(set(ids)) != len(ids):
            raise ValueError("repeated variable ID")
        return tuple(sorted(ids))

    def _dictionary_to_instance(
        problem: dict[str, object], variable_type: str
    ) -> Instance:
        terms: dict[tuple[int, ...], float] = {}
        variable_ids: set[int] = set()
        for key, value in problem.items():
            ids = _term_ids(key)
            if type(value) not in (int, float):
                raise ValueError("invalid coefficient")
            coefficient = float(value)
            if not math.isfinite(coefficient):
                raise ValueError("invalid coefficient")
            variable_ids.update(ids)
            terms[ids] = terms.get(ids, 0.0) + coefficient
            if not math.isfinite(terms[ids]):
                raise ValueError("coefficient overflow")
        variables = {
            i: DecisionVariable.binary(i) for i in sorted(variable_ids)
        }
        expressions = {
            i: 1 - 2 * variable if variable_type == "spin" else variable
            for i, variable in variables.items()
        }
        objective = 0.0
        for ids, coefficient in terms.items():
            term = coefficient
            for i in ids:
                term = term * expressions[i]
            objective = objective + term
        return Instance.from_components(
            decision_variables=list(variables.values()),
            objective=objective,
            constraints=[],
            sense=Instance.MINIMIZE,
        )

    if isinstance(problem, Instance):
        instance = problem
    else:
        if (
            not isinstance(problem, dict)
            or not {"problem", "variable_type"} <= problem.keys()
        ):
            raise ValueError(
                "SQOA sizing requires an OMMX Instance or a coefficient input envelope "
                "with 'problem' and 'variable_type'"
            )
        variable_type = problem["variable_type"]
        if variable_type not in ("binary", "spin"):
            raise ValueError("variable_type must be binary or spin")
        if not isinstance(problem["problem"], dict):
            raise ValueError(
                "problem must be a coefficient dictionary; pass OMMX Instances directly"
            )
        instance = _dictionary_to_instance(problem["problem"], variable_type)

    variables = list(instance.decision_variables)
    degree = instance.objective.degree()
    if not variables:
        raise ValueError(
            "problem must contain at least one decision variable"
        )
    if any(variable.kind == Kind.Continuous for variable in variables):
        raise ValueError(
            "problem must not contain Continuous decision variables"
        )
    if degree > 2:
        raise ValueError("problem objective degree must be at most two")
    # Copy the instance so minimization does not modify the caller's original.
    normalized = Instance.from_bytes(instance.to_bytes())
    normalized.as_minimization_problem()
    qubo, offset = normalized.as_qubo_format()
    if not math.isfinite(offset) or any(
        not math.isfinite(v) for v in qubo.values()
    ):
        raise ValueError("problem objective coefficients must all be finite")

    ids = [variable.id for variable in variables]
    dense_ids = {
        variable_id: index for index, variable_id in enumerate(sorted(ids))
    }
    linear = {}
    quadratic = {}
    for (first, second), coefficient in qubo.items():
        i, j = dense_ids[first], dense_ids[second]
        if i == j:
            linear[i] = linear.get(i, 0.0) + coefficient
        else:
            pair = (min(i, j), max(i, j))
            quadratic[pair] = quadratic.get(pair, 0.0) + coefficient

    model = OptimizationProblem()
    model.binary_var_list(len(ids), name="x")
    model.minimize(
        constant=offset,
        linear=linear,
        quadratic=quadratic,
    )
    return model

def _measure(problem: Any, **kwargs: Any) -> dict[str, float]:
    """Return the number of variables and the interaction density."""
    model = to_optimization_problem(problem)
    num_vars = model.get_num_vars()

    pairs = set()
    for term in _interactions(model):
        pairs.update(frozenset(pair) for pair in combinations(set(term), 2))

    max_pairs = num_vars * (num_vars - 1) // 2
    return {
        "num_vars": num_vars,
        "density": len(pairs) / max_pairs if max_pairs else 0.0,
    }

def _interactions(problem: OptimizationProblem) -> Iterator[tuple[int, ...]]:
    """Yield the variables of every term that couples two or more of them.

    A constraint contributes every variable in it, because on hardware it becomes
    a penalty whose square couples them all.
    """
    objective = problem.objective
    yield from objective.quadratic.to_dict()
    for expression in objective.higher_order.values():
        yield from expression.to_dict()

    for constraint in problem.linear_constraints:
        yield _constraint_support(constraint)
    for constraint in problem.quadratic_constraints:
        yield _constraint_support(constraint)
    for constraint in problem.higher_order_constraints:
        yield _constraint_support(constraint)

def _constraint_support(constraint: Any) -> tuple[int, ...]:
    """Return every variable appearing in a constraint's left-hand side."""
    variables = set(constraint.linear.to_dict())
    if hasattr(constraint, "quadratic"):
        for term in constraint.quadratic.to_dict():
            variables.update(term)
    if hasattr(constraint, "higher_order"):
        for expression in constraint.higher_order.values():
            for term in expression.to_dict():
                variables.update(term)
    return tuple(variables)

def _is_small(metrics: dict[str, float]) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return (
        metrics["num_vars"] <= _SMALL_NUMVARS
        and metrics["density"] <= _SMALL_DENSITY
    )

def _is_medium(metrics: dict[str, float]) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return (
        metrics["num_vars"] <= _MEDIUM_NUMVARS
        and metrics["density"] <= _MEDIUM_DENSITY
    )

Konklusyon​

Sa tutorial na ito, nag-download ka ng MIS instance mula sa QOBLIB, ginawa itong QUBO gamit ang qiskit-addon-opt-mapper, kumonekta sa SQOA Solver, kinonfigure at isinumite ang workload, imina-map pabalik sa graph ang ibinalik na assignment, at tiningnan ang mga napiling node laban sa orihinal na graph.

Inihambing mo rin ang resulta sa reference solution ng QOBLIB, sinuri ang kontribusyon ng classical post-processing, at siniyasat ang resource usage ng bawat execution phase.

Pinagsasama ng SQOA Solver ang presolve, QRAO na may QRAC-based na encoding, pagbuo ng sampling circuit, hardware-aware na transpilation, sample-based na diagonalization, rounding, at classical refinement. Kaya ng workflow na ito na mag-map ng mas maraming binary variable kaysa sa papayagan ng one-variable-per-qubit na encoding. Ang laki ng pagbawas mula sa presolve at encoding ay nakadepende sa istruktura ng problema, at ang kalidad ng solusyon ay nakadepende sa nakuhang mga sample.

Kinokontrol ng mga setting na shots at postprocessing_level ang quantum sampling budget at ang classical refinement, ayon sa pagkakasunod, nang hindi binabago ang submission workflow.

Appendix: Isumite ang problema bilang OMMX instance​

Tumatanggap din ang SQOA Solver ng ommx.v1.Instance mula sa OMMX SDK. Ang package na OMMX Quantum Benchmarks ay nagdi-distribute ng mga problema ng QOBLIB bilang OMMX instance kasama ang kanilang mga reference solution, kaya mailo-load mo ang parehong QUBO nang hindi mo ito kailangang i-formulate.

Sa OMMX input, ang objective_value ay sinusuri ayon sa kahulugan ng instance, at naglalaman din ang resulta ng canonical na ommx.v1.Solution. I-install ang package, na nag-i-install din ng OMMX SDK:

# %pip install ommx-quantum-benchmarks

I-load ang binary_unconstrained model ng parehong instance. Nagpi-print ng mga progress message ang dataset loader, kaya kinukuha ng code ang mga ito para manatiling compact ang output.

%%capture
from ommx_quantum_benchmarks.qoblib import IndependentSet

ommx_instance, _ = IndependentSet()("binary_unconstrained", INSTANCE_NAME)

Tumatanggap ang SQOA Solver ng OMMX instance bilang standard padded Base64 string at ibinabalik ang canonical solution sa parehong format. Tumukoy ng dalawang helper function para sa conversion na ito:

  • Sina-serialize ng to_problem_payload() ang isang ommx.v1.Instance tungo sa string na ipapasa mo bilang problem.

  • Dine-decode ng to_ommx_solution() ang canonical na ommx.v1.Solution mula sa resulta.

import base64

from ommx.v1 import Instance, Solution

def to_problem_payload(instance: Instance) -> str:
    """Serialize an OMMX instance into the `problem` string for SQOA Solver."""
    return base64.b64encode(instance.to_bytes()).decode()

def to_ommx_solution(result: dict) -> Solution:
    """Decode the canonical OMMX solution from a SQOA Solver result."""
    payload = result["metadata"]["solver_info"]["ommx_solution"]
    return Solution.from_bytes(base64.b64decode(payload, validate=True))

Isumite ang instance gamit ang parehong mga input tulad ng dati, problem lang ang papalitan. Pagkatapos, i-decode ang canonical solution at basahin ang mga napiling node ayon sa pangalan ng variable.
