Mga stabilizer code

Ngayon ay tukuyin natin ang mga stabilizer code sa pangkalahatan. Tatalakayin din natin ang ilan sa kanilang mga pangunahing katangian at kung paano sila gumagana, kasama na kung paano ma-encode ang mga estado at kung paano natutuklas at naitatama ang mga error gamit ang mga code na ito.

Kahulugan ng mga stabilizer code​

Ang isang nnn-qubit stabilizer code ay tinutukoy ng isang listahan ng nnn-qubit na mga Pauli operation, P1,…,Pr.P_1,\ldots,P_r.P1​,…,Pr​. Ang mga operation na ito ay tinatawag na mga stabilizer generator sa kontekstong ito, at dapat nilang matugunan ang sumusunod na tatlong katangian.

  1. Ang lahat ng stabilizer generator ay commute sa isa't isa.

    PjPk=PkPj(para sa lahat ng j,k∈{1,…,r})P_j P_k = P_k P_j \qquad \text{(para sa lahat ng $j,k\in\{1,\ldots,r\}$)}Pj​Pk​=Pk​Pj​(para sa lahat ng j,k∈{1,…,r})

  2. Ang mga stabilizer generator ay bumubuo ng isang minimal generating set.

    Pk∉⟨P1,…,Pk−1,Pk+1,…,Pr⟩(para sa lahat ng k∈{1,…,r})P_k \notin \langle P_1,\ldots,P_{k-1},P_{k+1},\ldots,P_r\rangle \qquad \text{(para sa lahat ng $k\in\{1,\ldots,r\}$)}Pk​∈/⟨P1​,…,Pk−1​,Pk+1​,…,Pr​⟩(para sa lahat ng k∈{1,…,r})

  3. May hindi bababa sa isang quantum state vector na naayos ng lahat ng stabilizer generator.

    −I⊗n∉⟨P1,…,Pr⟩-\mathbb{I}^{\otimes n} \notin \langle P_1,\ldots, P_r\rangle−I⊗n∈/⟨P1​,…,Pr​⟩

    (Hindi agad malinaw na ang pag-iral ng isang quantum state vector na ∣ψ⟩\vert\psi\rangle∣ψ⟩ na naayos ng lahat ng stabilizer generator, ibig sabihin P1∣ψ⟩=⋯=Pr∣ψ⟩=∣ψ⟩,P_1 \vert\psi\rangle = \cdots = P_r \vert\psi\rangle = \vert\psi\rangle,P1​∣ψ⟩=⋯=Pr​∣ψ⟩=∣ψ⟩, ay katumbas ng −I⊗n∉⟨P1,…,Pr⟩,-\mathbb{I}^{\otimes n} \notin \langle P_1,\ldots, P_r\rangle,−I⊗n∈/⟨P1​,…,Pr​⟩, ngunit totoong ganito ang kaso, at makikita natin kung bakit sa bandang huli ng aralin.)

Kung mayroon tayong ganoong listahan na P1,…,Pr,P_1,\ldots,P_r,P1​,…,Pr​, ang code space na tinukoy ng mga stabilizer generator na ito ay ang subspace na C\mathcal{C}C na naglalaman ng bawat nnn-qubit quantum state vector na naayos ng lahat ng rrr na stabilizer generator na ito.

C={∣ψ⟩ : P1∣ψ⟩=⋯=Pr∣ψ⟩=∣ψ⟩}\mathcal{C} = \bigl\{ \vert\psi\rangle \,:\, P_1 \vert\psi\rangle = \cdots = P_r \vert\psi\rangle = \vert\psi\rangle \bigr\}C={∣ψ⟩:P1​∣ψ⟩=⋯=Pr​∣ψ⟩=∣ψ⟩}

Ang mga quantum state vector sa subspace na ito ay eksakto ang mga maaaring ituring bilang mga wastong encoding ng mga quantum estado. Tatalakayin natin ang aktwal na proseso ng pag-encode sa bandang huli.

Sa wakas, ang stabilizer ng code na tinukoy ng mga stabilizer generator na P1,…,PrP_1, \ldots, P_rP1​,…,Pr​ ay ang set na binuo ng mga operation na ito:

⟨P1,…,Pr⟩.\langle P_1,\ldots,P_r\rangle.⟨P1​,…,Pr​⟩.

Ang natural na paraan upang isipin ang isang stabilizer code ay ang tingnan ang mga stabilizer generator bilang mga observable, at kolektibong bigyang-kahulugan ang mga resulta ng mga sukat na nauugnay sa mga observable na ito bilang isang error syndrome. Ang mga wastong encoding ay nnn-qubit quantum state vector kung saan ang mga resulta ng sukat, bilang mga eigenvalue, ay garantisadong +1+1+1 lahat. Ang anumang iba pang syndrome, kung saan may kahit isang −1-1−1 na resulta ng sukat, ay nagpapahiwatig na natuklas ang isang error.

Titingnan natin ang ilang halimbawa sa lalong madaling panahon, ngunit una ay ilang komento tungkol sa tatlong kondisyon sa mga stabilizer generator ang nararapat.

Ang unang kondisyon ay natural, sa liwanag ng interpretasyon ng mga stabilizer generator bilang mga observable, dahil ipinahihiwatig nito na hindi mahalaga kung sa anong pagkakasunod-sunod ginaganap ang mga sukat: ang mga observable ay commute, kaya ang mga sukat ay commute rin. Ang ito ay natural na nagpapataw ng ilang algebraic na hadlang sa mga stabilizer code na mahalaga sa kung paano sila gumagana.

Ang pangalawang kondisyon ay nangangailangan na ang mga stabilizer generator ay bumubuo ng isang minimal generating set, ibig sabihin, ang pag-aalis ng kahit isa sa kanila ay magreresulta sa isang mas maliit na stabilizer. Sa mahigpit na pagsasalita, ang kondisyong ito ay hindi talagang mahalaga sa paraan ng paggana ng mga stabilizer code sa isang operasyonal na kahulugan — at, tulad ng makikita natin sa susunod na aralin, minsan ay may saysay na pag-isipan ang mga set ng stabilizer generator para sa mga code na hindi aktwal na natutugunan ang kondisyong ito. Para sa kapakanan ng pagsusuri ng mga stabilizer code at pagpapaliwanag ng kanilang mga katangian, gayunpaman, ipagpapalagay natin na ang kondisyong ito ay nasa lugar. Sa madaling salita, tinitiyak ng kondisyong ito na ang bawat observable na sinusukat natin upang makuha ang error syndrome ay nagdadagdag ng impormasyon tungkol sa mga posibleng error, sa halip na maging redundante at gumagawa ng mga resulta na maaaring mahiwatig mula sa iba pang mga sukat ng stabilizer generator.

Ang ikatlong kondisyon ay nangangailangan na hindi bababa sa isang nonzero na vector ay naayos ng lahat ng stabilizer generator, na katumbas ng −I⊗n-\mathbb{I}^{\otimes n}−I⊗n na hindi nakapaloob sa stabilizer. Ang pangangailangan para sa kondisyong ito ay nagmumula sa katotohanang posible talaga ang pumili ng isang minimal generating set ng nnn-qubit na mga Pauli operation na lahat ay commute sa isa't isa, gayunpaman walang nonzero na vector ang naayos ng bawat isa sa mga operation. Hindi tayo interesado sa mga "code" na walang wastong encoding, kaya itinatanggal natin ang posibilidad na ito sa pamamagitan ng pag-aatas ng kondisyong ito bilang bahagi ng kahulugan.

Mga halimbawa​

Narito ang ilang halimbawa ng mga stabilizer code para sa maliliit na halaga ng n.n.n. Makikita natin ang higit pang mga halimbawa, kasama na ang mga kung saan ang nnn ay maaaring mas malaki, sa susunod na aralin.

3-bit repetition code​

Ang 3-bit repetition code ay isang halimbawa ng isang stabilizer code, kung saan ang ating mga stabilizer generator ay Z⊗Z⊗IZ \otimes Z \otimes \mathbb{I}Z⊗Z⊗I at I⊗Z⊗Z.\mathbb{I} \otimes Z \otimes Z.I⊗Z⊗Z.

Madali nating masusuri na ang dalawang stabilizer generator na ito ay natutugunan ang mga kinakailangang kondisyon. Una, ang dalawang stabilizer generator na Z⊗Z⊗IZ \otimes Z \otimes \mathbb{I}Z⊗Z⊗I at I⊗Z⊗Z\mathbb{I} \otimes Z \otimes ZI⊗Z⊗Z ay commute sa isa't isa.

(Z⊗Z⊗I)(I⊗Z⊗Z)=Z⊗I⊗Z=(I⊗Z⊗Z)(Z⊗Z⊗I)(Z \otimes Z \otimes \mathbb{I})(\mathbb{I} \otimes Z \otimes Z) = Z \otimes \mathbb{I} \otimes Z = (\mathbb{I} \otimes Z \otimes Z)(Z \otimes Z \otimes \mathbb{I})(Z⊗Z⊗I)(I⊗Z⊗Z)=Z⊗I⊗Z=(I⊗Z⊗Z)(Z⊗Z⊗I)

Pangalawa, mayroon tayong minimal generating set (medyo maliwanag sa kasong ito).

At pangatlo, alam na natin na ang ∣000⟩\vert 000\rangle∣000⟩ at ∣111⟩,\vert 111\rangle,∣111⟩, pati na rin ang anumang linear na kombinasyon ng mga vector na ito, ay naayos ng parehong Z⊗Z⊗IZ \otimes Z \otimes \mathbb{I}Z⊗Z⊗I at I⊗Z⊗Z.\mathbb{I} \otimes Z \otimes Z.I⊗Z⊗Z. Bilang alternatibo, maaari nating tapusin ito gamit ang katumbas na kondisyon mula sa kahulugan.

−I⊗I⊗I∉⟨Z⊗Z⊗I,I⊗Z⊗Z⟩={I⊗I⊗I,Z⊗Z⊗I,Z⊗I⊗Z,I⊗Z⊗Z}-\mathbb{I}\otimes\mathbb{I}\otimes\mathbb{I}\notin \langle Z \otimes Z \otimes \mathbb{I}, \mathbb{I} \otimes Z \otimes Z\rangle = \{ \mathbb{I}\otimes\mathbb{I}\otimes\mathbb{I}, Z\otimes Z\otimes\mathbb{I}, Z\otimes\mathbb{I}\otimes Z, \mathbb{I}\otimes Z\otimes Z \}−I⊗I⊗I∈/⟨Z⊗Z⊗I,I⊗Z⊗Z⟩={I⊗I⊗I,Z⊗Z⊗I,Z⊗I⊗Z,I⊗Z⊗Z}

Ang mga kondisyong ito ay maaaring maging mas mahirap suriin para sa mas kumplikadong mga stabilizer code.

Binagong 3-bit repetition code​

Sa nakaraang aralin, nakita natin na posible ang baguhin ang 3-bit repetition code upang maprotektahan laban sa mga phase-flip error sa halip na mga bit-flip error. Bilang isang stabilizer code, ang bagong code na ito ay madaling ilarawan: ang mga stabilizer generator nito ay X⊗X⊗IX \otimes X \otimes \mathbb{I}X⊗X⊗I at I⊗X⊗X.\mathbb{I} \otimes X \otimes X.I⊗X⊗X.

Sa pagkakataong ito ang mga stabilizer generator ay kumakatawan sa mga X⊗XX\otimes XX⊗X observable sa halip na mga Z⊗ZZ\otimes ZZ⊗Z observable, kaya sila ay mahalagang mga parity check sa plus/minus basis sa halip na sa standard basis. Ang tatlong kinakailangang kondisyon sa mga stabilizer generator ay madaling mapatunayan, sa katulad na paraan tulad ng sa ordinaryong 3-bit repetition code.

7-qubit Steane code​

Narito ang isa pang halimbawa ng isang stabilizer code, na kilala bilang 7-qubit Steane code. Mayroon itong ilang kapansin-pansing katangian, at babalik tayo sa code na ito paminsan-minsan sa natitirang mga aralin ng kurso.

ZZZZIIIZZIIZZIZIZIZIZXXXXIIIXXIIXXIXIXIXIX\begin{array}{ccccccc} Z & Z & Z & Z & \mathbb{I} & \mathbb{I} & \mathbb{I} \\[1mm] Z & Z & \mathbb{I} & \mathbb{I} & Z & Z & \mathbb{I} \\[1mm] Z & \mathbb{I} & Z & \mathbb{I} & Z & \mathbb{I} & Z \\[1mm] X & X & X & X & \mathbb{I} & \mathbb{I} & \mathbb{I} \\[1mm] X & X & \mathbb{I} & \mathbb{I} & X & X & \mathbb{I} \\[1mm] X & \mathbb{I} & X & \mathbb{I} & X & \mathbb{I} & X \end{array}ZZZXXX​ZZIXXI​ZIZXIX​ZIIXII​IZZIXX​IZIIXI​IIZIIX​

Sa ngayon, obserbahan lamang natin na ito ay isang wastong stabilizer code. Malinaw na nag-commute ang unang tatlong stabilizer generator sa isa't isa, dahil ang ZZZ ay nag-commute sa sarili nito at ang identity ay nag-commute sa lahat, at katulad ang sitwasyon para sa huling tatlong stabilizer generator. Nananatili pang suriin na kung kukuha tayo ng isa sa mga ZZZ-stabilizer generator (ibig sabihin, isa sa mga unang tatlo) at isa sa mga XXX-stabilizer generator (ibig sabihin, isa sa mga huling tatlo), ang dalawang generator na ito ay nag-commute, at maaaring suriin ang 9 na posibleng pares upang patunayan iyon. Sa lahat ng kasong ito, ang isang XXX at isang ZZZ na Pauli matrix ay palaging nakahanay sa parehong posisyon nang pantay na bilang ng beses, kaya ang dalawang generator ay mag-co-commute, tulad ng X⊗XX\otimes XX⊗X at Z⊗ZZ\otimes ZZ⊗Z na nag-commute. Ito rin ay isang minimal generating set, at nagtatakda ito ng isang nontrivial na code space, na mga katotohanang iniiwan sa inyo upang pag-isipan.

Ang 7-qubit Steane code ay katulad ng 9-qubit Shor code sa na ini-encode nito ang isang solong qubit at nagpapahintulot ng pagwawasto ng isang arbitrary na error sa isang qubit, ngunit nangangailangan lamang ito ng 7 qubit sa halip na 9.

5-qubit code​

Pitong ay hindi ang pinakamaliit na bilang ng mga qubit na kinakailangan upang mag-encode ng isang qubit at maprotektahan ito laban sa isang arbitrary na error sa isang qubit — narito ang isang stabilizer code na ginagawa ito gamit lamang ang 5 qubit.

XZZXIIXZZXXIXZZZXIXZ\begin{array}{ccccc} X & Z & Z & X & \mathbb{I} \\[1mm] \mathbb{I} & X & Z & Z & X \\[1mm] X & \mathbb{I} & X & Z & Z \\[1mm] Z & X & \mathbb{I} & X & Z \\[1mm] \end{array}XIXZ​ZXIX​ZZXI​XZZX​IXZZ​

Ang code na ito ay karaniwang tinatawag na ang 5-qubit code. Ito ang pinakamaliit na bilang ng mga qubit sa isang quantum error correcting code na maaaring magpahintulot ng pagwawasto ng isang arbitrary na single-qubit error.

Mga one-dimensional na stabilizer code​

Narito ang isa pang halimbawa ng isang stabilizer code, kahit na hindi ito aktwal na nag-e-encode ng anumang qubit: ang code space ay one-dimensional. Gayunpaman, ito ay isang wastong stabilizer code pa rin ayon sa kahulugan.

ZZXX\begin{array}{cc} Z & Z \\[1mm] X & X \end{array}ZX​ZX​

Sa partikular, ang code space ay ang one-dimensional na espasyo na isinasaklaw ng isang e-bit na ∣ϕ+⟩.\vert\phi^+\rangle.∣ϕ+⟩.

Narito ang isang kaugnay na halimbawa ng isang stabilizer code na ang code space ay ang one-dimensional na espasyo na isinasaklaw ng isang GHZ state na (∣000⟩+∣111⟩)/2.(\vert 000\rangle + \vert 111\rangle)/\sqrt{2}.(∣000⟩+∣111⟩)/2​.

Dimensyon ng code space​

Ipagpalagay na mayroon tayong isang stabilizer code, na inilalarawan ng nnn-qubit na mga stabilizer generator na P1,…,Pr.P_1,\ldots,P_r.P1​,…,Pr​. Marahil ang pinaka-unang tanong na pumapasok sa isip tungkol sa code na ito ay, "Ilang qubit ang ini-encode nito?"

Ang tanong na ito ay may simpleng sagot. Kung ipinapalagay na ang nnn-qubit na mga stabilizer generator na P1,…,PrP_1, \ldots, P_rP1​,…,Pr​ ay natutugunan ang tatlong kinakailangan ng kahulugan (ibig sabihin, ang lahat ng stabilizer generator ay nag-commute sa isa't isa, ito ay isang minimal generating set, at ang code space ay hindi walang laman), dapat na ang code space para sa stabilizer code na ito ay may dimensyong 2n−r,2^{n-r},2n−r, kaya ang n−rn-rn−r na mga qubit ay maaaring ma-encode gamit ang code na ito.

Sa intuitive na pagsasalita, mayroon tayong nnn na qubit upang gamitin para sa encoding na ito, at ang bawat stabilizer generator ay epektibong "nag-aalis ng isang qubit" sa mga tuntunin ng kung ilang qubit ang maaari nating i-encode. Tandaan na hindi ito tungkol sa kung aling o gaano karaming mga error ang maaaring matuklas o maiwasto, ito ay isang pahayag lamang tungkol sa dimensyon ng code space.

Mga Clifford na Operasyon at Encoding​

Susunod, tatalakayin natin nang maikli kung paano naka-encode ang mga qubit gamit ang mga stabilizer code, pero para magawa iyon, kailangan muna nating ipakilala ang mga Clifford na operasyon.

Mga Clifford na Operasyon​

Ang mga Clifford na operasyon ay mga unitary na operasyon, sa anumang bilang ng mga qubit, na maaaring ipatupad sa pamamagitan ng mga quantum circuit na gumagamit ng limitadong hanay ng mga Gate:

  • Mga Hadamard gate
  • Mga SSS gate
  • Mga CNOT gate

Pansinin na hindi kasama ang mga TTT gate, ni ang mga Toffoli gate at Fredkin gate. Hindi lamang hindi sila kasama sa listahan — sa katunayan, hindi posibleng ipatupad ang mga gate na iyon gamit ang mga nakalistang dito; hindi sila mga Clifford na operasyon. Ang mga Pauli na operasyon naman ay mga Clifford na operasyon dahil maaari itong ipatupad gamit ang mga pagkakasunud-sunod ng Hadamard at SSS gate.

Iyon ay isang simpleng paraan para tukuyin ang mga Clifford na operasyon, ngunit hindi nito ipinapaliwanag kung bakit ganito ang kanilang kahulugan o ano ang espesyal sa partikular na koleksyong ito ng mga gate. Ang tunay na dahilan kung bakit ganito ang kahulugan ng mga Clifford na operasyon ay ang mga ito, hanggang sa mga pandaigdigang phase factor, ay tiyak na ang mga unitary na operasyon na palaging nagko-conjugate ng mga Pauli na operasyon at nagreresulta sa mga Pauli na operasyon. Para maging mas tiyak, ang isang nnn-qubit na unitary na operasyon UUU ay katumbas ng isang Clifford na operasyon hanggang sa isang phase factor kung, at kung lamang, para sa bawat nnn-qubit na Pauli na operasyon P,P,P, mayroon tayong

UPU†=±QU P U^{\dagger} = \pm QUPU†=±Q

para sa ilang nnn-qubit na Pauli na operasyon Q.Q.Q.

(Pansinin na hindi posible na magkaroon ng UPU†=αQU P U^{\dagger} = \alpha QUPU†=αQ para sa α∉{+1,−1}\alpha\notin\{+1,-1\}α∈/{+1,−1} kapag ang UUU ay unitary at ang PPP at QQQ ay mga Pauli na operasyon. Sumusunod ito mula sa katotohanang ang matrix sa kaliwang bahagi ng equation ay parehong unitary at Hermitian, at ang +1+1+1 at −1-1−1 ang tanging mga pagpipilian para sa α\alphaα na nagpapahintulot sa kanang bahagi na maging unitary at Hermitian din.)

Madaling i-verify ang conjugation property na ito kapag ang UUU ay isang Hadamard, S,S,S, o CNOT gate. Sa partikular, madali ito para sa mga Hadamard gate,

HXH†=Z,HYH†=−Y,HZH†=X,H X H^{\dagger} = Z, \qquad H Y H^{\dagger} = -Y, \qquad H Z H^{\dagger} = X,HXH†=Z,HYH†=−Y,HZH†=X,

at mga SSS gate,

SXS†=Y,SYS†=−X,SZS†=Z.S X S^{\dagger} = Y, \qquad S Y S^{\dagger} = -X, \qquad S Z S^{\dagger} = Z.SXS†=Y,SYS†=−X,SZS†=Z.

Para sa mga CNOT gate, may 15 na di-pagkakakilanlan na Pauli na operasyon sa dalawang qubit na kailangang suriin. Natural, maaari silang suriin nang isa-isa — ngunit ang mga relasyon sa pagitan ng mga CNOT gate at mga XXX at ZZZ gate na nakalista (sa anyo ng circuit) sa nakaraang aralin, kasama ang mga patakaran sa pagpaparami ng mga Pauli matrix, ay nag-aalok ng shortcut patungo sa parehong konklusyon.

Kapag nalaman na natin na ang conjugation property na ito ay totoo para sa mga Hadamard, S,S,S, at CNOT gate, maaari tayong agad na magsimulang tapusin na ito ay totoo para sa mga circuit na binubuo ng mga gate na ito — ibig sabihin, lahat ng Clifford na operasyon.

Mas mahirap patunayan na ang relasyon ay gumagana sa kabilang direksyon, na kung ang isang ibinigay na unitary na operasyon UUU ay nakakatugon sa conjugation property para sa mga Pauli na operasyon, kailangang posibleng ipatupad ito (hanggang sa isang global phase) gamit lamang ang Hadamard, S,S,S, at CNOT gate. Hindi ito ipapaliwanag sa araling ito, ngunit totoo ito.

Ang mga Clifford na operasyon ay hindi universal para sa quantum computation; hindi tulad ng mga universal na hanay ng quantum gate, hindi posible ang pag-aapproximate ng mga arbitrary na unitary na operasyon sa anumang nais na antas ng katumpakan gamit ang mga Clifford na operasyon. Sa katunayan, para sa isang ibinigay na halaga ng n,n,n, may limitadong bilang lamang ng mga nnn-qubit na Clifford na operasyon (hanggang sa mga phase factor). Ang pagsasagawa ng mga Clifford na operasyon sa mga standard basis state na sinusundan ng mga standard basis measurement ay hindi rin nagbibigay-daan sa atin na magsagawa ng mga computation na wala sa abot ng mga klasikal na algorithm — dahil maaari tayong mahusay na mag-simulate ng mga computation na ganito nang klasikal. Ang katotohanang ito ay kilala bilang Gottesman-Knill theorem.

Mga Encoder para sa mga Stabilizer Code​

Ang isang stabilizer code ay nagtatakda ng code space na may tiyak na dimensyon, at mayroon tayong kalayaang gamitin ang code space na iyon ayon sa ating kagustuhan — walang pumipigil sa atin na i-encode ang mga qubit sa code space na ito sa isang tiyak na paraan. Palagi itong posible, gayunpaman, na gumamit ng Clifford na operasyon bilang encoder, kung pipiliin nating gawin iyon. Para maging mas tiyak, para sa anumang stabilizer code na nagbibigay-daan sa pag-encode ng mmm na qubit sa nnn na qubit, may isang nnn-qubit na Clifford na operasyon UUU na, para sa anumang mmm-qubit na quantum state vector ∣ϕ⟩,\vert\phi\rangle,∣ϕ⟩, mayroon tayong

∣ψ⟩=U(∣0n−m⟩⊗∣ϕ⟩)\vert\psi\rangle = U \bigl(\vert 0^{n-m} \rangle \otimes \vert \phi\rangle\bigr)∣ψ⟩=U(∣0n−m⟩⊗∣ϕ⟩)

na isang quantum state vector sa code space ng ating code na maaari nating interpretahin bilang encoding ng ∣ϕ⟩.\vert\phi\rangle.∣ϕ⟩.

Ito ay maganda dahil ang mga Clifford na operasyon ay medyo simple, kumpara sa mga arbitrary na unitary na operasyon, at may mga paraan para i-optimize ang kanilang implementasyon gamit ang mga teknik na katulad ng mga makikita sa patunay ng Gottesman-Knill theorem. Bilang resulta, ang mga circuit para sa pag-encode ng mga state gamit ang mga stabilizer code ay hindi kailangang maging masyadong malaki. Sa partikular, palaging posible na magsagawa ng encoding para sa isang nnn-qubit na stabilizer code gamit ang isang Clifford na operasyon na nangangailangan ng O(n2/log⁡(n))O(n^2/\log(n))O(n2/log(n)) gate. Ito ay dahil ang bawat Clifford na operasyon sa nnn na qubit ay maaaring ipatupad ng isang circuit na may sukat na ito.

Halimbawa, narito ang isang encoder para sa 7-qubit Steane code. Ito ay talagang isang Clifford na operasyon, at gaya ng lumalabas, ang isa na ito ay hindi na kailangan pang ng mga SSS gate.

Pagde-detect ng mga Error​

Para sa isang nnn-qubit na stabilizer code na inilalarawan ng mga stabilizer generator na P1,…,Pr,P_1,\ldots, P_r,P1​,…,Pr​, ang pag-detect ng error ay gumagana sa sumusunod na paraan.

Para ma-detect ang mga error, lahat ng stabilizer generator ay sinusukat bilang mga observable. Mayroon rrr na stabilizer generator, at samakatuwid rrr na kinalabasan ng pagsukat, bawat isa ay +1+1+1 o −1-1−1 (o isang binary na halaga kung pipiliin nating iugnay ang 000 sa +1+1+1 at 111 sa −1,-1,−1, ayon sa pagkakasunud-sunod). Itinuturing natin ang rrr na kinalabasan nang magkasama, bilang isang vector o string, bilang isang syndrome. Ang syndrome na (+1,…,+1)(+1,\ldots,+1)(+1,…,+1) ay nagpapahiwatig na walang nadetektang error, habang ang kahit isang −1-1−1 sa loob ng syndrome ay nagpapahiwatig na may nadetektang error.

Ipagpalagay, sa partikular, na ang EEE ay isang nnn-qubit na Pauli na operasyon, na kumakatawan sa isang hypothetical na error. (Isinasaalang-alang lamang natin ang mga Pauli na operasyon bilang mga error, sa pamamagitan ng paraan, dahil ang discretization ng mga error ay gumagana sa parehong paraan para sa mga arbitrary na stabilizer code tulad ng para sa 9-qubit Shor code.) May tatlong kaso na nagtatakda kung nadetektahan ang EEE bilang isang error o hindi.

Mga Kaso sa Pag-detect ng Error​

  1. Ang operasyon EEE ay proporsyonal sa isang elemento sa stabilizer.

    E=±Q  para sa ilang  Q∈⟨P1,…,Pr⟩E = \pm Q \; \text{para sa ilang}\; Q \in \langle P_1,\ldots,P_r\rangleE=±Qpara sa ilangQ∈⟨P1​,…,Pr​⟩

    Sa kasong ito, ang EEE ay kailangang mag-commute sa bawat stabilizer generator, kaya makukuha natin ang syndrome na (+1,…,+1).(+1,\ldots,+1).(+1,…,+1). Nangangahulugan ito na ang EEE ay hindi nadetektahan bilang isang error.

  2. Ang operasyon EEE ay hindi proporsyonal sa isang elemento sa stabilizer, ngunit nagko-commute pa rin ito sa bawat stabilizer generator.

    E≠±Q  para sa  Q∈⟨P1,…,Pr⟩,  ngunit  EPk=PkE  para sa bawat  k∈{1,…,r}E\neq \pm Q\; \text{para sa} \; Q \in \langle P_1,\ldots,P_r\rangle, \;\text{ngunit}\; E P_k = P_k E \;\text{para sa bawat}\; k\in\{1,\ldots,r\}E=±Qpara saQ∈⟨P1​,…,Pr​⟩,ngunitEPk​=Pk​Epara sa bawatk∈{1,…,r}

    Ito ay isang error na nagbabago ng mga vector sa code space sa ilang di-trivial na paraan. Ngunit, dahil ang EEE ay nagko-commute sa bawat stabilizer generator, ang syndrome ay (+1,…,+1),(+1,\ldots,+1),(+1,…,+1), kaya ang EEE ay hindi nadetektahan ng code.

  3. Ang operasyon EEE ay nag-anti-commute sa kahit isa sa mga stabilizer generator.

    PkE=−EPk  para sa kahit isa  k∈{1,…,r}P_k E = -E P_k \; \text{para sa kahit isa} \; k\in\{1,\ldots,r\}Pk​E=−EPk​para sa kahit isak∈{1,…,r}

Sa unang kaso, ang error EEE ay hindi isang alalahanin dahil ang operasyong ito ay walang ginagawa sa mga vector sa code space, maliban sa posibleng mag-inject ng isang hindi-kaugnay na global phase: E∣ψ⟩=±∣ψ⟩E \ket{\psi} = \pm\ket{\psi}E∣ψ⟩=±∣ψ⟩ para sa bawat naka-encode na state na ∣ψ⟩.\ket{\psi}.∣ψ⟩. Sa esensya, hindi ito tunay na isang error — anumang di-trivial na aksyon ng EEE ay nangyayari sa labas ng code space — kaya maganda na ang EEE ay hindi nadetektahan bilang isang error, dahil wala namang kailangang gawin tungkol dito.

Ang ikalawang kaso, sa intuitive na pagsasalita, ay ang masamang kaso. Ito ay ang anti-commutation ng isang error sa isang stabilizer generator na nagdudulot ng −1-1−1 na lumabas sa isang lugar sa syndrome, na nagpapahiwatig ng isang error, ngunit hindi iyon nangyayari sa kasong ito. Kaya, mayroon tayong error EEE na nagbabago ng mga vector sa code space sa ilang di-trivial na paraan, ngunit ito ay hindi nadetektahan ng code. Halimbawa, para sa 3-bit repetition code, ang operasyon E=X⊗X⊗XE = X\otimes X\otimes XE=X⊗X⊗X ay napapabilang sa kategoryang ito.

Ang katotohanan na ang ganitong error na EEE ay kailangang magbago ng ilang vector sa code space sa isang di-trivial na paraan ay maaaring ipangalandakan tulad nito. Sa pamamagitan ng pagpapalagay na ang EEE ay nagko-commute sa P1,…,PrP_1,\ldots,P_rP1​,…,Pr​ ngunit hindi proporsyonal sa isang stabilizer element, maaari tayong magsimulang tapusin na makakakuha tayo ng isang bago, valid na stabilizer code sa pamamagitan ng pagsasama ng EEE bilang isang stabilizer generator kasama ang P1,…,Pr.P_1,\ldots,P_r.P1​,…,Pr​. Ang code space para sa bagong code na ito, gayunpaman, ay may kalahating dimensyon lamang ng orihinal na code space, mula sa kung saan maaari tayong magsimulang tapusin na ang aksyon ng EEE sa orihinal na code space ay hindi maaaring proporsyonal sa identity na operasyon.

Para sa huli sa tatlong kaso, na ang error EEE ay nag-anti-commute sa kahit isa sa mga stabilizer generator, ang syndrome ay may kahit isang −1-1−1 sa isang lugar dito, na nagpapahiwatig na may mali. Tulad ng napag-usapan na natin, ang syndrome ay hindi natatanging nagtatukoy sa EEE sa pangkalahatan, kaya kinakailangan pa ring pumili ng correction operation para sa bawat syndrome, na maaaring o hindi makakatama sa error E.E.E. Tatalakayin natin ang hakbang na ito sa lalong madaling panahon, sa huling bahagi ng aralin.

para sa PPP at QQQ na posibleng di-identity na Pauli matrix. Ito ay isang kaso lamang, at kinakailangang ulitin ang argumento na sumusunod para sa lahat ng iba pang posibleng lokasyon para sa mga di-identity na Pauli matrix sa mga tensor factor ng E,E,E, ngunit ang argumento ay halos kapareho para sa lahat ng posibleng lokasyon.

Ang operasyon EEE ay nagko-commute sa lahat ng anim na stabilizer generator, kaya nagko-commute ito sa dalawang ito sa partikular:

Z⊗I⊗Z⊗I⊗Z⊗I⊗ZX⊗I⊗X⊗I⊗X⊗I⊗X\begin{gathered} Z \otimes \mathbb{I} \otimes Z \otimes \mathbb{I} \otimes Z \otimes \mathbb{I} \otimes Z\\[1mm] X \otimes \mathbb{I} \otimes X \otimes \mathbb{I} \otimes X \otimes \mathbb{I} \otimes X \end{gathered}Z⊗I⊗Z⊗I⊗Z⊗I⊗ZX⊗I⊗X⊗I⊗X⊗I⊗X​

Ang tensor factor na QQQ sa ating error na EEE ay naka-linya sa identity matrix sa parehong stabilizer generator (kaya naman sila napili). Dahil mayroon tayong mga identity matrix sa pinakakanan na 5 posisyon ng E,E,E, magsisimula tayong tapusin na ang PPP ay kailangang mag-commute sa XXX at Z,Z,Z, dahil kung hindi, ang EEE ay mag-anti-commute sa isa sa dalawang generator. Gayunpaman, ang tanging Pauli matrix na nagko-commute sa parehong XXX at ZZZ ay ang identity matrix, kaya P=I.P = \mathbb{I}.P=I.

Ngayon na alam na natin ito, maaari tayong pumili ng dalawa pang stabilizer generator na may XXX at ZZZ sa ikalawang posisyon mula sa kaliwa, at makakakuha tayo ng katulad na konklusyon: Q=I.Q = \mathbb{I}.Q=I. Samakatuwid, ang EEE ay ang identity na operasyon.

Kaya, walang paraan para ang isang error na may weight na hindi hihigit sa 2 ay hindi madetektahan ng code na ito, maliban kung ang error ay ang identity na operasyon (na nasa stabilizer at samakatuwid ay hindi tunay na isang error). Sa kabilang banda, mayroon mga weight 3 na Pauli na operasyon na nagko-commute sa lahat ng anim na stabilizer generator na ito, ngunit hindi proporsyonal sa mga stabilizer element, tulad ng I⊗I⊗I⊗I⊗X⊗X⊗X\mathbb{I}\otimes\mathbb{I}\otimes\mathbb{I}\otimes\mathbb{I}\otimes X\otimes X\otimes XI⊗I⊗I⊗I⊗X⊗X⊗X at I⊗I⊗I⊗I⊗Z⊗Z⊗Z.\mathbb{I}\otimes\mathbb{I}\otimes\mathbb{I}\otimes\mathbb{I}\otimes Z\otimes Z\otimes Z.I⊗I⊗I⊗I⊗Z⊗Z⊗Z. Pinapatunayan nito na ang code na ito ay may distansyang 3, gaya ng sinabi.

Pagwawasto ng mga Error​

Ang huling paksa ng talakayan para sa araling ito ay ang pagwawasto ng mga error para sa mga stabilizer code. Tulad ng dati, ipagpalagay na mayroon tayong stabilizer code na tinukoy ng n-qubit na stabilizer generator na P1,…,Pr.P_1, \ldots, P_r.P1​,…,Pr​.

Ang mga nnn-qubit na Pauli na operasyon, bilang mga error na maaaring makaapekto sa mga state na naka-encode gamit ang code na ito, ay nahahati sa mga pantay na laking koleksyon ayon sa kung aling syndrome ang kanilang naisasanhi. Mayroon 2r2^r2r na natatanging syndrome at 4n4^n4n na Pauli na operasyon, na nangangahulugang mayroon 4n/2r4^n/2^r4n/2r na Pauli na operasyon na nagsasanhi ng bawat syndrome. Anuman sa mga error na ito ay maaaring responsable sa kaugnay na syndrome.

Gayunpaman, sa gitna ng 4n/2r4^n/2^r4n/2r na Pauli na operasyon na nagsasanhi ng bawat syndrome, mayroon ilang dapat ituring na katumbas. Sa partikular, kung ang produkto ng dalawang Pauli na operasyon ay proporsyonal sa isang stabilizer element, ang dalawang operasyong iyon ay epektibong katumbas bilang mga error.

Isa pang paraan para sabihin ito ay kung maglalapat tayo ng correction operation na CCC para subukang itama ang isang error na E,E,E, ang pagwawasto na ito ay matagumpay hangga't ang komposisyon na CECECE ay proporsyonal sa isang stabilizer element. Dahil mayroon 2r2^r2r na elemento sa stabilizer, sumusunod na ang bawat correction operation na CCC ay nagtutuwid ng 2r2^r2r na iba't ibang Pauli error. Nag-iiwan ito ng 4n−r4^{n-r}4n−r na hindi magkaparehong klase ng Pauli na operasyon, itinuturing bilang mga error, na naaayon sa bawat posibleng syndrome.

Nangangahulugan ito na, maliban kung ang n=rn=rn=r (kung saan mayroon tayong trivial, isang-dimensional na code space), hindi natin maaaring itama ang bawat error na nadetektahan ng isang stabilizer code. Ang dapat nating gawin sa halip ay pumili ng isang correction operation para sa bawat syndrome, sa pag-asa na maitama ang isang klase lamang ng katumbas na mga error na nagsasanhi ng syndrome na ito.

Ang isang natural na estratehiya para pumili ng kung aling correction operation ang isasagawa para sa bawat syndrome ay ang pumili ng pinakamababang weight na Pauli na operasyon na, bilang isang error, ay nagsasanhi ng syndrome na iyon. Maaaring mayroon sa katunayan ng maramihang operasyon na nagtatali para sa pinakamababang weight na error na naaayon sa isang ibinigay na syndrome, kung saan anuman sa mga ito ay maaaring mapili. Ang ideya ay ang mga Pauli na operasyon na may mas mababang weight ay kumakatawan sa mas malamang na mga paliwanag para sa anumang syndrome na nasukat. Maaaring hindi ito ang kaso para sa ilang noise model, at ang isang alternatibong estratehiya ay ang mag-compute ng pinaka-malamang na error na nagsasanhi ng ibinigay na syndrome, batay sa piniling noise model. Para sa araling ito, gayunpaman, pinanatili nating simple ang mga bagay at isinasaalang-alang lamang ang mga pinakamababang weight na pagwawasto.

Para sa isang distansya ddd na stabilizer code, ang estratehiyang ito ng pagpili ng correction operation na maging isang pinakamababang weight na Pauli na operasyon na naaayon sa nasukat na syndrome ay palaging nagbibigay-daan sa pagwawasto ng mga error na may weight na mahigpit na wala sa kalahati ng d,d,d, o sa ibang salita, weight na hindi hihigit sa (d−1)/2.(d-1)/2.(d−1)/2. Ipinapakita nito, halimbawa, na ang 7-qubit Steane code ay makakaitama ng anumang weight-one na Pauli error, at sa pamamagitan ng discretization ng mga error, nangangahulugan ito na ang Steane code ay makakaitama ng isang arbitrary na error sa isang qubit.

Para makita kung paano gumagana ito, isaalang-alang ang diagram sa ibaba. Ang bilog sa kaliwa ay kumakatawan sa lahat ng Pauli na operasyon na nagresulta sa syndrome na (+1,…,+1),(+1,\ldots,+1),(+1,…,+1), na ang syndrome na nagmumungkahi na walang naganap na error at walang mali. Sa gitna ng mga operasyong ito mayroon tayo mga elemento ng stabilizer (o mga operasyon na proporsyonal sa mga elemento ng stabilizer, para maging mas tiyak) at mayroon din tayong mga di-trivial na error na nagbabago ng code space sa ilang paraan ngunit hindi nadetektahan ng code. Sa kahulugan ng distansya, ang bawat Pauli na operasyon sa kategoryang ito ay kailangang may weight na hindi bababa sa d,d,d, dahil ang ddd ay tinukoy bilang ang pinakamababang weight ng mga operasyong ito.

Ang bilog sa kanan ay kumakatawan sa mga Pauli na operasyon na nagresulta sa ibang syndrome na s≠(+1,…,+1),s\neq(+1,\ldots,+1),s=(+1,…,+1), kabilang ang isang error EEE na may weight na mahigpit na wala sa d/2d/2d/2 na ating isasaalang-alang.

Ang correction operation na CCC na pinili para sa syndrome na sss ay ang pinakamababang weight na Pauli na operasyon sa koleksyon na kinakatawan ng bilog sa kanan sa diagram (o anuman sa kanila kung may tali). Kaya, maaaring ang C=E,C = E,C=E, ngunit hindi kinakailangan. Ang maaari nating sabihin nang may katiyakan, gayunpaman, ay ang CCC ay hindi maaaring magkaroon ng weight na mas malaki kaysa sa weight ng E,E,E, dahil ang CCC ay may minimal na weight sa gitna ng mga operasyon sa koleksyong ito — at samakatuwid ang CCC ay may weight na mahigpit na wala sa d/2.d/2.d/2.

Ngayon isaalang-alang kung ano ang mangyayari kapag ang correction operation na CCC ay inilapat sa anumang state na nakuha natin pagkatapos mangyari ang error na E.E.E. Ipagpalagay na ang orihinal na encoding ay ∣ψ⟩,\vert\psi\rangle,∣ψ⟩, naiwan tayong may CE∣ψ⟩.CE\vert\psi\rangle.CE∣ψ⟩. Ang ating layunin ay ipakita na ang CECECE ay proporsyonal sa isang elemento sa stabilizer, na nagpapahiwatig na ang pagwawasto ay matagumpay at (hanggang sa isang global phase) naiwan tayo ng orihinal na naka-encode na state na ∣ψ⟩.\vert\psi\rangle.∣ψ⟩.

Una, dahil ang EEE at CCC ay nagsasanhi ng parehong syndrome, ang komposisyon na CECECE ay kailangang mag-commute sa bawat stabilizer generator. Sa partikular, kung ang PkP_kPk​ ay anuman sa mga stabilizer generator, kailangan nating magkaroon ng

PkE=αEPkatPkC=αCPkP_k E = \alpha E P_k \quad\text{at}\quad P_k C = \alpha C P_kPk​E=αEPk​atPk​C=αCPk​

para sa parehong halaga ng α∈{+1,−1},\alpha\in\{+1,-1\},α∈{+1,−1}, dahil ito ang kkk-th na entry sa syndrome na sss na parehong CCC at EEE ang nagge-generate. Samakatuwid, mayroon tayong

Pk(CE)=αCPkE=α2(CE)Pk=(CE)Pk,P_k (CE) = \alpha C P_k E = \alpha^2 (CE) P_k = (CE) P_k,Pk​(CE)=αCPk​E=α2(CE)Pk​=(CE)Pk​,

kaya nagko-commute ang PkP_kPk​ sa CE.CE.CE. Pinatunayan natin samakatuwid na ang CECECE ay napapabilang sa bilog sa kaliwa sa diagram, dahil nagge-generate ito ng syndrome na (+1,…,+1).(+1,\ldots,+1).(+1,…,+1).

Pangalawa, ang komposisyon na CECECE ay kailangang magkaroon ng weight na hindi hihigit sa kabuuan ng mga weight ng CCC at EEE — na sumusunod mula sa sandaling pag-iisip tungkol sa mga produkto ng Pauli na operasyon — at samakatuwid ang weight ng CECECE ay mahigpit na wala sa d.d.d. Nangangahulugan ito na ang CECECE ay proporsyonal sa isang elemento sa stabilizer ng ating code, na siyang nais nating ipakita. Sa pamamagitan ng pagpili ng ating mga correction operation na maging mga pinakamababang-weight na kinatawan ng hanay ng mga error na nagge-generate ng bawat syndrome, garantisado nating maitatama ang anumang Pauli error na may weight na wala sa kalahati ng distansya ng code.

Mayroon, gayunpaman, isang problema. Para sa mga stabilizer code sa pangkalahatan, ito ay isang computationally mahirap na problema ang mag-compute ng pinakamababang weight na Pauli na operasyon na nagsasanhi ng isang ibinigay na syndrome. (Sa katunayan, totoo ito kahit para sa mga klasikal na code, na sa kontekstong ito ay maaari nating isipin bilang mga stabilizer code kung saan may I\mathbb{I}I at ZZZ lamang na matrix na lumalabas bilang mga tensor factor sa loob ng mga stabilizer generator.) Kaya, hindi tulad ng encoding step, ang mga Clifford na operasyon ay hindi darating para iligtas tayo sa pagkakataong ito.

Ang solusyon ay pumili ng mga tiyak na code kung saan ang mga magagandang pagwawasto ay maaaring ma-compute nang mahusay, na walang simpleng recipe para dito. Sa madaling salita, ang pagbuo ng mga stabilizer code kung saan ang mga magagandang correction operation ay maaaring ma-compute nang mahusay ay bahagi ng sining ng quantum code design.
