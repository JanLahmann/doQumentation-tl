AI-QEM ng LTM

tala

Ang IBM Quantum® Functions ay isang beta feature na available lang sa mga user ng IBM Quantum Premium Plan, Flex Plan, at On-Prem (sa pamamagitan ng IBM Quantum Platform API) Plan. Puwedeng magbago ang mga beta feature.

Tingnan ang API reference.

Mga kasalukuyang limitasyon

Ang kasalukuyang release ng AI-QEM ay may mga sumusunod na limitasyon:

  • Limitado ang mitigation sa pamilya ng Heron processor. Plano ng LTM na suportahan ang mga karagdagang backend sa mga susunod na bersyon.

  • Pinipili lang ang pagkakataon ng error mitigation. Isinasagawa lang ang mitigation kapag ang absolute expectation value ay nakakatugon sa ∣⟨O⟩noisy∣≥0.1|\langle O \rangle_{noisy}| \geq 0.1∣⟨O⟩noisy​∣≥0.1, para magamit lang ang mitigation kung saan inaasahang magbibigay ito ng makabuluhang benepisyo.

Sumasalamin ang mga limitasyong ito sa kasalukuyang saklaw ng AI-QEM. Maaaring luwagan ng mga susunod na release ang mga ito habang nagdaragdag ang LTM ng suporta para sa mga karagdagang workflow, backend, at feature.

Pangkalahatang-ideya​

Ang quantum error mitigation (QEM) ay sumasaklaw sa mga algorithmic protocol, tulad ng zero-noise extrapolation (ZNE) [2] at probabilistic error cancellation (PEC) [3], na idinisenyo para pigilan ang bias na dulot ng noise sa mga expectation value sa noisy intermediate-scale quantum (NISQ) hardware, nang hindi nangangailangan ng malaking qubit overhead ng ganap na fault tolerance. Mahalaga ang mga paraang ito para makakuha ng maaasahang pisikal na simulation at benchmark result mula sa mga kasalukuyang processor. Bagaman maraming QEM method ang nabuo nitong mga nakaraang taon, halos lahat ng mga ito ay may iisang pangunahing trade-off: umaasa sila sa mas mahabang QPU time para makamit ang katumpakan. Ang tumutukoy sa limitasyon nila ay ang exponential na sampling overhead, dahil ang muling pagbuo ng unbiased na signal mula sa mga noisy circuit ay lubhang nagpapataas sa statistical variance ng estimator. Dahil dito, ang pagtagumpayan sa mas mataas na antas ng noise ay nangangailangan ng ilang order of magnitude na mas maraming measurement shot, na humahantong sa mas mahabang QPU runtime at malalaking hardware bottleneck [4, 5, 6].

Gamit ang AI-QEM, puwede kang magpatakbo ng mga quantum circuit sa mga noisy QPU at makakuha ng mas pinahusay na expectation value kumpara sa ibang AI-based na error mitigation technique, nang walang karagdagang QPU runtime overhead. Gumagamit ang paraan ng deep neural network na may graph convolutional network (GCN)-Transformer architecture. Sinasanay ang network sa mga feature na kinabibilangan ng istruktura ng circuit, topology ng backend, mga Pauli observable, at mga qubit calibration, at nagpe-predict ito ng correction factor, na tinutukoy ng ζ\zetaζ. Ang paghahati sa noisy expectation value sa ζ\zetaζ ay nagbubunga ng pinahusay na expectation value. Ipinapakita ng mga eksperimento na mas mahusay ang resulta ng AI-QEM kaysa sa ibang AI-based na mitigation method, lalo na para sa mga circuit na may malaking depth (mga layer ng gate) at width (bilang ng mga qubit), kaya angkop ito para sa mga utility-scale na quantum experiment. Ipinapakita ng talahanayan sa seksyong Benchmarks na nahihigitan ng GCN-Transformer-based na model ang mga random forest (RF)-based na model sa saklaw na 80 hanggang 150 qubit, na may mean absolute error (MAE) na 0.343. Ang MAE ay ang average, sa maraming configuration ng circuit at observable, ng absolute na pagkakaiba ng ideal na expectation value at ng expectation value matapos bawasan ng model ang noise sa resulta ng noisy hardware. Bukod pa rito, dahil circuit-agnostic ang model, magagamit mo ito sa malawak na hanay ng mga quantum circuit at aplikasyon nang hindi kailangan ng customization na partikular sa circuit.

Para sa buong paglalarawan ng mga pinagbabatayang component at isang utility-scale na demonstrasyon, tingnan ang AI-QEM paper [1].

Paglalarawan​

Gamitin ang LTM AI-QEM function para tantiyahin ang mga expectation value ng mga observable para sa isang quantum circuit. Para magamit ang LTM AI-QEM, magbigay ng quantum circuit, set ng mga observable na susukatin, at isang QPU. Gumagamit ang function ng parehong QPU time gaya ng IBM Quantum Estimator primitive, at walang karagdagang QPU time.

Ang karaniwang paraan para kalkulahin ang expectation value ng observable na OOO ay hatiin ang observable sa kabuuan ng mga Pauli operator, O=∑iciPiO=\sum_i{c_i}{P_i}O=∑i​ci​Pi​, at kalkulahin nang isa-isa ang expectation value ng bawat Pauli operator, ⟨Pi⟩\langle P_i \rangle⟨Pi​⟩. Ang expectation value ng observable, ⟨O⟩\langle O \rangle⟨O⟩, ay ang parehong linear combination ng mga Pauli expectation value: ⟨O⟩=∑ici⟨Pi⟩{\langle O \rangle}=\sum_i{c_i}{\langle P_i \rangle}⟨O⟩=∑i​ci​⟨Pi​⟩. Kung ang isang set ng mga Pauli operator ay nagko-commute sa isa't isa, maaaring sabay-sabay na gawin ang mga sukat na kailangan para kalkulahin ang kanilang mga expectation value. Kapag nagpatakbo ka ng circuit gamit ang LTM AI-QEM function, ginagamit ng function ang Estimator primitive para patakbuhin ang circuit sa hardware gaya ng dati. Sinusunod nito ang parehong pamamaraan ng paghahati sa observable sa mga Pauli operator at pagkalkula ng kanilang mga expectation value nang isa-isa. Pagkatapos, ang GCN-Transformer, isang deep learning architecture, ay nagpe-predict ng correction factor na ζi\zeta_iζi​ para sa bawat Pauli operator na PiP_iPi​. Ginagamit ng function ang correction factor na ito para itama ang noisy expectation value ng bawat Pauli operator: ⟨Pi⟩mitigated=⟨Pi⟩noisyζi{\langle P_i \rangle}_{mitigated} = \frac{{\langle P_i \rangle}_{noisy}}{\zeta_i}⟨Pi​⟩mitigated​=ζi​⟨Pi​⟩noisy​​. Samakatuwid, ang mitigated expectation value ay ⟨O⟩mitigated=∑ici⟨Pi⟩mitigated=∑ici⟨Pi⟩noisyζi{\langle O \rangle}_{mitigated} = \sum_i{c_i}{\langle {P_i} \rangle}_{mitigated} = \sum_i{c_i}{\frac{{\langle P_i \rangle}_{noisy}}{\zeta_i}}⟨O⟩mitigated​=∑i​ci​⟨Pi​⟩mitigated​=∑i​ci​ζi​⟨Pi​⟩noisy​​.

Ang workflow para sa paggamit ng LTM AI-QEM function ay ang sumusunod:

  1. Tukuyin ang iyong mga circuit at observable.

  2. Patakbuhin ang LTM AI-QEM function sa pamamagitan ng pagpasa ng circuit at mga pares ng observable bilang primitive unified blocs (PUBs).

  3. Kunin ang mga resulta, na naglalaman ng expectation value ng observable kaugnay ng katumbas na quantum circuit sa bawat PUB.

Maraming test example ang empirikal na nagpapakitang pinapabuti ng LTM AI-QEM function ang pagtantiya ng mga observable. Ang function ay may mga sumusunod na feature:

  • Mga utility-scale na eksperimento: Ipinapakita ng mga test example na mas mahusay ang AI-QEM kaysa sa ibang AI-based na paraan para sa mga circuit na may malaking depth at malaking width. Tingnan ang seksyong Benchmarks para sa mga resulta.

  • Primitive: Sinusuportahan ng function ang Estimator primitive, kaya magagamit mo ito para kalkulahin ang expectation value ng anumang observable kaugnay ng anumang quantum circuit.

  • Primitive unified bloc (PUB): Sinusuportahan ng LTM AI-QEM function ang lahat ng uri ng PUB (ibig sabihin, lahat ng configuration ng circuit-observable) na sinusuportahan ng Estimator primitive.

Nagsisimula ang AI-QEM technique sa pagbuo ng dataset, kung saan gumagawa ng mga random na quantum circuit na may iba't ibang setting ng parameter. Para sa bawat circuit, kinakalkula ang parehong ideal na expectation value (nakuha sa pamamagitan ng simulation) at noisy na expectation value (nakuha mula sa pagpapatakbo sa hardware). Ang mga resultang ito, kasama ang kaukulang mga quantum circuit at impormasyon ng backend, ay iniimbak sa isang dataset repository. Ginagamit ang dataset para sanayin ang machine-learning o deep-learning model na kayang bawasan ang noise sa mga quantum computation, at sine-save ang sinanay na model para sa susunod na gamit. Sa inference, ang sinanay na model ay tumatanggap bilang input ng isang quantum circuit, ang noisy expectation value nito na kinalkula sa hardware, ang mga kaugnay na observable, at impormasyon ng backend. Pagkatapos ay pinoproseso ng model ang mga input na ito para makabuo ng expectation value na nabawasan ang noise.

Mga Halimbawa​

Halimbawa 1: GHZ circuit​

Ipinapakita ng halimbawang ito ang basic na workflow ng LTM AI-QEM function gamit ang simpleng nnn-qubit na GHZ circuit at ang two-body tensor product observable na ZiZjZ_iZ_jZi​Zj​, na ang expectation value para sa GHZ state ay kilalang 1.

Buuin ang PUB​

Tulad ng Estimator primitive, tumatanggap ang LTM AI-QEM function ng primitive unified blocs (PUBs) bilang input. Ang PUB ay isang tuple na may anyong (circuit, observables, parameter_values, precision), kung saan kailangan ang parameter_values para sa mga parametric na circuit at opsyonal ang precision.

Circuit​

Ang nnn-qubit na Greenberger-Horne-Zeilinger (GHZ) state ay ibinibigay ng:

∣GHZ⟩n=∣0⟩⊗n+∣1⟩⊗n2=∣00…0⟩⏞n qubits+∣11…1⟩⏞n qubits2.|GHZ\rangle_{n} = \frac{\vert{0}\rangle^{\otimes{n}} + \vert{1}\rangle^{\otimes{n}}}{\sqrt2} = \frac{\overbrace{\vert{00}\dots{0}\rangle}^{\text{$n$ qubits}} + \overbrace{\vert{11}\dots{1}\rangle}^{\text{$n$ qubits}}}{\sqrt2}.∣GHZ⟩n​=2​∣0⟩⊗n+∣1⟩⊗n​=2​∣00…0⟩​n qubits​+∣11…1⟩​n qubits​​.

Para buuin ang nnn-qubit na GHZ state, i-initialize ang lahat ng qubit sa ∣0⟩|0\rangle∣0⟩ state at maglapat ng Hadamard gate sa unang qubit para makagawa ng pantay na superposition. Pagkatapos, maglapat ng sunod-sunod na CNOT gate sa buong register, na ang qubit iii ang control at ang qubit i+1i+1i+1 ang target. Ang hagdang ito ng mga entangling gate ay nagpapalaganap ng paunang superposition sa lahat ng qubit, na nagreresulta sa entangled na GHZ state.

Mga Observable​

Ang pagsukat ng two-body tensor product na Zi⊗ZjZ_i \otimes Z_jZi​⊗Zj​ sa isang GHZ state ay sumusuri sa parity correlation ng alinmang dalawang qubit sa register. Dahil ang GHZ state ay superposition ng all-zeros at all-ones na mga state, perpektong magkorelasyon ang alinmang dalawang qubit. Ang eigenvalue ay (+1×+1)=1(+1 \times +1) = 1(+1×+1)=1 para sa branch na ∣00…0⟩\vert00\dots0\rangle∣00…0⟩ at (−1×−1)=1(-1 \times -1) = 1(−1×−1)=1 para sa branch na ∣11…1⟩\vert11\dots1\rangle∣11…1⟩. Dahil +1 ang ibinabalik ng parehong branch, 1 ang theoretical na expectation value. Buuin ang observable gamit ang SparsePauliOp class.

Dahil hindi parametric ang circuit, buuin ang PUB bilang (circuit, observable).

from qiskit import QuantumCircuit
from qiskit.quantum_info import SparsePauliOp

def construct_ghz_circuit(n: int):
    """Constructs GHZ circuit with n qubits."""
    circuit = QuantumCircuit(n)
    circuit.h(0)
    for i in range(n - 1):
        circuit.cx(i, i + 1)
    return circuit

# Construct a GHZ circuit with the specified number of qubits
num_qubits = 50
ghz_circuit = construct_ghz_circuit(num_qubits)

# Observables
obs = SparsePauliOp.from_sparse_list(
    [("ZZ", [0, 49], 1.0)], num_qubits=num_qubits
)

# PUB
pub = (ghz_circuit, obs)

print("Details:")
print(f"\tNumber of Qubits: {num_qubits}")
print(f"\tCircuit Depth: {ghz_circuit.depth()}")
print(f"\tObservable: {obs}")

ghz_circuit.draw("mpl", fold=-1, scale=0.5)

Halimbawa 2: Mirror circuit​

Gumagamit ang halimbawang ito ng mirror circuit para kalkulahin ang mga expectation value ng mga observable na ipinasa sa mga PUB na may iba't ibang hugis. Ipinapakita nito ang LTM AI-QEM function at ang compatibility nito sa iba't ibang hugis ng PUB, at ikinukumpara ang mga mitigated na resulta sa mga unmitigated na resulta.

Ang mirror circuit ay naglalapat ng random na nabuong circuit at pagkatapos ay ng inverse nito. Sa ideal at walang noise na pagpapatakbo, nagkakansela ang dalawang kalahati at ibinabalik ang mga qubit sa paunang state nila. Dahil dito, kapaki-pakinabang ang circuit para pag-aralan kung paano nakakaapekto ang noise ng hardware at runtime sa isang resultang kung hindi man ay mahuhulaan.

Sa halimbawang ito, bubuo ka ng maraming PUB. Pinagpapares ng bawat PUB ang iisang mirror circuit sa mga observable na binubuo ng mga Pauli operator, na may iba't ibang hugis.

Sinusuri ng LTM AI-QEM function ang mga observable na ito at ibinabalik ang parehong mga expectation value mula sa noisy na pagpapatakbo at ang mga value pagkatapos ng mitigation. May dalawang layunin ang halimbawang ito: beripikahin na tinatanggap ng function ang mga sinusuportahang format ng PUB, at ikumpara ang mga mitigated na expectation value sa mga noisy na value para makita kung gaano kaepektibo ang error mitigation workflow sa pagbabalik ng inaasahang gawi ng mirror circuit.

Buuin ang mga PUB​

Ang bawat PUB ay isang tuple ng isang circuit at isang listahan ng mga observable. Kinakalkula ng function ang mga expectation value ng mga observable kaugnay ng circuit. Sa halimbawang ito, pareho ang circuit para sa lahat ng configuration ng observable. Ipapasa mo ang listahan ng mga PUB, pubs, sa ltm_function para patakbuhin.

Circuit​

Una, gumawa ng mirror circuit na may limang qubit. Para dito, gumawa ng random na circuit gamit ang Qiskit random_circuit function. Tukuyin ang bilang ng mga qubit (n_qubits=5), ang depth ng circuit (depth=5), at isang seed para sa reproducibility (seed=42). Pagkatapos, magdagdag ng barrier sa dulo ng random na circuit, at gamitin ang unitary_overlap para buuin ang mirror circuit. Dahil ang unitary_overlap(U1, U2) ay gumagawa ng circuit na tumutugma sa U2†U1U_{2}^{\dagger}U_{1}U2†​U1​, ang pagpasa ng parehong circuit bilang dalawang argument ay lumilikha ng mirror circuit. Pinipigilan ng barrier na maging identity ang circuit habang nagta-transpile. Ipinapakita ng output ng code ang depth ng mirror circuit, na inaasahang mga 10 para sa depth=5, dagdag ang mga layer ng barrier.

Mga Observable​

Susunod, gumawa ng mga listahan ng mga observable na gusto mong kalkulahin ang mga expectation value, sa iba't ibang format. Una, tukuyin ang mga variable na ALL_X_PAULI = XXXXX, ALL_Y_PAULI = YYYYY, at ALL_Z_PAULI = ZZZZZ, na kumakatawan sa mga katumbas na Pauli observable sa lahat ng limang qubit.

Pagkatapos, tukuyin ang obs_1 bilang listahan ng tatlong observable. Ang una ay linear combination ng dalawang Pauli operator, 0.3 ZZZZZ+0.5 XXXXX0.3\,ZZZZZ + 0.5\,XXXXX0.3ZZZZZ+0.5XXXXX, na tinukoy bilang SparsePauliOp. Ang pangalawa ay SparsePauliOp([ALL_Z_PAULI]), na isa ring SparsePauliOp. Ang pangatlo ay ang Pauli string na ALL_X_PAULI. Ang PUB na may obs_1 ay may observable array na may hugis na (3,).

Panghuli, tukuyin ang obs_2 sa matrix layout, ibig sabihin, bilang listahan ng mga listahan, kung saan ang bawat panloob na listahan ay naglalaman ng mga observable na may uri na SparsePauliOp o mga Pauli string. Ang unang hilera ay naglalaman ng ALL_X_PAULI at 0.3 ZZZZZ+0.5 YYYYY0.3\,ZZZZZ + 0.5\,YYYYY0.3ZZZZZ+0.5YYYYY. Ang pangalawang hilera ay naglalaman ng 0.3 XXXXX+0.5 ZZZZZ0.3\,XXXXX + 0.5\,ZZZZZ0.3XXXXX+0.5ZZZZZ at 2.0 ZZZZZ2.0\,ZZZZZ2.0ZZZZZ. import numpy as np
from qiskit.circuit.library import unitary_overlap
from qiskit.circuit.random import random_circuit
from qiskit.quantum_info import SparsePauliOp

def create_mirror_circuit(
    n_qubits: int, depth: int, seed: int = 42
) -> QuantumCircuit:
    """Generates an n-qubit random circuit followed by its inverse (mirror) and measure all qubits."""  # noqa: E501
    circuit = random_circuit(n_qubits, depth=depth, seed=seed)
    circuit.barrier()
    mirror_circuit = unitary_overlap(circuit, circuit)
    return mirror_circuit

    """{'ZZZZZ': 0.3, 'XXXXX': 0.5} -> '0.3 ZZZZZ\n+\n0.5 XXXXX'"""
    return "\n+\n".join(

Halimbawa 4: Brickwork Clifford circuit​

Sinisimulate ng halimbawang ito ang mga Clifford circuit. Kapaki-pakinabang ang pamilyang ito ng mga circuit dahil maaari mong idisenyo ang simulation para magkaroon ng kilalang expectation value. Partikular, maaari mong idisenyo ang circuit at ang observable para laging 1 ang expectation value, tulad ng sumusunod:

  1. Ang panimulang punto (ang stabilizer): Magsimula sa vacuum state na ∣0⟩⊗n|0\rangle^{{\otimes}n}∣0⟩⊗n. Ang paglalapat ng Pauli ZZZ o ng identity operator sa ∣0⟩|0\rangle∣0⟩ ay nag-iiwan dito na hindi nagbabago: Z∣0⟩=∣0⟩Z|0\rangle = |0\rangleZ∣0⟩=∣0⟩ at I∣0⟩=∣0⟩I |0\rangle = |0\rangleI∣0⟩=∣0⟩. Kaya, anumang Pauli string na PPP na tensor product ng ZZZ at III lamang ay nag-iiwan sa all-zero state na ∣0⟩⊗n|0\rangle^{{\otimes}n}∣0⟩⊗n na hindi nagbabago: P∣0⟩⊗n=∣0⟩⊗nP |0\rangle^{{\otimes}n} = |0\rangle^{{\otimes}n}P∣0⟩⊗n=∣0⟩⊗n.

  2. Ang Clifford evolution: Ang paglalapat ng unitary na ULU_LUL​ sa state ay nagbibigay ng ∣ψ⟩=UL∣0⟩⊗n|\psi\rangle = U_L |0\rangle^{{\otimes}n}∣ψ⟩=UL​∣0⟩⊗n. Para makahanap ng observable na 1 ang expectation value para sa bagong state na ito, ilapat ang parehong unitary transformation sa operator: OL=ULPUL†O_L = U_L P U_L^{\dagger}OL​=UL​PUL†​. Ito ang Heisenberg picture ng quantum mechanics.

  3. Bakit nananatiling iisang Pauli string ang observable: Kung ang ULU_LUL​ ay may mga non-Clifford na gate (tulad ng mga T gate o arbitrary na rotation), ang ULPUL†U_L P U_L^\daggerUL​PUL†​ ay lalawak at magiging kabuuan ng maraming magkakaibang Pauli string. Kakailanganin mong sukatin ang maraming magkakaibang observable at pagsamahin ang mga ito para makakuha ng 1. Gayunpaman, dahil mga Clifford gate lang ang ginagamit ng circuit, ginagarantiya ng Gottesman-Knill theorem na ang ULPUL†U_L P U_L^\daggerUL​PUL†​ ay nagma-map sa eksaktong isang Pauli string (halimbawa, XY−ZXX Y -Z XXY−ZX).

  4. Ang mathematical na garantiya: Dahil sa konstruksyong ito, ang pagkalkula ng expectation value ay isang simpleng algebraic na pagpapalit:

⟨OL⟩=⟨ψ∣OL∣ψ⟩\langle O_L \rangle = \langle \psi | O_L | \psi \rangle⟨OL​⟩=⟨ψ∣OL​∣ψ⟩

Ipalit ang ∣ψ⟩|\psi \rangle∣ψ⟩ at OLO_LOL​:

(⟨0∣⊗nUL†)(ULPUL†)(UL∣0⟩⊗n)(\langle 0 |^{\otimes n} U_L^{\dagger}) (U_L P U_L^{\dagger}) (U_L | 0 \rangle ^{\otimes n})(⟨0∣⊗nUL†​)(UL​PUL†​)(UL​∣0⟩⊗n)

Nagkakansela ang magkatabing terminong UL†ULU_L^\dagger U_LUL†​UL​ (katumbas ng mga ito ang identity na III):

=⟨0∣⊗nP∣0⟩⊗n= \langle 0 |^{\otimes n} P | 0 \rangle ^{\otimes n}=⟨0∣⊗nP∣0⟩⊗n

Dahil ang PPP ay tensor product ng ZZZ at III lamang, P∣0⟩⊗n=∣0⟩⊗nP| 0 \rangle ^{\otimes n} = | 0 \rangle ^{\otimes n}P∣0⟩⊗n=∣0⟩⊗n, at samakatuwid:

=⟨0∣⊗n∣0⟩⊗n=1= \langle 0 |^{\otimes n} | 0 \rangle ^{\otimes n} = 1=⟨0∣⊗n∣0⟩⊗n=1

Una, magdisenyo ng mga quantum circuit na may mga Clifford gate lamang: ang mga single-qubit na gate na HHH, SSS, XXX, YYY, at ZZZ, at ang two-qubit na gate na CZCZCZ. Ang function na create_brickwork_clifford ay tumatanggap ng bilang ng mga qubit (num_qubits) at depth bilang mga argument, at nagbabalik ng Clifford quantum circuit na may ibinigay na bilang ng mga qubit at depth.

import random
from qiskit import QuantumCircuit
from qiskit.circuit.library import HGate, SGate, XGate, YGate, ZGate

def create_brickwork_clifford(num_qubits: int, depth: int = 2):
    def get_random_1q_gate():
        gates = [HGate(), SGate(), XGate(), YGate(), ZGate()]
        return random.choice(gates)

    circuit = QuantumCircuit(num_qubits)
    for layer_idx in range(depth):
        for qubit in range(num_qubits):
            circuit.append(get_random_1q_gate(), [qubit])

        # Add CZ Gate in brickwork pattern
        if layer_idx % 2 == 0:
            for qubit in range(0, num_qubits - 1, 2):
                circuit.cz(qubit, qubit + 1)
        else:
            for qubit in range(1, num_qubits - 1, 2):
                circuit.cz(qubit, qubit + 1)
    return circuit

Ang mga circuit sa halimbawang ito ay may 50 qubit (num_qubits=50) at iba't ibang depth: 30, 35, 40, 45, 50, 55, 60, 65, at 70. Para sa mga observable, magsimula sa isang Pauli string na PPP na may Pauli weight na 2, ibig sabihin, dalawang Pauli ZZZ operator sa mga random na posisyon. Pagkatapos, gamitin ang evolve method para i-evolve ang PPP tungo sa ULiPULi†U_{L_i} P U_{L_i}^{\dagger}ULi​​PULi​†​ para sa circuit na ULiU_{L_i}ULi​​ ng bawat depth. I-save ang mga circuit at ang mga katumbas na observable sa mga listahang circuits_list at observables_list, ayon sa pagkakasunod.

from qiskit.quantum_info import Pauli, Clifford, SparsePauliOp
import numpy as np

num_qubits = 50
depth_list = list(range(30, 71, 5))
pauli_weight = 2

# Set random seed for reproducibility
random.seed(42)
np.random.seed(42)

circuits_list = []
observables_list = []

# Choose two unique random positions for 'Z'
z_positions = random.sample(range(num_qubits), pauli_weight)

# Build the Pauli string
pauli_str = ["I"] * num_qubits
for pos in z_positions:
    pauli_str[pos] = "Z"
Z_n = Pauli("".join(pauli_str))

for depth in depth_list:
    # Generate the brickwork stabilizer circuit
    circuit = create_brickwork_clifford(num_qubits, depth)
    circuits_list.append(circuit)

    # Get Clifford object for the circuit
    cliff = Clifford(circuit)
    # Evolve Z^n by the Clifford (Heisenberg picture, default)
    conj_pauli = Z_n.evolve(cliff, frame="s")
    # Convert to SparsePauliOp
    transformed_operator = SparsePauliOp(conj_pauli)
    observables_list.append(transformed_operator)

Para makuha ang mga ideal na value, magpatakbo ng stabilizer simulation. Gumawa ng stabilizer state mula sa bawat quantum circuit gamit ang Qiskit StabilizerState class, na tumatanggap ng QuantumCircuit bilang input at naglalabas ng katumbas na stabilizer state. Pagkatapos, gamitin ang expectation_value method para kalkulahin ang ideal na expectation value, na sa disenyo ay 1 para sa bawat pares ng circuit at observable.

from qiskit.quantum_info import StabilizerState

stabilizer_result_ideal_evs = []
for index in range(len(depth_list)):
    # Expectation value calculated using stabilizer group algebra, NOT matrix multiplication
    circuit = circuits_list[index]
    observable = observables_list[index]

    stab_state = StabilizerState(circuit)
    exp_val = stab_state.expectation_value(observable)
    stabilizer_result_ideal_evs.append(int(exp_val.real))

print(
    f"Ideal Results from Stabilizer Simulation:{stabilizer_result_ideal_evs}"
)

I-extract at i-visualize ang mga resulta​

Pagkatapos matapos ang job, kolektahin ang mga expectation value at standard deviation mula sa bawat resulta ng PUB. Para sa bawat circuit depth, kasama sa mga resulta ang mga noisy (unmitigated) na value, noisy_evs at noisy_stds, at ang mga value pagkatapos ng mitigation gamit ang AI-QEM, mitigated_evs at mitigated_stds.

Pagkatapos, gamitin ang plot_clifford_results function para i-plot ang expectation value laban sa circuit depth. Naglalaman ang plot ng mga sumusunod:

  • Unmitigated: Ang mga raw na expectation value na ibinalik ng hardware, na ipinapakita kasama ng mga error bar na may laking ±σ\pm\sigma±σ.

  • Mitigated (AI-QEM): Ang mga expectation value pagkatapos ng error mitigation, na ipinapakita rin kasama ng mga error bar.

  • Ideal (stabilizer simulation): Ang walang-noise na expectation value, ⟨O⟩ideal=1\langle O \rangle_{\text{ideal}} = 1⟨O⟩ideal​=1, para sa lahat ng depth.

  • Threshold: Isang gray na band na sumasaklaw sa −0.1≤⟨O⟩≤0.1-0.1 \le \langle O \rangle \le 0.1−0.1≤⟨O⟩≤0.1. Ang mga value sa loob ng band na ito ay walang kapaki-pakinabang na signal na ima-mitigate, kaya iniiwan ang mga ito na unmitigated.

# Extract results
results = clifford_job.result()

noisy_evs, noisy_stds = [], []
mitigated_evs, mitigated_stds = [], []

for pub_result in results:
    data = pub_result.data
    # Mitigated values
    mitigated_evs.append(data.evs)
    mitigated_stds.append(data.stds)
    # Noisy values (raw values returned by the hardware)
    noisy_evs.append(data.noisy_evs)
    noisy_stds.append(data.noisy_stds)
import matplotlib.pyplot as plt
import numpy as np

def plot_clifford_results(
    depth_list,
    noisy_evs,
    noisy_stds,
    mitigated_evs,
    mitigated_stds,
    ideal_evs,
):
    """Plot unmitigated, mitigated and ideal expectation values vs circuit depth."""
    style = dict(marker="*", markeredgecolor="black", markeredgewidth=0.5)

    plt.figure(figsize=(12, 6))
    plt.errorbar(
        depth_list,
        noisy_evs,
        yerr=noisy_stds,
        label="Unmitigated",
        capsize=4,
        **style,
    )
    plt.errorbar(
        depth_list,
        mitigated_evs,
        yerr=mitigated_stds,
        label="Mitigated (AI-QEM)",
        capsize=4,
        **style,
    )
    plt.plot(
        depth_list, ideal_evs, label="Ideal (Stabilizer simulation)", **style
    )
    # Threshold: Gray-out y = -0.1 to 0.1
    plt.axhspan(-0.1, 0.1, color="gray", alpha=0.3, label="Threshold")

    plt.xticks(depth_list)
    plt.xlabel("Circuit Depth")
    plt.ylabel("Expectation Value")
    plt.title("Clifford Circuit Simulation")
    plt.grid(alpha=0.3)
    plt.ylim(-0.2, 1.2)
    plt.legend(loc="upper left", bbox_to_anchor=(1, 1))
    plt.show()

# Flatten
clifford_results = {
    "noisy_evs": np.asarray(noisy_evs),
    "noisy_stds": np.asarray(noisy_stds),
    "mitigated_evs": np.asarray(mitigated_evs),
    "mitigated_stds": np.asarray(mitigated_stds),
    "ideal_evs": np.ones_like(noisy_evs),
}

plot_clifford_results(np.asarray(depth_list), **clifford_results)
