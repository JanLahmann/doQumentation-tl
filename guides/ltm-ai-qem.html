tala

Ang IBM Quantum® Functions ay isang beta feature na available lang sa mga user ng IBM Quantum Premium Plan, Flex Plan, at On-Prem (sa pamamagitan ng IBM Quantum Platform API) Plan. Puwedeng magbago ang mga beta feature.

Mga kasalukuyang limitasyon

Ang kasalukuyang release ng AI-QEM ay may mga sumusunod na limitasyon:

  • Limitado ang mitigation sa pamilya ng Heron processor. Plano ng LTM na suportahan ang mga karagdagang backend sa mga susunod na bersyon.

  • Pinipili lang ang pagkakataon ng error mitigation. Isinasagawa lang ang mitigation kapag ang absolute expectation value ay nakakatugon sa ∣⟨O⟩noisy∣≥0.1|\langle O \rangle_{noisy}| \geq 0.1∣⟨O⟩noisy​∣≥0.1, para magamit lang ang mitigation kung saan inaasahang magbibigay ito ng makabuluhang benepisyo.

Sumasalamin ang mga limitasyong ito sa kasalukuyang saklaw ng AI-QEM. Maaaring luwagan ng mga susunod na release ang mga ito habang nagdaragdag ang LTM ng suporta para sa mga karagdagang workflow, backend, at feature.

Pangkalahatang-ideya​

Ang quantum error mitigation (QEM) ay sumasaklaw sa mga algorithmic protocol, tulad ng zero-noise extrapolation (ZNE) [2] at probabilistic error cancellation (PEC) [3], na idinisenyo para pigilan ang bias na dulot ng noise sa mga expectation value sa noisy intermediate-scale quantum (NISQ) hardware, nang hindi nangangailangan ng malaking qubit overhead ng ganap na fault tolerance. Mahalaga ang mga paraang ito para makakuha ng maaasahang pisikal na simulation at benchmark result mula sa mga kasalukuyang processor. Bagaman maraming QEM method ang nabuo nitong mga nakaraang taon, halos lahat ng mga ito ay may iisang pangunahing trade-off: umaasa sila sa mas mahabang QPU time para makamit ang katumpakan. Ang tumutukoy sa limitasyon nila ay ang exponential na sampling overhead, dahil ang muling pagbuo ng unbiased na signal mula sa mga noisy circuit ay lubhang nagpapataas sa statistical variance ng estimator. Dahil dito, ang pagtagumpayan sa mas mataas na antas ng noise ay nangangailangan ng ilang order of magnitude na mas maraming measurement shot, na humahantong sa mas mahabang QPU runtime at malalaking hardware bottleneck [4, 5, 6].

Gamit ang AI-QEM, puwede kang magpatakbo ng mga quantum circuit sa mga noisy QPU at makakuha ng mas pinahusay na expectation value kumpara sa ibang AI-based na error mitigation technique, nang walang karagdagang QPU runtime overhead. Gumagamit ang paraan ng deep neural network na may graph convolutional network (GCN)-Transformer architecture. Sinasanay ang network sa mga feature na kinabibilangan ng istruktura ng circuit, topology ng backend, mga Pauli observable, at mga qubit calibration, at nagpe-predict ito ng correction factor, na tinutukoy ng ζ\zetaζ. Ang paghahati sa noisy expectation value sa ζ\zetaζ ay nagbubunga ng pinahusay na expectation value. Ipinapakita ng mga eksperimento na mas mahusay ang resulta ng AI-QEM kaysa sa ibang AI-based na mitigation method, lalo na para sa mga circuit na may malaking depth (mga layer ng gate) at width (bilang ng mga qubit), kaya angkop ito para sa mga utility-scale na quantum experiment. Ipinapakita ng talahanayan sa seksyong Benchmarks na nahihigitan ng GCN-Transformer-based na model ang mga random forest (RF)-based na model sa saklaw na 80 hanggang 150 qubit, na may mean absolute error (MAE) na 0.343. Ang MAE ay ang average, sa maraming configuration ng circuit at observable, ng absolute na pagkakaiba ng ideal na expectation value at ng expectation value matapos bawasan ng model ang noise sa resulta ng noisy hardware. Bukod pa rito, dahil circuit-agnostic ang model, magagamit mo ito sa malawak na hanay ng mga quantum circuit at aplikasyon nang hindi kailangan ng customization na partikular sa circuit.

Para sa buong paglalarawan ng mga pinagbabatayang component at isang utility-scale na demonstrasyon, tingnan ang AI-QEM paper [1].

Paglalarawan​

Gamitin ang LTM AI-QEM function para tantiyahin ang mga expectation value ng mga observable para sa isang quantum circuit. Para magamit ang LTM AI-QEM, magbigay ng quantum circuit, set ng mga observable na susukatin, at isang QPU. Gumagamit ang function ng parehong QPU time gaya ng IBM Quantum Estimator primitive, at walang karagdagang QPU time.

Ang karaniwang paraan para kalkulahin ang expectation value ng observable na OOO ay hatiin ang observable sa kabuuan ng mga Pauli operator, O=∑iciPiO=\sum_i{c_i}{P_i}O=∑i​ci​Pi​, at kalkulahin nang isa-isa ang expectation value ng bawat Pauli operator, ⟨Pi⟩\langle P_i \rangle⟨Pi​⟩. Ang expectation value ng observable, ⟨O⟩\langle O \rangle⟨O⟩, ay ang parehong linear combination ng mga Pauli expectation value: ⟨O⟩=∑ici⟨Pi⟩{\langle O \rangle}=\sum_i{c_i}{\langle P_i \rangle}⟨O⟩=∑i​ci​⟨Pi​⟩. Kung ang isang set ng mga Pauli operator ay nagko-commute sa isa't isa, maaaring sabay-sabay na gawin ang mga sukat na kailangan para kalkulahin ang kanilang mga expectation value. Kapag nagpatakbo ka ng circuit gamit ang LTM AI-QEM function, ginagamit ng function ang Estimator primitive para patakbuhin ang circuit sa hardware gaya ng dati. Sinusunod nito ang parehong pamamaraan ng paghahati sa observable sa mga Pauli operator at pagkalkula ng kanilang mga expectation value nang isa-isa. Pagkatapos, ang GCN-Transformer, isang deep learning architecture, ay nagpe-predict ng correction factor na ζi\zeta_iζi​ para sa bawat Pauli operator na PiP_iPi​. Ginagamit ng function ang correction factor na ito para itama ang noisy expectation value ng bawat Pauli operator: ⟨Pi⟩mitigated=⟨Pi⟩noisyζi{\langle P_i \rangle}_{mitigated} = \frac{{\langle P_i \rangle}_{noisy}}{\zeta_i}⟨Pi​⟩mitigated​=ζi​⟨Pi​⟩noisy​​. Samakatuwid, ang mitigated expectation value ay ⟨O⟩mitigated=∑ici⟨Pi⟩mitigated=∑ici⟨Pi⟩noisyζi{\langle O \rangle}_{mitigated} = \sum_i{c_i}{\langle {P_i} \rangle}_{mitigated} = \sum_i{c_i}{\frac{{\langle P_i \rangle}_{noisy}}{\zeta_i}}⟨O⟩mitigated​=∑i​ci​⟨Pi​⟩mitigated​=∑i​ci​ζi​⟨Pi​⟩noisy​​.

Ang workflow para sa paggamit ng LTM AI-QEM function ay ang sumusunod:

  1. Tukuyin ang iyong mga circuit at observable.

  2. Patakbuhin ang LTM AI-QEM function sa pamamagitan ng pagpasa ng circuit at mga pares ng observable bilang primitive unified blocs (PUBs).

  3. Kunin ang mga resulta, na naglalaman ng expectation value ng observable kaugnay ng katumbas na quantum circuit sa bawat PUB.

Maraming test example ang empirikal na nagpapakitang pinapabuti ng LTM AI-QEM function ang pagtantiya ng mga observable. Ang function ay may mga sumusunod na feature:

  • Mga utility-scale na eksperimento: Ipinapakita ng mga test example na mas mahusay ang AI-QEM kaysa sa ibang AI-based na paraan para sa mga circuit na may malaking depth at malaking width. Tingnan ang seksyong Benchmarks para sa mga resulta.

  • Primitive: Sinusuportahan ng function ang Estimator primitive, kaya magagamit mo ito para kalkulahin ang expectation value ng anumang observable kaugnay ng anumang quantum circuit.

  • Primitive unified bloc (PUB): Sinusuportahan ng LTM AI-QEM function ang lahat ng uri ng PUB (ibig sabihin, lahat ng configuration ng circuit-observable) na sinusuportahan ng Estimator primitive.

Nagsisimula ang AI-QEM technique sa pagbuo ng dataset, kung saan gumagawa ng mga random na quantum circuit na may iba't ibang setting ng parameter. Para sa bawat circuit, kinakalkula ang parehong ideal na expectation value (nakuha sa pamamagitan ng simulation) at noisy na expectation value (nakuha mula sa pagpapatakbo sa hardware). Ang mga resultang ito, kasama ang kaukulang mga quantum circuit at impormasyon ng backend, ay iniimbak sa isang dataset repository. Ginagamit ang dataset para sanayin ang machine-learning o deep-learning model na kayang bawasan ang noise sa mga quantum computation, at sine-save ang sinanay na model para sa susunod na gamit. Sa inference, ang sinanay na model ay tumatanggap bilang input ng isang quantum circuit, ang noisy expectation value nito na kinalkula sa hardware, ang mga kaugnay na observable, at impormasyon ng backend. Pagkatapos ay pinoproseso ng model ang mga input na ito para makabuo ng expectation value na nabawasan ang noise.

Tandaan: Ang CPU time ay ang oras ng post-processing. Magkakasamang isinumite sa isang run ang tatlong mirror circuit, kaya ang naitalang QPU at CPU time ay para sa lahat ng tatlong circuit nang magkakasama. Ang bawat run ng Clifford circuit ay may siyam na PUB na may iba't ibang circuit depth, kaya ang naitalang oras ay para sa lahat ng siyam na PUB nang magkakasama. Ang bawat run ng Ising circuit ay may 10 PUB na may iba't ibang bilang ng Trotter step, kaya ang naitalang oras ay para sa lahat ng 10 PUB nang magkakasama.

Para sa mga mirror circuit, gumagamit ang mga benchmark ng mga ansatz na RealAmplitudes, TwoLocal, at EfficientSU2 na may 30, 35, at 40 qubit, ayon sa pagkakasunod. Binubuo ang mga observable ng iisang Pauli-ZZZ operator sa isang random na napiling qubit, na may ideal na expectation value na 1.

Para sa mga Clifford circuit, gumagamit ang mga benchmark ng mga circuit na may 50 at 100 qubit na may mga observable na sinimulan bilang isa o higit pang random na nakaposisyong Pauli-ZZZ operator. Pinapataas ng operator evolution ang Pauli weight ng mga observable na ito, na nagbibigay ng mas masalimuot na mga observable para sa benchmarking. Binuo ang mga observable para magkaroon ng ideal na expectation value na 1, na hiwalay na beneripika gamit ang stabilizer simulation.

Para sa mga simulation ng Trotterized 2D tilted-field Ising (TFI) Hamiltonian, gumagamit ang mga benchmark ng tatlong parameter regime: small angle (θX,θZ,θZZ)=(0.1,0.1,0.1)(\theta_X,\theta_Z,\theta_{ZZ})=(0.1,0.1,0.1)(θX​,θZ​,θZZ​)=(0.1,0.1,0.1), near-Clifford (0.1,0.05,1.5708)(0.1,0.05,1.5708)(0.1,0.05,1.5708), at chaotic (0.53,0.1,1.0)(0.53,0.1,1.0)(0.53,0.1,1.0). Ang observable ay ang average magnetization,

OM=1M∑iZi,O_M = \frac{1}{M}\sum_i Z_i,OM​=M1​i∑​Zi​,

kung saan ang MMM ay ang bilang ng mga qubit sa simulation. Kinakalkula ang mga ideal na expectation value gamit ang sparse Pauli dynamics (SPD), isang Pauli propagation method, at bineberipika laban sa mga Qiskit statevector simulation para sa mga circuit na wala pang 29 qubit.

Humingi ng suporta​

Nandito ang AI-QEM support team para tumulong. Kung may makaharap kang mga isyu, may mga tanong tungkol sa paggamit ng AI-QEM Function, o kailangan mo ng tulong sa pag-troubleshoot ng job, makipag-ugnayan sa support team.

Suporta: quantumfunction.support@ltm.com

Para matulungan ang support team na imbestigahan at lutasin ang isyu mo nang mabilis hangga't maaari, isama ang sumusunod na impormasyon sa support request mo:

  • Job ID ng Function (halimbawa, job.job_id)

  • Detalyadong paglalarawan ng isyu

  • Anumang kaugnay na error message, stack trace, o error code

  • Inaasahang gawi at aktwal na gawi (kung naaangkop)

Nakakatulong ang kumpletong impormasyon para mas mahusay na ma-diagnose ng support team ang mga isyu at mas mabilis itong malutas.

Malugod ding tinatanggap ng AI-QEM support team ang feedback at mga feature request. Kung may mga mungkahi ka para sa mga pagpapabuti o kakayahang gusto mong makita sa mga susunod na release, ipadala ang mga ito sa quantumfunction.support@ltm.com.
