SQOA Solver ng JIJ

Tingnan ang API reference.

tala

Ang IBM Quantum® Functions ay isang beta feature na available lang sa mga user ng IBM Quantum Premium Plan, Flex Plan, at On-Prem (sa pamamagitan ng IBM Quantum Platform API) Plan. Puwedeng magbago ang mga beta feature.

Overview​

Gamit ang SQOA Solver ng JIJ, malulutas mo ang malalaking combinatorial optimization problem sa mga quantum computer ng IBM®. Ang solver ay batay sa Sampling-based Quantum Optimization Algorithm with Quantum Relaxation (SQOA-QR) [1]. Hindi tulad ng mga quantum algorithm na gumagamit ng one-to-one mapping sa pagitan ng classical decision variable at qubit, kaya ng SQOA Solver na humawak ng mga optimization problem na mas marami ang variable kaysa sa bilang ng qubit na available sa mga kasalukuyang quantum device. Dahil sa sampling-based na disenyo nito, mas hindi rin ito sensitibo sa physical noise ng kasalukuyang quantum hardware. Dahil sa mga katangiang ito, bagay na bagay ang SQOA Solver sa mga optimization problem sa kasalukuyang yugto ng quantum computing.

Hinahawakan ng solver ang mga Quadratic Unconstrained Binary Optimization (QUBO) problem na ibinigay bilang classical mathematical formulation, at awtomatiko nitong imamapa ang classical formulation sa quantum setting. Puwede mo ring gawing unconstrained ang mga constrained problem gamit ang penalty method.

Inilalarawan ng mga sumusunod na seksyon ang workflow ng solver, mga resulta ng benchmark, at mga end-to-end na halimbawa na nagmo-model ng mga problema gamit ang qiskit-addon-opt-mapper at, opsyonal, ang Open Mathematical prograMming eXchange (OMMX). Ang OMMX ay isang open data format at SDK na nagpapadali sa pagpapalitan ng mga optimization problem sa pagitan ng mga software tool.

Paglalarawan​

Ipinapatupad ng SQOA Solver ang Sampling-based Quantum Optimization Algorithm with Quantum Relaxation (SQOA-QR) at nilalagyan ito ng classical preprocessing at postprocessing sa paligid. Ipinapaliwanag ng seksyong ito ang SQOA framework at kung paano ito naiiba sa Quantum Approximate Optimization Algorithm (QAOA).

Ipinapakita ng sumusunod na figure ang schematic ng workflow ng SQOA Solver.

Ang SQOA framework​

Ang SQOA ay isang sampling-based na framework para sa combinatorial optimization [1]. Pinagsasama nito ang dalawang technique: ang Quantum Random Access Optimization (QRAO) [2], na nag-e-encode ng problema sa isang quantum relaxation, at ang sample-based quantum diagonalization (SQD) [3], na kilala rin bilang quantum-selected configuration interaction (QSCI) [4], na gumagamit ng quantum computer para lang mag-sample ng mga bitstring at hinahanap ang low-energy state sa isang classical computer. Ang SQOA ay isang framework dahil itinatakda nito ang kombinasyong ito pero iniiwan ang mga detalye sa bawat implementasyon, tulad ng kung paano itinatalaga ang mga variable sa mga qubit at kung aling mga circuit ang gumagawa ng mga sample.

  • Quantum relaxation gamit ang QRAO. Ang QAOA at iba pang Ising-based na approach ay kumakatawan sa bawat binary variable gamit ang ZZZ operator ng qubit nito. Gumagamit din ang QRAO ng mga XXX at YYY operator. Sa (3,1) quantum random access code (QRAC), hanggang tatlong binary variable ang puwedeng magbahagi ng isang qubit, at ang bawat variable ay kinakatawan ng ibang Pauli operator.

    Ang QUBO ay nagiging relaxed Hamiltonian na mas kaunti ang kailangang qubit kaysa sa Ising Hamiltonian. Ang mga variable na nag-i-interact sa QUBO ay dapat ilagay sa magkakaibang qubit. Kung magbabahagi sila ng qubit, ang product ng kanilang mga Pauli operator ay magiging iisang operator na lang sa qubit na iyon (halimbawa, XY=iZXY = iZXY=iZ), at hindi na kakatawanin ng relaxed Hamiltonian ang interaction nila.

    Kaya ang pagtatalaga ng mga variable sa mga qubit ang nagtatakda ng bilang ng qubit at ng kalidad ng relaxation, at dinidisenyo ng SQOA Solver ang pagtatalagang ito sa preprocessing nito.

  • Sample-based quantum diagonalization (SQD). Naghahanda muna ang quantum computer ng quantum state na may overlap sa mga low-energy state ng relaxed Hamiltonian, at pagkatapos ay nag-sample ng mga bitstring mula rito. Ipino-project ng classical computer ang relaxed Hamiltonian sa subspace na sakop ng mga na-sample na bitstring at dina-diagonalize ito para tantiyahin ang ground state.

    Dahil non-diagonal ang relaxed Hamiltonian, pinagsasama ng diagonalization ang mga na-sample na bitstring sa isang superposition. Sa diagonal na Ising Hamiltonian, eigenstate na ang bawat bitstring, at pipiliin lang ng diagonalization ang pinakamahusay na sample. Ang parehong approach ay naipatupad na sa malalaking problema sa quantum chemistry.

Ang tinatayang ground state na nakuha ng SQD ay hindi direktang tumutugma sa isang classical na solusyon ng orihinal na problema, kaya kailangang i-decode mula rito ang classical na solusyon. Dahil kinukuwenta ang state na ito sa isang classical computer, ang decoding, na tinatawag na rounding, ay classical postprocessing. Gumagamit ang SQOA Solver ng mga decoding technique na idinisenyo para heuristic na makakuha ng mas magagandang classical na solusyon.

Inihahambing ng sumusunod na table ang SQOA sa QAOA, isang karaniwang variational approach para sa parehong klase ng mga problema.

Ihanda ang input gamit ang qiskit-addon-opt-mapper​

Nagmo-model ang gabay na ito ng mga problema gamit ang OptimizationProblem class ng qiskit-addon-opt-mapper. Tumatanggap ang SQOA Solver ng QUBO problem bilang coefficient dictionary sa tuple-string format na ginagamit ng mga IBM optimization function, kaya ang bawat halimbawa sa gabay na ito ay sumusunod sa parehong client-side na pattern ng paghahanda:

  1. Isulat ang model. Gumawa ng OptimizationProblem, magdagdag ng mga binary decision variable, at itakda ang objective at anumang constraint.

  2. I-convert sa QUBO. I-convert ang problema gamit ang OptimizationProblemToQubo, na nagdaragdag ng anumang constraint sa objective bilang mga penalty term at nagbabalik ng katumbas na unconstrained minimization problem.

  3. I-convert sa dictionary. Ipasa ang QUBO sa helper function na to_problem_dict() na tinukoy sa susunod na seksyon, at ipasa ang resulta sa solver.run() bilang problem, kasama ang variable_type="binary".

Laging minimina ng SQOA Solver ang isang dictionary problem, na tugma sa minimization problem na ibinabalik ng OptimizationProblemToQubo. Para sa maximization problem, ang ibinalik na objective_value ay ang negatibo ng orihinal na objective. Para mabasa ang resulta ayon sa orihinal na problema, i-evaluate ang ibinalik na assignment gamit ang OptimizationProblem, gaya ng ipinapakita ng mga halimbawa. Para sa mga detalye ng dictionary format, tingnan ang Accepted problem formats sa API reference.

# %pip install qiskit-addon-opt-mapper

Tukuyin nang isang beses ang sumusunod na helper function at gamitin ito ulit sa bawat halimbawa. Kino-convert nito ang QUBO na ibinalik ng OptimizationProblemToQubo sa dictionary format. Ang mga key ay gumagamit ng mga variable index ng QUBO, kaya ang mga solution key na x_0, x_1, at iba pa sa resulta ay tumutugma sa mga index na iyon. Bawat variable ay tumatanggap ng linear entry, kahit zero ang coefficient, para saklaw ng ibinalik na solusyon ang lahat ng variable.

from qiskit_addon_opt_mapper import OptimizationProblem
from qiskit_addon_opt_mapper.converters import OptimizationProblemToQubo

def to_problem_dict(qubo: OptimizationProblem) -> dict[str, float]:
    """Convert a QUBO from OptimizationProblemToQubo to the SQOA Solver dictionary format."""
    objective = qubo.objective
    payload = {"()": objective.constant}
    # Keep every variable in the problem, even with a zero linear coefficient.
    payload.update({f"({i},)": 0.0 for i in range(qubo.get_num_vars())})
    for i, coefficient in objective.linear.to_dict().items():
        payload[f"({i},)"] += coefficient
    for (i, j), coefficient in objective.quadratic.to_dict().items():
        # Fold a binary diagonal term x_i * x_i = x_i into the linear term.
        key = f"({i},)" if i == j else f"({i}, {j})"
        payload[key] = payload.get(key, 0.0) + coefficient
    return {key: float(value) for key, value in payload.items()}

Mga laki ng Function​

Bawat job ay tumatakbo sa isang laki: "S", "M", o "L". Kung masyadong maliit ang laki, tatanggihan ang job. Kung mas malaki ito kaysa sa kailangan, tatakbo ang job sa mas malaking compute profile kaysa sa hinihingi ng gawain. Tingnan ang Mga laki ng Function para sa kung paano gumagana ang mga laki sa pangkalahatan.

Nagmumula ang laki sa dalawang katangian ng QUBO na isinusumite mo: kung ilan ang mga variable nito, at kung gaano kasiksik ang interaksyon ng mga ito, ibig sabihin, ang bahagi ng lahat ng pares ng variable na magkasamang lumalabas sa isang quadratic term na may nonzero na coefficient.

Pinapalitan ng OptimizationProblemToQubo ang bawat constraint ng penalty term, at ang pag-square sa constraint ay nagdudugtong sa bawat pares ng variable dito, kaya ang one-hot constraint sa apat na variable ay nag-aambag ng lahat ng anim na pares.

Ang default na laki, na ginagamit kapag walang hiniling na laki ang job, ay "M". Mababasa mo rin ang mapping mula sa function mismo gamit ang solver.sizes_map, at ang default na laki gamit ang solver.default_size.

# %pip install ommx
# Calculate the function size a problem needs, before submitting it.
# calculate_function_size(problem) returns "S", "M", or "L" and submits
# nothing. The size comes from the number of variables and how densely
# they interact.

from collections.abc import Iterator
from itertools import combinations
from typing import Any, Literal

from qiskit_addon_opt_mapper.problems import OptimizationProblem

Size = Literal["S", "M", "L"]
_ORDER = {"S": 0, "M": 1, "L": 2}

# Limits are provided by IBM
_SMALL_NUMVARS, _SMALL_DENSITY = 50, 0.1
_MEDIUM_NUMVARS, _MEDIUM_DENSITY = 100, 0.25

def calculate_function_size(problem: Any, **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") needed to run ``problem``."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def to_optimization_problem(problem: Any) -> OptimizationProblem:
    """Convert SQOA input into an ``OptimizationProblem``.

    Accept an OMMX ``Instance`` directly, or a dictionary containing a coefficient
    dictionary as ``problem`` and ``"binary"`` or ``"spin"`` as ``variable_type``.
    Convert to a binary minimization problem with consecutive variable IDs from zero.
    Leave the input instance unchanged.
    Return an existing ``OptimizationProblem`` unchanged.
    """
    if isinstance(problem, OptimizationProblem):
        return problem
    import ast
    import math
    import re

    from ommx.v1 import DecisionVariable, Instance, Kind

    _TERM_ID = r"(?:0|[1-9][0-9]*)"
    _TERM_SPACE = r"[ \t\r\n]*"
    _TERM_KEY_PATTERN = (
        rf"^\({_TERM_SPACE}(?:{_TERM_ID}{_TERM_SPACE},"
        rf"{_TERM_SPACE}(?:{_TERM_ID}{_TERM_SPACE}(?:,{_TERM_SPACE})?)?)?\)(?![\s\S])"
    )

    def _term_ids(key: str) -> tuple[int, ...]:
        if (
            not isinstance(key, str)
            or re.fullmatch(_TERM_KEY_PATTERN, key) is None
        ):
            raise ValueError("invalid term key")
        ids = ast.literal_eval(key)
        if len(set(ids)) != len(ids):
            raise ValueError("repeated variable ID")
        return tuple(sorted(ids))

    def _dictionary_to_instance(
        problem: dict[str, object], variable_type: str
    ) -> Instance:
        terms: dict[tuple[int, ...], float] = {}
        variable_ids: set[int] = set()
        for key, value in problem.items():
            ids = _term_ids(key)
            if type(value) not in (int, float):
                raise ValueError("invalid coefficient")
            coefficient = float(value)
            if not math.isfinite(coefficient):
                raise ValueError("invalid coefficient")
            variable_ids.update(ids)
            terms[ids] = terms.get(ids, 0.0) + coefficient
            if not math.isfinite(terms[ids]):
                raise ValueError("coefficient overflow")
        variables = {
            i: DecisionVariable.binary(i) for i in sorted(variable_ids)
        }
        expressions = {
            i: 1 - 2 * variable if variable_type == "spin" else variable
            for i, variable in variables.items()
        }
        objective = 0.0
        for ids, coefficient in terms.items():
            term = coefficient
            for i in ids:
                term = term * expressions[i]
            objective = objective + term
        return Instance.from_components(
            decision_variables=list(variables.values()),
            objective=objective,
            constraints=[],
            sense=Instance.MINIMIZE,
        )

    if isinstance(problem, Instance):
        instance = problem
    else:
        if (
            not isinstance(problem, dict)
            or not {"problem", "variable_type"} <= problem.keys()
        ):
            raise ValueError(
                "SQOA sizing requires an OMMX Instance or a coefficient input envelope "
                "with 'problem' and 'variable_type'"
            )
        variable_type = problem["variable_type"]
        if variable_type not in ("binary", "spin"):
            raise ValueError("variable_type must be binary or spin")
        if not isinstance(problem["problem"], dict):
            raise ValueError(
                "problem must be a coefficient dictionary; pass OMMX Instances directly"
            )
        instance = _dictionary_to_instance(problem["problem"], variable_type)

    variables = list(instance.decision_variables)
    degree = instance.objective.degree()
    if not variables:
        raise ValueError(
            "problem must contain at least one decision variable"
        )
    if any(variable.kind == Kind.Continuous for variable in variables):
        raise ValueError(
            "problem must not contain Continuous decision variables"
        )
    if degree > 2:
        raise ValueError("problem objective degree must be at most two")
    # Copy the instance so minimization does not modify the caller's original.
    normalized = Instance.from_bytes(instance.to_bytes())
    normalized.as_minimization_problem()
    qubo, offset = normalized.as_qubo_format()
    if not math.isfinite(offset) or any(
        not math.isfinite(v) for v in qubo.values()
    ):
        raise ValueError("problem objective coefficients must all be finite")

    ids = [variable.id for variable in variables]
    dense_ids = {
        variable_id: index for index, variable_id in enumerate(sorted(ids))
    }
    linear = {}
    quadratic = {}
    for (first, second), coefficient in qubo.items():
        i, j = dense_ids[first], dense_ids[second]
        if i == j:
            linear[i] = linear.get(i, 0.0) + coefficient
        else:
            pair = (min(i, j), max(i, j))
            quadratic[pair] = quadratic.get(pair, 0.0) + coefficient

    model = OptimizationProblem()
    model.binary_var_list(len(ids), name="x")
    model.minimize(
        constant=offset,
        linear=linear,
        quadratic=quadratic,
    )
    return model

def _measure(problem: Any, **kwargs: Any) -> dict[str, float]:
    """Return the number of variables and the interaction density."""
    model = to_optimization_problem(problem)
    num_vars = model.get_num_vars()

    pairs = set()
    for term in _interactions(model):
        pairs.update(frozenset(pair) for pair in combinations(set(term), 2))

    max_pairs = num_vars * (num_vars - 1) // 2
    return {
        "num_vars": num_vars,
        "density": len(pairs) / max_pairs if max_pairs else 0.0,
    }

def _interactions(problem: OptimizationProblem) -> Iterator[tuple[int, ...]]:
    """Yield the variables of every term that couples two or more of them.

    A constraint contributes every variable in it, because on hardware it becomes
    a penalty whose square couples them all.
    """
    objective = problem.objective
    yield from objective.quadratic.to_dict()
    for expression in objective.higher_order.values():
        yield from expression.to_dict()

    for constraint in problem.linear_constraints:
        yield _constraint_support(constraint)
    for constraint in problem.quadratic_constraints:
        yield _constraint_support(constraint)
    for constraint in problem.higher_order_constraints:
        yield _constraint_support(constraint)

def _constraint_support(constraint: Any) -> tuple[int, ...]:
    """Return every variable appearing in a constraint's left-hand side."""
    variables = set(constraint.linear.to_dict())
    if hasattr(constraint, "quadratic"):
        for term in constraint.quadratic.to_dict():
            variables.update(term)
    if hasattr(constraint, "higher_order"):
        for expression in constraint.higher_order.values():
            for term in expression.to_dict():
                variables.update(term)
    return tuple(variables)

def _is_small(metrics: dict[str, float]) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return (
        metrics["num_vars"] <= _SMALL_NUMVARS
        and metrics["density"] <= _SMALL_DENSITY
    )

def _is_medium(metrics: dict[str, float]) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return (
        metrics["num_vars"] <= _MEDIUM_NUMVARS
        and metrics["density"] <= _MEDIUM_DENSITY
    )

1. Isulat ang model​

Magtalaga ng binary variable na xv∈{0,1}x_v \in \{0, 1\}xv​∈{0,1} sa bawat vertex ng graph na G=(V,E)G = (V, E)G=(V,E) para ipahiwatig ang panig nito sa cut. Ang isang edge ay na-cut kapag magkaibang panig ang mga dulo nito, kaya ang laki ng cut ay:

Cut(x)=∑(u,v)∈E(xu+xv−2xuxv).\mathrm{Cut}(x) = \sum_{(u,v) \in E} \left(x_u + x_v - 2 x_u x_v\right).Cut(x)=(u,v)∈E∑​(xu​+xv​−2xu​xv​).

Ang objective na ito ay QUBO na mismo nang walang constraint, kaya ginagawa lang ng OptimizationProblemToQubo na katumbas na minimization ang maximization at pinananatiling hindi nagbabago ang mga variable. Binubuo ng Maxcut application class sa qiskit_addon_opt_mapper.applications ang parehong model gamit ang Maxcut(G).to_optimization_problem().

import networkx as nx

G = nx.random_regular_graph(3, 40, seed=42)

linear = {v: 0 for v in G.nodes}
quadratic = {}
for u, v in G.edges:
    linear[u] += 1
    linear[v] += 1
    quadratic[(u, v)] = -2

maxcut = OptimizationProblem("MaxCut")
maxcut.binary_var_list(G.number_of_nodes(), name="x")
maxcut.maximize(linear=linear, quadratic=quadratic)

2. Patakbuhin ang solver​

I-convert ang model sa QUBO at pagkatapos ay sa dictionary, at isumite ito. Kailangan ang problem at variable_type. Opsyonal ang backend_name. Kapag hindi ito ibinigay o None, pinipili ng function ang pinakamaluwag na operational na QPU na available sa instance mo.

Tumatanggap ang options dictionary ng shots, seed, session, postprocessing_level, at job_tags. Para sa mga paglalarawan at default, tingnan ang API reference.

Pinipili ng argumentong function_size ang mga computing resource para sa job. Ipasa ito nang direkta sa solver.run(), sa labas ng options. Kalkulahin ito gamit ang calculate_function_size() mula sa Mga laki ng Function. May 40 node at 60 edge ang graph, kaya ang QUBO ay may 40 variable at density na humigit-kumulang 0.08, na pasok sa "S".

qubo = OptimizationProblemToQubo().convert(maxcut)
problem = to_problem_dict(qubo)

size = calculate_function_size(
    {"problem": problem, "variable_type": "binary"}
)

    variable_type="binary",
    backend_name="ibm_fez",
    options={
        "shots": 4096,
        "seed": 42,

    function_size=size,

3. Kunin ang resulta​

Nagbabalik ang job.result() ng dictionary na may apat na key:

  • Ang solution ay ang kumpletong variable assignment, na naka-key sa x_i, kung saan ang i ay ang variable index (halimbawa, x_3).

  • Ang objective_value at feasible ay ang objective at feasibility ng assignment na iyon, na na-evaluate sa isinumiteng dictionary.

  • Hawak ng metadata ang solver_info at resource_usage.

Dahil ang QUBO ang minimization form ng MaxCut, ang objective_value ay ang negatibo ng laki ng cut. I-evaluate ang assignment sa orihinal na OptimizationProblem para direktang mabasa ang laki ng cut.

result = job.result()

x = [result["solution"][f"x_{i}"] for i in range(maxcut.get_num_vars())]
print(f"Cut value: {maxcut.objective.evaluate(x)}")
print(f"Nodes on side 1: {[v for v, value in enumerate(x) if value > 0.5]}")

Tumatanggap ang SQOA Solver ng mga unconstrained problem. Ipinapakita ng halimbawang ito kung paano i-convert ang constrained problem sa QUBO gamit ang OptimizationProblemToQubo at imapa pabalik ang resulta sa mga variable ng orihinal na problema.

selection = OptimizationProblem("ConstrainedExample")
selection.binary_var_list(2, name="x")
selection.maximize(linear={"x0": 1, "x1": 1})
selection.linear_constraint({"x0": 1, "x1": 1}, "<=", 1, name="at_most_one")

print(selection.prettyprint())

Idinaragdag ng OptimizationProblemToQubo ang mga constraint sa objective bilang mga penalty term at kino-convert ang problema sa minimization. Nakadepende sa problema ang angkop na penalty weight.

Pagkatapos ng run, imamapa pabalik ng interpret() ang QUBO assignment sa mga variable ng orihinal na problema.

I-evaluate ang objective at ang feasibility sa orihinal na problema. Para sa dictionary problem, ang field na feasible ng resulta ay tumutukoy lang sa variable domain, dahil walang constraint ang dictionary.

Nag-iinteract ang dalawang variable ng QUBO na ito, kaya ang density nito ay 1, at nagbabalik ang calculate_function_size() ng "L".

converter = OptimizationProblemToQubo(penalty=4.0)

Halimbawa 3: Magsumite ng OMMX instance​

Tumatanggap din ang SQOA Solver ng ommx.v1.Instance mula sa OMMX SDK, na pinagsasama ang mga variable name, subscript, at conversion metadata kasama ng problema. Kumpara sa dictionary, may mga sumusunod na bentahe ang OMMX input:

  • Naglalaman din ang resulta ng canonical na ommx.v1.Solution sa solver_info["ommx_solution"].

  • Ang objective_value ay ine-evaluate ayon sa instance, kaya hindi ginagawang negatibo ang objective ng maximization problem.

  • Para sa instance na kinonvert in place gamit ang Instance.to_qubo(), ang feasible ay ine-evaluate laban sa mga orihinal na constraint.

Binubuo ng halimbawang ito ang MaxCut model mula sa Halimbawa 1 gamit ang JijModeling, isang mathematical optimization modeler na nagko-compile ng mga model sa mga OMMX instance. I-install ang JijModeling, na nag-i-install din ng package na ommx:

# %pip install "jijmodeling~=2.8.0"

Nagpapalitan ang SQOA Solver ng OMMX data bilang standard padded Base64 string. Tukuyin ang sumusunod na helper function para sa conversion na ito:

  • Sine-serialize ng to_problem_payload() ang isang ommx.v1.Instance sa string na ipinapasa mo bilang problem.

  • Dine-decode ng to_ommx_solution() ang canonical na ommx.v1.Solution mula sa resulta.

import base64

from ommx.v1 import Instance, Solution

def to_problem_payload(instance: Instance) -> str:
    """Serialize an OMMX instance into the `problem` string for SQOA Solver."""
    return base64.b64encode(instance.to_bytes()).decode()

def to_ommx_solution(result: dict) -> Solution:
    """Decode the canonical OMMX solution from a SQOA Solver result."""
    payload = result["metadata"]["solver_info"]["ommx_solution"]
    return Solution.from_bytes(base64.b64decode(payload, validate=True))

1. Isulat ang model gamit ang JijModeling​

Ang karaniwang spin formulation ng MaxCut sa graph na G=(V,E)G = (V, E)G=(V,E) ay nagtatalaga ng sv∈{−1,+1}s_v \in \{-1, +1\}sv​∈{−1,+1} sa bawat vertex. Ang isang edge ay na-cut kapag susv=−1s_u s_v = -1su​sv​=−1, kaya ang laki ng cut ay:

Cut⁡(s)=∑(u,v)∈E1−susv2.\operatorname{Cut}(s) = \sum_{(u,v) \in E} \frac{1 - s_u s_v}{2}.Cut(s)=(u,v)∈E∑​21−su​sv​​.

Walang native na spin decision variable ang JijModeling, at tumatanggap ang SQOA Solver ng mga binary QUBO variable. Kaya, magdeklara ng bv∈{0,1}b_v \in \{0, 1\}bv​∈{0,1} at tukuyin ang spin-valued na expression sv=1−2bvs_v = 1 - 2b_vsv​=1−2bv​ sa loob ng model. Sa expression na ito, nananatili ang objective sa standard spin form, at ang na-compile na instance ay nananatiling binary QUBO.

import jijmodeling as jm

@jm.Problem.define("MaxCut", sense=jm.ProblemSense.MAXIMIZE)
def maxcut_model(problem: jm.DecoratedProblem):
    V = problem.Natural()  # number of nodes
    E = problem.Graph(dtype=V)  # edge list
    b = problem.BinaryVar(shape=(V,))
    s = 1 - 2 * b  # spin-valued expression

    problem += jm.sum((1 - s[u] * s[v]) / 2 for u, v in E)
