Pangkalahatang-ideya ng mga teknik sa noise management

Maraming teknik ang available para bawasan ang epekto ng noise sa iyong mga quantum workload. Nagbibigay ang mga tool at kakayahang ito ng mga teknik ng error mitigation at suppression na direktang nai-integrate sa iyong development workflow, habang awtomatikong nag-a-apply ang IBM Quantum® Compute Service ng mga advanced na estratehiya sa error mitigation kapag isinusumite ang mga job para patakbuhin. Inililista ng pahinang ito ang lahat ng available na tool at feature sa parehong opsyon para matulungan kang piliin ang tamang paraan para pamahalaan ang noise.

Puwede ka ring magbasa ng isang set ng mga paliwanag na bumubuod kung paano gumagana ang ilan sa mga teknik na ito sa seksyong Explanations ng pahinang ito.

Mga pangkalahatang teknik sa noise management​

Qiskit Mitigation
Bumuo ng mga custom na error mitigation pipeline gamit ang mga teknik tulad ng Probabilistic Error Cancellation (PEC), Zero-Noise Extrapolation (ZNE), Twirled Readout Error eXtinction (TREX), at Probabilistic Error Amplification (PEA) nang direkta gamit ang Samplomatic.

Directed execution model

Mga teknik para sa error suppression​

Gamitin ang mga kakayahang ito para bawasan ang circuit depth o supilin ang noise habang nag-e-execute. Karaniwang may kasamang mas mataas na sampling overhead ang mga teknik na ito.

Dynamical decoupling
Naglalagay ng mga pulse sequence sa mga idling qubit para supilin ang mga coherence error na dulot ng hindi gustong interaksyon ng mga qubit habang pinapatakbo ang circuit. Kino-configure gamit ang Qiskit SDK o ang IBM Quantum Compute service.

Pamahalaan ang noise para sa expectation value estimation​

Gamitin ang mga sumusunod na tool at kakayahan sa loob ng IBM Quantum Compute service para pamahalaan ang noise kapag bumubuo ng mga quantum workload na nag-e-estimate ng mga expectation value ng mga observable.

Probabilistic error cancellation (PEC)
Nagbabalik ng unbiased na estimate ng expectation value, kapalit ng mas malaking overhead kaysa sa ibang teknik tulad ng ZNE. Ine-extrapolate nito ang output ng ideal na circuit sa pamamagitan ng pagpapatakbo ng iba't ibang noisy na circuit instance. Mababawasan ang sampling cost sa paggamit ng shaded lightcones package na nasa pahina ng noise modeling.

Zero Noise Extrapolation (ZNE) with gate folding
Teknik ng error mitigation na kumukuha ng expectation value sa iba't ibang antas ng noise, at pagkatapos ay tinatantya ang ideal na resulta sa pamamagitan ng pag-extrapolate ng mga noisy na resulta ng expectation value patungo sa zero-noise limit. Kino-configure gamit ang Qiskit Mitigation o ang IBM Quantum Compute service.
Basahin ang paliwanag →
ZNE with Probabilistic error amplification (PEA)
Teknik ng ZNE na nagpapatakbo muna ng mga preliminary experiment para matutunan ang twirled noise model ng circuit, at pagkatapos ay ginagamit ang model na ito para magsagawa ng mas tumpak na error amplification. Kino-configure gamit ang Qiskit Mitigation o ang IBM Quantum Compute service.
Basahin ang paliwanag →
Twirled readout error extinction (TREX)
Bawasan ang epekto ng mga measurement error sa pamamagitan ng random na pagpapalit sa mga ito ng twirled na measurement sequence. Kino-configure gamit ang Qiskit Mitigation o ang IBM Quantum Compute service.

Propagated noise absorption (PNA)
Teknik para bawasan ang mga error sa mga expectation value ng observable sa pamamagitan ng 'pag-absorb' ng mga inverse ng natutunang noise channel sa isang observable gamit ang Pauli propagation.

Mga paliwanag sa mga teknik sa noise management​

Ang mga teknik ng error mitigation at error suppression ay maaaring magpabuti ng kalidad ng resulta kapag nagpa-scale up sa mas malalaking workload. Nagbibigay ang mga sumusunod na seksyon ng mga high-level na paliwanag sa mga teknik ng error suppression at error mitigation na available sa Qiskit at sa IBM Quantum Compute Service.

Bagong execution model, nasa beta release na

Available na ang beta release ng bagong execution model. Ang directed execution model ay nagbibigay ng mas maraming flexibility kapag kina-customize ang iyong error mitigation workflow. Tingnan ang gabay na Directed execution model para sa karagdagang impormasyon.

Dynamical decoupling​

Ang mga quantum circuit ay isinasagawa sa IBM hardware bilang mga sequence ng microwave pulse na kailangang i-schedule at patakbuhin sa tiyak na mga agwat ng oras. Sa kasamaang palad, ang mga hindi gustong interaksyon sa pagitan ng mga qubit ay maaaring humantong sa mga coherent error sa mga idling qubit. Gumagana ang dynamical decoupling sa pamamagitan ng paglalagay ng mga pulse sequence sa mga idling qubit upang halos kanselahin ang epekto ng mga error na ito. Ang bawat na-insert na pulse sequence ay katumbas ng isang identity operation, ngunit ang pisikal na presensya ng mga pulse ay may epekto ng pag-suppress ng mga error. Maraming posibleng pagpipilian ng mga pulse sequence, at kung aling sequence ang mas mabuti para sa bawat partikular na kaso ay nananatiling isang aktibong larangan ng pananaliksik.

Tandaan na ang dynamical decoupling ay pangunahing kapaki-pakinabang para sa mga circuit na naglalaman ng mga puwang kung saan ang ilang qubit ay idle nang walang anumang operasyon na kumikilos sa kanila. Kung ang mga operasyon sa circuit ay napakadense, kung kaya't ang lahat ng qubit ay abala karamihan sa oras, ang pagdaragdag ng mga dynamical decoupling pulse ay maaaring hindi mapabuti ang performance. Sa katunayan, maaari pa nitong mapasama ang performance dahil sa mga kakulangan ng mismong mga pulse.

Ang diagram sa ibaba ay naglalarawan ng dynamical decoupling gamit ang isang XX pulse sequence. Ang abstract circuit sa kaliwa ay nima-map sa isang microwave pulse schedule sa kanang tuktok. Ang kanang ibaba ay naglalarawan ng parehong schedule, ngunit may isang sequence ng dalawang X pulse na ipinasok sa panahon ng idle period ng unang qubit.

Maaari mong i-enable ang dynamical decoupling sa mga sumusunod na paraan:

  • Ang dynamical decoupling transpiler pass sa Qiskit
  • Ang dynamical decoupling option kung gumagamit ng IBM Quantum® Estimator o Sampler

Pauli twirling​

Ang twirling, na kilala rin bilang randomized compiling, ay isang malawakang ginagamit na teknik para sa pag-convert ng mga arbitrary na noise channel sa mga noise channel na may mas tiyak na istraktura.

Ang Pauli twirling ay isang espesyal na uri ng twirling na gumagamit ng mga Pauli operation. Mayroon itong epekto ng pag-transform ng anumang quantum channel sa isang Pauli channel. Kapag ginawa nang mag-isa, maaari nitong mapagaan ang coherent noise dahil ang coherent noise ay may tendency na mag-accumulate nang quadratically kasabay ng bilang ng mga operasyon, samantalang ang Pauli noise ay nag-a-accumulate nang linearly. Ang Pauli twirling ay madalas na pinagsama sa iba pang mga teknik ng error mitigation na mas gumagana sa Pauli noise kaysa sa arbitrary na noise.

Ang Pauli twirling ay isinasagawa sa pamamagitan ng pag-sandwich ng isang piniling hanay ng mga gate gamit ang mga random na piniling single-qubit Pauli gate sa paraang nananatiling pareho ang ideal na epekto ng gate. Ang resulta ay ang isang circuit ay pinapalitan ng isang random na ensemble ng mga circuit, lahat ay may parehong ideal na epekto. Kapag nagsa-sample ng circuit, ang mga sample ay kinukuha mula sa maraming random na instance, hindi lang sa iisa.

Dahil karamihan sa mga error sa kasalukuyang quantum hardware ay nagmumula sa mga two-qubit gate, ang teknik na ito ay madalas na inilalapat nang eksklusibo sa mga (native) two-qubit gate. Ang sumusunod na diagram ay naglalarawan ng ilang Pauli twirl para sa mga CNOT at ECR gate. Ang bawat circuit sa loob ng isang hilera ay may parehong ideal na epekto.

Maaari mong i-enable ang Pauli twirling sa mga sumusunod na paraan:

  • Isang Pauli twirling custom pass sa Qiskit
  • Ang mga twirling option kung gumagamit ng IBM Quantum Estimator o Sampler

Twirled Readout Error eXtinction (TREX)​

Ang Twirled Readout Error eXtinction (TREX) ay nagpapagaan ng epekto ng mga measurement error para sa pagtatantya ng mga expectation value ng Pauli observable. Batay ito sa konsepto ng twirled measurements, na naaabot sa pamamagitan ng random na pagpapalit ng mga measurement gate ng isang sequence ng (1) isang Pauli X gate, (2) isang measurement, at (3) classical bit flip. Tulad ng sa standard gate twirling, ang sequence na ito ay katumbas ng isang simpleng measurement kung walang noise, tulad ng inilalarawan sa sumusunod na diagram:

Sa presensya ng readout error, ang measurement twirling ay may epekto ng pag-diagonalize ng readout-error transfer matrix, na ginagawang madaling i-invert. Natututunan ang isang rescaling term mula sa diagonal noise channel sa pamamagitan ng benchmarking ng mga random circuit na na-initialize sa zero state. Maaaring alisin ng serbisyo ang bias mula sa mga expectation value na nagmumula sa readout noise. Ang pagtatantya ng readout-error transfer matrix ay nangangailangan ng pagpapatupad ng karagdagang mga calibration circuit, na nagdudulot ng maliit na overhead.

Maaari mong i-enable ang TREX sa mga sumusunod na paraan:

  • Gamit ang Qiskit Mitigation
  • Ang measure_mitigation option kung gumagamit ng IBM Quantum Estimator
  • Ang resilience level kung gumagamit ng IBM Quantum Estimator

Extrapolation ng zero-noise (ZNE)​

Ang Zero-noise extrapolation (ZNE) ay isang teknik para mapagaan ang mga error sa pagtatantya ng mga expectation value ng mga observable. Habang madalas nitong pinapabuti ang mga resulta, hindi garantisado na makakagawa ito ng walang bias na resulta.

Ang ZNE ay binubuo ng dalawang yugto:

  1. Noise amplification: Ang orihinal na quantum circuit ay isinasagawa nang maraming beses sa iba't ibang antas ng noise. (Magagawa ito gamit ang gate folding o probabilistic error amplification.)

  2. Extrapolation: Ang ideal na resulta ay tinatantya sa pamamagitan ng pag-extrapolate ng mga maingay na resulta ng expectation value patungo sa zero-noise limit. (Karaniwan gamit ang exponential o polynomial.)

Ang parehong noise amplification at extrapolation na yugto ay maaaring ipatupad sa maraming iba't ibang paraan. Bilang default, ang IBM Quantum Compute ay nagpapatupad ng noise amplification sa pamamagitan ng "digital gate folding," na nangangahulugang ang mga two-qubit gate ay pinapalitan ng mga katumbas na sequence ng gate at ang inverse nito. Halimbawa, ang pagpapalit ng isang unitary UUU ng UU†UU U^\dagger UUU†U ay magbubunga ng noise amplification factor na 3. Para sa extrapolation, maaari kang pumili mula sa isa sa ilang functional form, kasama ang linear fit o exponential fit. Ang larawan sa ibaba ay naglalarawan ng digital gate folding sa kaliwa, at ang extrapolation procedure sa kanan.

Ang overhead ng pamamaraang ito ay nag-e-scale kasabay ng bilang ng mga noise factor. Ang mga default na setting ay nagsa-sample ng expectation value sa tatlong noise factor, na humahantong sa halos 3x na overhead.

Maaari mong i-enable ang ZNE sa mga sumusunod na paraan:

  • Gamit ang Qiskit Mitigation
  • Ang zne_mitigation option kung gumagamit ng IBM Quantum Estimator
  • Ang resilience level kung gumagamit ng IBM Quantum Estimator

ZNE na may Probabilistic Error Amplification (PEA)​

Isa sa mga pangunahing hamon sa ZNE ay ang tumpak na pag-amplify ng noise na nakakaapekto sa target na circuit. Ang gate folding ay nagbibigay ng madaling paraan para maisagawa ang amplification na ito, ngunit maaaring hindi tumpak at maaaring humantong sa maling mga resulta. Tingnan ang artikulong "Scalable error mitigation for noisy quantum circuits produces competitive expectation values" (partikular ang pahina 4 ng supplementary information) para sa mga detalye. Nagbibigay ang probabilistic error amplification ng mas tumpak na diskarte sa error amplification sa pamamagitan ng noise learning.

Ang PEA ay isang mas sopistikadong teknik na nagsasagawa ng mga paunang eksperimento upang muling itayo ang noise at pagkatapos ay ginagamit ang impormasyong ito upang maisagawa ang isang tumpak na amplification. Nagsisimula ito sa pag-aaral ng twirled noise model ng bawat layer ng mga entangling gate sa circuit bago sila patakbuhin. Pagkatapos ng learning phase, ang mga circuit ay isinasagawa sa bawat noise factor, kung saan ang bawat entangling layer ng mga circuit ay pine-amplify sa pamamagitan ng probabilistic na pag-inject ng single-qubit noise na proporsyonal sa kaukulang natutunan na noise model. Tingnan ang artikulo "Evidence for the utility of quantum computing before fault tolerance" para sa karagdagang detalye.

Ang PEA ay binubuo ng tatlong yugto:

  1. Learning: Natututunan ang twirled noise model ng bawat layer ng mga entangling gate sa circuit.
  2. Noise amplification: Ang orihinal na quantum circuit ay isinasagawa nang maraming beses sa iba't ibang noise factor.
  3. Extrapolation: Ang ideal na resulta ay tinatantya sa pamamagitan ng pag-extrapolate ng mga maingay na resulta ng expectation value patungo sa zero-noise limit.

Para sa mga eksperimento sa utility-scale, ang PEA ay madalas na pinakamainam na pagpipilian.

Dahil ang PEA ay isang teknik ng noise amplification para sa ZNE, kailangan mo ring i-enable ang ZNE. Maaari mong i-enable ang PEA at ZNE sa mga sumusunod na paraan:

  • Gamit ang Qiskit Mitigation
  • Ang zne_mitigation option na may pea bilang amplifier kung gumagamit ng IBM Quantum Estimator
Kinakailangan ang noise learning

Kung ginagamit mo ang bagong client-side Estimator na ipinakilala sa qiskit-ibm-runtime v0.50.0, kailangan ng hiwalay na noise-learning job para magamit ang PEA. Tingnan ang Mag-migrate mula sa server-side patungo sa client-side na Sampler at Estimator para sa karagdagang impormasyon.

Probabilistic na pagkansela ng error (PEC)​

Ang Probabilistic error cancellation (PEC) ay isang teknik para mapagaan ang mga error sa pagtatantya ng mga expectation value ng mga observable. Hindi tulad ng ZNE, nagbabalik ito ng walang bias na tantya ng expectation value. Gayunpaman, sa pangkalahatan ito ay nagdudulot ng mas malaking overhead.

Sa PEC, ang epekto ng isang ideal na target circuit ay ipinahayag bilang isang linear combination ng mga maingay na circuit na aktwal na maisasagawa sa practice:

Oideal=∑iηiOnoisy,i\mathcal{O}_{\text{ideal}} = \sum_{i} \eta_i \mathcal{O}_{noisy, i}Oideal​=i∑​ηi​Onoisy,i​

Ang output ng ideal na circuit ay maaaring muling gawin sa pamamagitan ng pagpapatupad ng iba't ibang maingay na circuit instance na kinuha mula sa isang random na ensemble na tinukoy ng linear combination. Kung ang mga coefficient na ηi\eta_iηi​ ay bumubuo ng isang probability distribution, maaari itong gamitin nang direkta bilang mga probabilidad ng ensemble. Sa practice, ang ilan sa mga coefficient ay negatibo, kaya bumubuo sila ng isang quasi-probability distribution sa halip. Maaari pa rin itong gamitin upang tukuyin ang isang random na ensemble, ngunit may sampling overhead na kaugnay sa negativity ng quasi-probability distribution, na nailalarawan ng dami

γ=∑i∣ηi∣≥1.\gamma = \sum_{i} \lvert \eta_i \rvert \geq 1.γ=i∑​∣ηi​∣≥1.

Ang sampling overhead ay isang multiplicative factor sa bilang ng mga shot na kinakailangan upang matantya ang isang expectation value sa isang partikular na katumpakan, kumpara sa bilang ng mga shot na kakailanganin mula sa ideal na circuit. Nag-e-scale ito nang quadratically kasabay ng γ\gammaγ, na nag-e-scale naman nang exponentially kasabay ng depth ng circuit.

Maaari mong i-enable ang PEC sa mga sumusunod na paraan:

  • Gamit ang Qiskit Mitigation
  • Ang pec_mitigation option kung gumagamit ng IBM Quantum Estimator
