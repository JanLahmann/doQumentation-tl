Constrained Quantum Optimizer - Isang Quantum Function ni Aqarios

Tingnan ang sanggunian sa API

tala

Ang IBM Quantum® Functions ay isang beta feature na available lamang sa mga user ng IBM Quantum Premium Plan, Flex Plan, at On-Prem (sa pamamagitan ng IBM Quantum Platform API) Plan. Maaaring magbago ang mga beta feature.

Pangkalahatang-ideya​

Sa Constrained Quantum Optimizer ni Aqarios, malulutas mo ang mga constrained binary optimization problem sa IBM® quantum hardware nang walang manual reformulation at circuit mapping. Sapat nang magbigay ng problema bilang LP file, MPS file, o Luna Model. Awtomatikong inaasikaso ng function ang reformulation, circuit synthesis, transpilation, at hardware execution. Ginagamit ng solver ang iterative warm-starting [1] ng FlexQAOA algorithm, isang constraint-native extension ng Quantum Approximate Optimization Algorithm (QAOA).

Tinatarget ng optimizer ang mga binary problem na may constraints. Sa partikular, ang one-hot constraints at set-packing constraints ay maaaring i-enforce nang natively gamit ang XY-mixers. Ang ibang uri ng constraint ay awtomatikong nire-reformulate bilang penalty terms.

Mga sinusuportahang uri ng variable

Discrete na mga problema lang ang nalulutas ng function. Ang bawat decision variable ay dapat binary, o integer na may tahasang lower at upper bound, para ma-encode ito sa mga qubit. Hindi sinusuportahan ang mga continuous (real-valued) na variable: ang modelong may ganoon ay tinatanggihan gamit ang error code na 4710.

Deskripsyon​

Paalala

Maaaring depende ang performance sa parehong problem instance at sa mga susunod na processing step. Sa ilang kaso, ang classical samples at quantum-generated samples ay maaaring magkaroon ng magkatulad na final solution quality matapos ang equivalent post-processing. Kaya dapat isaalang-alang ng evaluation ang kabuuang optimization workflow.

Ipinapatupad ng Constrained Quantum Optimizer ang Iterative warm-start XY-mixer QAOA (IWS-QAOA) [1]. Pinapatakbo ng algorithm ang fixed-angle QAOA circuits sa quantum hardware at ina-update ang paunang warm-start probabilities ng bawat circuit gamit ang measurement outcomes mula sa nakaraang iteration. Walang kinakailangang variational parameter training; sa halip, isang fixed linear ramp parametrization ang ginagamit.

Sa paggamit ng XY-mixers para i-enforce ang one-hot constraints, malaki ang maipapabuti mo sa solution quality ng mga constrained problem, dahil praktikal na nababawasan ang search space patungo sa mas maliit na feasible subspace — at walang idinadagdag na komplikasyon, dahil sa penalty terms, sa optimization landscape.

Daloy ng Gawain​

Inilalarawan sa ibaba ang daloy ng gawain ng function:

  1. Preprocessing: Bago ang circuit synthesis, sinusuri ng optimizer ang constraint structure ng input problem:

    • Graph preprocessing: Kapag naaangkop sa problema, sinusuri ito bilang graph, kung saan tinutukoy ng mga edge ang relasyon sa pagitan ng mga variable. Ang graph analysis na ito ay nagbibigay-daan sa dalawang preprocessing enhancement. Una, ang mga single constraint ay maaaring pagsamahin sa isang malaking constraint gamit ang clique merging, para irepresenta ang mga ito ng iisang XY-mixer. Pangalawa, ang mga variable na may iisang neighbor lamang ay maaaring i-fix nang deterministiko, na binabawasan ang laki at komplikasyon ng problema.

    • Constraint resolution: Inaasikaso ng preprocessor ang bawat constraint nang hiwalay: Kung ang constraint ay one-hot constraint, maaari itong i-enforce sa pamamagitan ng XY-mixers. Kung ito ay set-packing constraint, iko-convert muna ito sa one-hot constraint. Ang equality constraints ay inaasikaso sa pamamagitan ng quadratic penalties, at ang inequality constraints sa pamamagitan ng unbalanced penalization.

    • Penalty derivation: Ang mga constraint na hindi maipapahayag bilang one-hot equality constraints ay kino-convert sa penalty terms. Awtomatikong kinukuha ng optimizer ang penalty strength batay sa structure ng problema.

  2. Iterative warm-starting: Pinapatakbo ng optimizer ang maraming parallel warm-start chains. Ang bawat chain ay may hawak na probability distribution sa mga variable assignment, na ginagamit bilang starting probability ng QAOA circuit (warm-start state). Sa bawat iteration, kumukuha ang chain ng samples mula sa quantum circuit, nag-aaplay ng classical postprocessing, at ina-update ang distribution nito batay sa paglitaw ng mga sample. Sa magkakasunod na iteration, tinutuunan nito ang paghahanap sa mga high-quality solution nang walang variational optimization loop.

Ang bilang ng chains (num_parallel), ang total shot budget kada chain (total_shots), at ang bilang ng QAOA repetitions (reps) ang pangunahing mga kontrol para sa pagbabalanse ng solution quality laban sa runtime.

Mga Benchmark​

Ipinapakita ng mga benchmark sa ibaba na kayang makahanap ng Constrained Quantum Optimizer Quantum Function ng high-quality at feasible na mga solusyon para sa constrained optimization problem na may higit na higit sa 100 binary variable. Ang accuracy ay ang ratio ng nakitang objective value sa kilalang optimum. Ang runtime ay ang wall-clock time mula sa pag-invoke ng function hanggang sa paghahatid ng resulta. Ang QPU usage ay ang billable Quantum Compute time.

Dalawang problema ang sinuri: ang Maximum Independent Set (MIS) problem at ang Max-kkk-Cut, na isang extension ng kilalang MaxCut problem sa higit sa dalawang kategorya. Ang Max-kkk-Cut ay katumbas din na optimization problem ng graph coloring decision problem (kapag naputol ang lahat ng edge, ang graph ay kkk-colorable).

Mga Tala sa Benchmark​

  • Ang mga resulta sa itaas ay nakuha gamit ang ibm_marrakesh Heron r2 processor na may default options at naka-enable ang use_session. Para sa sloane_2dc_128 instance, ginamit ang total_shots=12500.

  • Ang nabawasang bilang ng qubit para sa mga MIS instance (74 at 124 kumpara sa 128 at 186 na variable) ay resulta ng variable fixing sa preprocessing.

  • Ang mga problem instance para sa MIS ay kinuha mula sa Quantum Optimization Benchmarking Library. - Ang instance para sa Max-kkk-Cut problem ay ang Zachary Karate Club graph, na may chromatic number na 5.

Tungkol sa QPU time​

Malaki ang epekto ng mga napiling option, ng bilang ng warm-start iteration, at ng mga shot sa QPU time na kailangan ng isang function run. Sa mga default option, mas kaunti nang malaki ang QPU time na kailangan ng function kaysa sa standard QAOA, dahil gumagamit ito ng iterative warm-starting sa halip na variational parameter training loop sa QPU.

Bilang halimbawa, pinaghambing ang dalawang paraan sa ibm_phoenix gamit ang mga Maximum Independent Set instance na tumutugma sa function size na M at L. Ang isang standard QAOA workflow ay nangailangan ng humigit-kumulang 130 at 200 segundo ng QPU time, ayon sa pagkakasunod. Ang function na may default option ay nangailangan ng humigit-kumulang 30 segundo sa parehong kaso. Iba ang magiging resulta para sa ibang problema at setting.
