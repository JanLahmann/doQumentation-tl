I-set up ang QCSC-Prefect sa isang Slurm cluster

Inihahanda ng gabay na ito ang login node ng isang Slurm cluster bilang workflow host ng qcsc-prefect. Ang qcsc-prefect SQD tutorial ay nagsisimula sa resulta ng gabay na ito.

Pagkatapos mong kumpletuhin ang gabay na ito, mayroon ka ng mga sumusunod na item:

ItemSaanNilalaman
~/venv/qcsc-hostLogin node, ang workflow hostPrefect, ang mga qcsc-prefect package, at ang command na qcsc-qrmi
~/venv/qcsc-nodeMga compute node, sa loob ng mga Slurm jobAng QRMI worker: QRMI kasama ang command nitong task_runner, at qcsc-prefect-qiskit
qrmi-runtimePrefectAng block na nagpapangalan sa iyong IBM Quantum® instance at QPU
qrmi_config.jsonLogin node at mga compute nodeAng iyong IBM Cloud® API key, mga instance, at mga backend para sa QRMI

Patakbuhin ang bawat command sa isang terminal sa login node, maliban kung iba ang sinasabi ng hakbang.

Mga Kinakailangan​

  • Isang Slurm cluster na may OpenMPI, PMIx, at ang QRMI SPANK plugin, na ini-install ng administrator ng cluster. Inilalarawan ng mga sumusunod na gabay ang mga component na ito:

    • Quantum resource management interface (QRMI)

    • SPANK plugin para sa QRMI

    • Gabay ng user sa SPANK plugin

  • Isang home directory at isang work directory na nakikita ng login node at ng mga compute node sa parehong absolute path

  • Outbound HTTPS access sa GitHub, PyPI, IBM Quantum, at Prefect Cloud mula sa login node, at sa IBM Quantum mula sa mga compute node

  • Isang IBM Quantum Platform account na may IBM Cloud API key at kahit isang instance

  • Isang Prefect Cloud account, o isang Prefect server na ikaw ang nagho-host

  • Git, mga C at C++ compiler, CMake, BLAS, LAPACK, at MPI sa cluster, para sa mga solver build ng tutorial

tala

Ginagamit ng mga halimbawa ang Slurm partition na normal at ang mga compute node na c1 at c2. Palitan ang mga ito ng mga pangalan sa cluster mo.

Hakbang 1: Mag-log in sa login node​

# Run in a terminal on your computer.
ssh <user>@<login-node>

Hakbang 2: I-install ang uv​

I-install ang uv package manager, at suriin ang installation:

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv --version

Hakbang 3: Itakda ang mga path at gawin ang work directory​

Gumagamit ang gabay na ito at ang mga tutorial ng dalawang environment variable:

VariableHalimbawaLayunin
QCSC_PREFECT$HOME/qcsc-prefectAng qcsc-prefect checkout
QCSC_WORK_DIR/shared/work/qcsc-prefectAng work directory ng mga solver job at mga QRMI job

Dapat nasa storage ang parehong path na nakikita ng mga compute node sa parehong absolute path. Kung walang /shared directory ang cluster mo, pumili ng ibang shared path.

Itakda ang mga variable, at gawin ang work directory. Itakda muli ang mga variable sa bawat bagong shell bago ka sumunod sa isang tutorial:

export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR=/shared/work/qcsc-prefect
mkdir -p "$QCSC_WORK_DIR"

Para awtomatikong itakda ang mga variable sa bawat bagong shell, idagdag ang mga ito sa ~/.bashrc:

# Optional
echo "export QCSC_PREFECT=$QCSC_PREFECT" >> ~/.bashrc
echo "export QCSC_WORK_DIR=$QCSC_WORK_DIR" >> ~/.bashrc

Hakbang 4: I-clone ang qcsc-prefect​

I-clone ang repository, at i-check out ang isang release tag, halimbawa v0.3.1:

git clone https://github.com/qiskit-community/qcsc-prefect.git "$QCSC_PREFECT"
cd "$QCSC_PREFECT"
git checkout v0.3.1

Hakbang 5: Gawin ang workflow environment​

Gawin ang workflow environment gamit ang Python 3.12, at i-activate ito:

uv venv ~/venv/qcsc-host -p 3.12
source ~/venv/qcsc-host/bin/activate

I-install ang mga qcsc-prefect package. Pinapanatili ng opsyong --no-deps ang eksaktong version pin sa pagitan ng mga package ng checkout. Ini-install ng tutorial ang workflow mismo:

cd "$QCSC_PREFECT"
uv pip install --no-deps \
  -e packages/qcsc-prefect-core -e packages/qcsc-prefect-adapters \
  -e packages/qcsc-prefect-blocks -e packages/qcsc-prefect-executor \
  -e 'packages/qcsc-prefect-qiskit[slurm]'

Tiyaking available ang mga command:

which prefect qcsc-qrmi

I-activate ang ~/venv/qcsc-host sa bawat bagong shell sa login node.

Hakbang 6: Mag-log in sa Prefect​

Mag-log in sa Prefect Cloud. Piliin ang Paste an API key, i-paste ang Prefect Cloud API key, at piliin ang iyong workspace:

prefect cloud login

Tingnan ang koneksyon. Ipinapakita ng output ang PREFECT_API_URL at ang iyong workspace:

prefect config view
Opsyonal: gamitin ang sarili mong Prefect server

Laktawan ang tala na ito kung gumagamit ka ng Prefect Cloud. Para gamitin ang sarili mong Prefect server sa halip na Prefect Cloud, sundan ang How to run and access a Prefect server on a Slurm login node, at itakda ang address ng server mo kapalit ng <server-host>:

# Optional: only for your own Prefect server
prefect config set PREFECT_API_URL=http://<server-host>:4200/api

Hakbang 7: I-store ang mga IBM Quantum credential​

Patakbuhin ang qcsc-qrmi login pagkatapos ng Prefect login, dahil sine-save nito ang qrmi-runtime block:

qcsc-qrmi login

Sagutin ang mga prompt:

  1. I-paste ang IBM Cloud API key mo. Hindi ipinapakita ang key.

  2. Pindutin ang Enter para gamitin ang lahat ng instance.

  3. Ilagay ang numero ng default instance, 1 sa sumusunod na halimbawa.

  4. Ilagay ang numero o pangalan ng default backend, 4 (ibm_kingston) sa sumusunod na halimbawa.

Nagpi-print din ang command ng tala tungkol sa mga compute node at mga linyang [qrmi] para sa sqd_blocks.toml, na nilaktawan ng halimbawa (...). Hindi mo kailangan ang mga linyang [qrmi], dahil binabasa ng workflow ang instance at ang backend mula sa qrmi-runtime block.

Ang command na qcsc-qrmi ay may mga sumusunod na subcommand:

CommandLayunin
qcsc-qrmi loginI-store ang API key, ang mga instance, at ang mga backend, at i-save ang block
qcsc-qrmi refreshHanapin muli ang mga instance at backend gamit ang naka-store na key
qcsc-qrmi listI-print ang mga instance at backend, nang walang key
qcsc-qrmi checkTiyaking magagamit ng instance ng block ang backend nito

I-install ang file sa mga compute node​

Binabasa ng SPANK plugin ang qrmi_config.json sa bawat compute node, mula sa path sa plugstack.conf, kadalasan /etc/slurm/qrmi_config.json. Hilingin sa administrator ng cluster mo na i-install ang ~/.qiskit/qrmi_config.json mo sa path na iyon. I-install itong muli pagkatapos ng bawat qcsc-qrmi login o qcsc-qrmi refresh.

Panatilihin ang Session Mode ng qrmi-runtime block sa batch, dahil kinukuha ng SPANK plugin ang QPU sa batch mode.

Hakbang 8: Gumawa ng compute-node environment​

Tumatakbo ang QRMI worker sa isang compute node, sa sarili nitong environment. Gawin ito mula sa parehong checkout. Pinapanatili ng opsyong --python na aktibo ang ~/venv/qcsc-host:

cd "$QCSC_PREFECT"
uv venv ~/venv/qcsc-node -p 3.12
uv pip install --python ~/venv/qcsc-node/bin/python "qrmi[ibm]"
uv pip install --python ~/venv/qcsc-node/bin/python -e packages/qcsc-prefect-qiskit

Ibinibigay ng package na qrmi[ibm] ang command na task_runner. Idinadagdag ng tutorial ang SQD compilation hook sa environment na ito, at ginagamit ang ~/venv/qcsc-node/bin/python bilang python_executable ng sqd_blocks.toml.

Tingnan ang mga naka-store na instance at backend. Hindi kailanman ipi-print ng command ang key:

qcsc-qrmi list
# Output
API key: set
premium-instance (premium, us-east) (default): ibm_boston, ibm_chicago, ibm_fez, ibm_kingston, ibm_marrakesh, ibm_phoenix, ibm_pittsburgh
open-instance (open, us-east): ibm_fez, ibm_kingston, ibm_marrakesh

Tiyaking magagamit ng default instance ang default backend:

qcsc-qrmi check
# Output
premium-instance (premium, us-east) can use ibm_kingston.

Tiyaking nagpapatakbo ang Slurm ng job sa dalawang compute node, kasama rin sa PMIx:

srun -N2 hostname
srun -N2 --mpi=pmix hostname
# Output of each command
c1
c2

Tingnan ang compute-node environment at ang work directory sa isang compute node. Walang ipi-print ang unang command kapag matagumpay ang mga import:

srun -N1 ~/venv/qcsc-node/bin/python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker"
srun -N1 ls ~/venv/qcsc-node/bin/task_runner
srun -N1 ls -ld "$QCSC_WORK_DIR"
