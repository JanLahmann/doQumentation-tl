Parity Twine Optimizer: Isang Qiskit Function ni ParityQC

Tingnan ang sanggunian sa API

tala

Ang Qiskit Functions ay isang experimental feature na available lamang sa mga user ng IBM Quantum® Premium Plan, Flex Plan, at On-Prem (sa pamamagitan ng IBM Quantum Platform API) Plan. Nasa preview release status pa ito at maaaring magbago.

Pangkalahatang-ideya​

Ipinapahintulot ng Parity Twine Optimizer sa mga user na lutasin ang mga optimization problem gamit ang quantum computers sa pamamagitan ng Parity Twine method. Ang approach na ito, na binuo sa ibabaw ng Parity Architecture, ay gumagamit ng ParityQC compiler para bawasan ang gate counts at circuit depth na kinakailangan para magpatakbo ng quantum algorithm habang isinasaalang-alang ang device connectivity.

Ang pagbawas na ito sa resource ay nagbibigay-daan sa paglutas ng mga optimization problem na mahalaga sa industriya para sa mga sukat na hindi kayang lutasin ng standard, SWAP-heavy, transpilation methods. Inaawtomatiko ng Parity Twine Optimizer ang mga transpilation step at maaaring gamitin nang minimal ang input ng user.

Nauunahan ng Parity Twine approach ang lahat ng ibang compilation method sa pagbawas ng gate counts at circuit depths para sa mga quantum algorithm tulad ng quantum approximate optimization algorithm (QAOA) at quantum Fourier transform (QFT). Sa pamamagitan ng pag-abstract ng quantum information palayo sa physical qubits, naipapatupad ang non-local interactions nang walang SWAP gates. Sa halip, ang Parity Twine chains (mga sequence ng CNOT gates) ay sistematikong ipinamamahagi ang logical parity information sa pagitan ng mga qubit.

Ginagamit ng optimizer ang QAOA para bawasan ang energy ng ibinigay na cost function. Ang QAOA ay isang hybrid quantum-classical variational algorithm na dinisenyo para lutasin ang combinatorial optimization problem sa pamamagitan ng pagtantiya sa ground state ng cost Hamiltonian (HCH_CHC​). Ang mixing term (HBH_BHB​) ay nagtutulak ng mga transition sa pagitan ng mga estado para tuklasin ang solution space. Ang alternating sequence ng mga terminong ito, na kinokontrol ng mga parameter na γ\gammaγ at β\betaβ, ay tumutukoy sa unitary U(γ,β)=Πi=1pe−iβiHBe−iγiHCU(\gamma, \beta) = \Pi_{i=1}^p e^{-i \beta_i H_B} e^{-i \gamma_i H_C}U(γ,β)=Πi=1p​e−iβi​HB​e−iγi​HC​, na kumikilos sa paunang estado.

Ang pag-encode ng problem unitary, exp(−iβHC)-i \beta H_C)−iβHC​)), ay nangangailangan ng pag-encode ng lahat ng logical nnn-body rotation operators (exp(−iβJi,j,...nZiZj...Zn-i \beta J_{i,j,...n}Z_iZ_j...Z_n−iβJi,j,...n​Zi​Zj​...Zn​)). Maaari itong maisagawa gamit ang nnn-body generators (Parity Twine Networks), na binabawasan ang QAOA circuit depth at two-qubit gate count.

Deskripsyon​

Binubuo ang input ng Parity Twine Optimizer ng optimization problem, ang napiling pangalan ng IBM Quantum hardware, at karagdagang optional arguments para i-tailor ang mga setting ng transpilation at hardware execution. Ina-route ng optimizer function ang problem definition papunta sa Parity Twine Compiler. Ipinapakita ng Figure 1 ang buod ng function workflow.

Ang input optimization problem ay pre-processed papunta sa isang (normalized) Hamiltonian. Pagkatapos ay bumubuo ang ParityQC compiler ng parameterized Parity Twine ansatz circuit, na tine-transpile papunta sa logical ansatz na tumutugma sa native gate set ng napiling hardware.

Ang QAOA circuit parameters ay classically optimized gamit ang "efficient depth one" approach at inilalapat sa transpiled circuit. Dahil isang round lang ng QAOA ang ginagamit, ang optimal na γ\gammaγ at β\betaβ parameters ay nakukuha gamit ang grid search sa CPU nang hindi na kailangan ng magastos na iterative optimization sa maraming circuit call. Malaki ang naitutulong nito sa pagbawas ng kinakailangang QPU runtime ng optimizer. Ang execution time kada circuit ay pangunahing tinutukoy ng constant overhead sa pagpapatakbo ng job sa QPU. Matapos itakda ang circuit parameters, isinusumite ang job sa itinalagang IBM® QPU.

Ang raw results ay pagkatapos post-processed. Ginagamit ng hakbang na ito ang local greedy search na umuulit nang random sa solution string at binabaligtad ang bit values kung ito ay nagpapababa sa value ng cost function.

Mga Benchmark​

Paalala

Maaaring depende ang performance sa parehong problem instance at sa mga susunod na processing step. Sa ilang kaso, ang classical samples at quantum-generated samples ay maaaring magkaroon ng magkatulad na final solution quality matapos ang equivalent post-processing. Kaya dapat isaalang-alang ng evaluation ang kabuuang optimization workflow.

Modelo ng Sherrington-Kirkpatrick​

Ipinapakita ng Figure 2 ang pagiging epektibo ng Parity Twine Optimizer. Inihahambing nito ang mga resultang nakuha gamit ang optimizer laban sa random sampling para sa Sherrington-Kirkpatrick model sa pagdami ng mga qubit.

Ang post-processing ng parehong random at optimizer results ay humahantong sa eksaktong ground states, ngunit ang raw minimum energy output mula sa Twine QAOA ay palaging mas mahusay kaysa sa random na values. Para sa pinakamalaking bilang ng qubit na isinaalang-alang (90 at 100), binababa ng hardware noise ang resulta ng optimizer kung saan ito bumabalik sa raw values na katumbas ng random sampling.

Tingnan ang tutorial na ito para sa introduksyon sa Sherrington-Kirkpatrick model at mga detalye kung paano ito lutasin gamit ang Parity Twine Optimizer.

Maximum Independent Set Problem​

Inihahambing ng Figure 3 ang mga resultang nakuha gamit ang Parity Twine optimizer laban sa random sampling para sa maximum independent set problem para sa mga piniling instance na kinuha mula sa QOBLIB - Quantum Optimization Benchmarking Library. Ang mga ito ay saklaw mula 18 (mammalia-kangaroo-interactions) hanggang 114 (es60fst03) qubit.

Para sa maliliit na instance, magkatulad ang raw Maximum Independent Set size results mula sa optimizer at random sampling, ngunit para sa mas malalaking instance, mas malaki ang naibibigay na resulta ng optimizer. Ang post-processing ng parehong random-sampled at optimizer results ay muling humahantong sa mga set size na tugma sa eksaktong values.

Magsimula​

Mag-authenticate gamit ang iyong IBM Quantum Platform API token at piliin ang Qiskit Function bilang:

# Added by doQumentation — required packages for this notebook
!pip install -q qiskit-ibm-catalog
from qiskit_ibm_catalog import QiskitFunctionsCatalog

# Authenticate and load the Qiskit Function
catalog = QiskitFunctionsCatalog(
    channel="ibm_quantum_platform",
)
function = catalog.load("parityqc/parity-twine-optimizer")

Halimbawa​

Maaaring ilapat ang Parity Twine Optimizer sa isang simpleng QUBO na halimbawa gaya ng sumusunod. Ang problema ay unang tinutukoy gamit ang dictionary:

problem = {"()": 3, "(0,)": 1, "(0, 1)": 2, "(1, 2)": -1}

Pagkatapos, dapat tukuyin ang variable type bilang binary o spin:

variable_type = "spin"

Tinutukoy nito ang objective function 3+s0+2s0s1−s1s23 + s_0 + 2 s_0s_1 - s_1s_23+s0​+2s0​s1​−s1​s2​ kung saan si∈{−1,1}s_i \in \{-1, 1\}si​∈{−1,1}.

Pumili ng backend. Halimbawa:

backend_name = "ibm_phoenix"

Gamitin ang catalog.backends() para makita ang listahan ng mga available na backend mula sa user account/instance.

Kung walang tinukoy na backend, ang least-busy backend (ang isa na may pinakakaunting pending jobs) ang awtomatikong napipili.

Kapag na-load na ang optimizer (tingnan sa nakaraan), maaari mo itong patakbuhin sa problema gamit ang default options:

function_job = function.run(
    problem=problem, variable_type=variable_type, backend_name=backend_name
)
print(f"Job ID: {function_job.job_id}")

Suriin ang job status gaya ng sumusunod:

# Monitor the job status
function_job.status()

Kunin ang mga resulta gaya ng sumusunod:

# Retrieve the job result if the status is DONE
result = function_job.result()

result

Ang solution dictionary ay tumutugma sa mga qubit na tinukoy sa problema (s0,s1s_0, s_1s0​,s1​, at s2s_2s2​) at ibinibigay ang kanilang optimized spin values.

Ang objective_value ay ang cost o energy ng optimization problem. Sinusukat nito ang kalidad ng solution.

Ang metadata ay nagbibigay ng impormasyon tungkol sa transpilation (two-qubit gate counts/depth, mga ginamit na gate, active qubits) at iba't ibang runtime para sa parehong quantum at classical compute time.

Bukod pa rito, ibinibigay ng metadata ang isang tingin sa internal workings ng algorithm. Makikita mo ang optimized variational parameters (beta at gamma) at masusuri kung paano bumuti ang distribution ng measured bitstrings matapos ilapat ang classical post-processing sa raw quantum results.

Lahat ng bitstrings sa result output ay maaaring i-map sa mga problem variable gamit ang variable_mapping. Halimbawa, maaari mong i-map ang 'solution_bitstring': '100' gamit ang 'variable_mapping': {'0': 0, '1': 1, '2': 2} papunta sa binary solution: {'0': 1, '1': 0, '2': 0}. Dahil nilulutas mo ang problema sa termino ng spin variables, kailangan mong ilapat ang binary to spin transformation (0 -> 1, 1 -> -1 ). Sa huli, dadating ka sa final solution 'solution': {'0': -1, '1': 1, '2': 1}.

Notes

Minamarkahan ng release na ito ang unang stable production version ng Parity Twine Optimizer Qiskit Function. Inaasahang ipapakilala ng mga susunod na release ang sumusunod:

  • mga pagpapabuti sa pre- at post-processing.
