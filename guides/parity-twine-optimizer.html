Parity Twine Optimizer ng ParityQC

Tingnan ang sanggunian sa API

tala

Ang IBM Quantum® Functions ay isang beta feature na available lang sa mga user ng IBM Quantum Premium Plan, Flex Plan, at On-Prem (sa pamamagitan ng IBM Quantum Platform API) Plan. Maaaring magbago ang mga beta feature.

Pangkalahatang-ideya​

Ipinapahintulot ng Parity Twine Optimizer sa mga user na lutasin ang mga optimization problem gamit ang quantum computers sa pamamagitan ng Parity Twine method. Ang approach na ito, na binuo sa ibabaw ng Parity Architecture, ay gumagamit ng ParityQC compiler para bawasan ang gate counts at circuit depth na kinakailangan para magpatakbo ng quantum algorithm habang isinasaalang-alang ang device connectivity.

Ang pagbawas na ito sa resource ay nagbibigay-daan sa paglutas ng mga optimization problem na mahalaga sa industriya para sa mga sukat na hindi kayang lutasin ng standard, SWAP-heavy, transpilation methods. Inaawtomatiko ng Parity Twine Optimizer ang mga transpilation step at maaaring gamitin kahit kaunti lang ang input ng user.

Nauunahan ng Parity Twine approach ang lahat ng ibang compilation method sa pagbawas ng gate counts at circuit depths para sa mga quantum algorithm tulad ng quantum approximate optimization algorithm (QAOA) at quantum Fourier transform (QFT). Sa pamamagitan ng pag-abstract ng quantum information palayo sa physical qubits, naipapatupad ang non-local interactions nang walang SWAP gates. Sa halip, ang Parity Twine chains (mga sequence ng CNOT gates) ay sistematikong namamahagi ng logical parity information sa pagitan ng mga qubit.

Ginagamit ng optimizer ang QAOA para bawasan ang energy ng ibinigay na cost function. Ang QAOA ay isang hybrid quantum-classical variational algorithm na dinisenyo para lutasin ang combinatorial optimization problem sa pamamagitan ng pagtantiya sa ground state ng cost Hamiltonian (HCH_CHC​). Ang mixing term (HBH_BHB​) ay nagtutulak ng mga transition sa pagitan ng mga estado para tuklasin ang solution space. Ang alternating sequence ng mga terminong ito, na kinokontrol ng mga parameter na γ\gammaγ at β\betaβ, ay tumutukoy sa unitary U(γ,β)=Πi=1pe−iβiHBe−iγiHCU(\gamma, \beta) = \Pi_{i=1}^p e^{-i \beta_i H_B} e^{-i \gamma_i H_C}U(γ,β)=Πi=1p​e−iβi​HB​e−iγi​HC​, na kumikilos sa paunang estado.

Ang pag-encode ng problem unitary, exp(−iβHC)-i \beta H_C)−iβHC​)), ay nangangailangan ng pag-encode ng lahat ng logical nnn-body rotation operators (exp(−iβJi,j,...nZiZj...Zn-i \beta J_{i,j,...n}Z_iZ_j...Z_n−iβJi,j,...n​Zi​Zj​...Zn​)). Maaari itong maisagawa gamit ang nnn-body generators (Parity Twine Networks), na binabawasan ang QAOA circuit depth at two-qubit gate count.

Deskripsyon​

Binubuo ang input ng Parity Twine Optimizer ng optimization problem, ang napiling pangalan ng IBM Quantum hardware, at karagdagang optional arguments para i-tailor ang mga setting ng transpilation at hardware execution. Ina-route ng optimizer function ang problem definition papunta sa Parity Twine Compiler. Ipinapakita ng Figure 1 ang buod ng function workflow.

Ang input optimization problem ay pre-processed papunta sa isang (normalized) Hamiltonian. Pagkatapos ay bumubuo ang ParityQC compiler ng parameterized Parity Twine ansatz circuit, na tine-transpile papunta sa logical ansatz na tumutugma sa native gate set ng napiling hardware.

Ang QAOA circuit parameters ay classically optimized gamit ang "efficient depth one" approach at inilalapat sa transpiled circuit. Dahil isang round lang ng QAOA ang ginagamit, ang optimal na γ\gammaγ at β\betaβ parameters ay nakukuha gamit ang grid search sa CPU nang hindi na kailangan ng magastos na iterative optimization sa maraming circuit call. Malaki ang naitutulong nito sa pagbawas ng kinakailangang QPU runtime ng optimizer. Ang execution time kada circuit ay pangunahing tinutukoy ng constant overhead sa pagpapatakbo ng job sa QPU. Matapos itakda ang circuit parameters, isinusumite ang job sa itinalagang IBM® QPU.

Pagkatapos, dumadaan sa post-processing ang raw results. Ginagamit ng hakbang na ito ang local greedy search na umuulit nang random sa solution string at binabaligtad ang bit values kung ito ay nagpapababa sa value ng cost function.

Mga laki ng function​

Bawat job ay tumatakbo sa isang laki: S, M, o L. Kung masyadong maliit ang laki, ire-reject ang job. Kung mas malaki ito kaysa sa kailangan, tatakbo ang job sa mas malaking compute profile kaysa sa hinihingi ng trabaho. Tingnan ang Function sizes para sa kung paano gumagana ang mga laki sa pangkalahatan.

Nanggagaling ang laki sa dalawang katangian ng model mo: kung ilan ang variable nito, at kung gaano kasiksik ang interaksyon ng mga ito, ibig sabihin, ang bahagi ng lahat ng pares ng variable na magkasamang lumalabas sa isang term ng objective o ng isang constraint.

Dapat pasok ang model sa parehong hangganan ng isang laki, kaya ang maliit pero mahigpit ang ugnayang model ay maaaring maging L: ang sampung variable na magkakaugnay lahat ay may density na 1.0. Pare-pareho ang mga hangganang ito para sa bawat optimization function, kaya ang isang laki ay may parehong hirap ng model kahit alin pa ang tawagin mo.

May dalawang bagay na mas nagpapataas ng density kaysa sa inaakala:

  • Ang term na higit sa dalawang variable ay nag-uugnay sa bawat pares ng mga ito. Ang term na may apat na variable ay nag-aambag ng lahat ng anim na pares.

  • Ang constraint ay binibilang bilang penalty na pumapalit dito sa hardware. Ang pag-square sa constraint ay nag-uugnay sa bawat pares ng variable dito, kaya ang one-hot constraint sa apat na variable ay nag-aambag din ng lahat ng anim na pares.

Ang default ay M, na ginagamit kapag walang hiniling na laki ang job.

Maaari mo ring basahin ang mapping mula mismo sa function gamit ang function.sizes_map, at ang default na laki gamit ang function.default_size. Sa Parity Twine Optimizer, bawat variable na lumalabas sa problem ay binibilang nang isang beses, at bawat quadratic term gaya ng "(0, 1)" ay nag-aambag ng isang pares. Ang model sa example ay may limang variable at isa sa sampung posibleng pares, isang density na 0.1, kaya kailangan nito ng S. Ang mga fully connected na model, gaya ng Sherrington-Kirkpatrick model o ang QUBO form ng market split problem, ay may density na 1.0 at laging nangangailangan ng L.

Patakbuhin ang sumusunod na calculator sa sarili mong model. Ang model lang ang binabasa nito at wala nang iba: walang job na isa-submit at walang nire-reserve, kaya puwede mo itong tawagin nang kasing dalas ng gusto mo habang binabawasan mo ang isang model patungo sa mas maliit na laki.

# Calculate the function size a model needs, before submitting it.
# Call ``calculate_function_size(problem)``: it returns "S", "M" or "L" and submits
# nothing. The size comes from the number of variables and how densely they interact.

import ast

from collections.abc import Iterator
from itertools import combinations
from typing import Any, Literal

from qiskit_addon_opt_mapper.problems import OptimizationProblem

Size = Literal["S", "M", "L"]
VariableType = Literal["spin", "binary"]
_ORDER = {"S": 0, "M": 1, "L": 2}

# Limits are provided by IBM
_SMALL_NUMVARS, _SMALL_DENSITY = 50, 0.1
_MEDIUM_NUMVARS, _MEDIUM_DENSITY = 100, 0.25

def calculate_function_size(
    problem: dict[str, float] | OptimizationProblem, **kwargs: Any
) -> Size:
    """Return the size ("S", "M" or "L") needed to run ``problem``."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def to_optimization_problem(
    problem: dict[str, float] | OptimizationProblem,
    problem_type: str = "",
    variable_type: VariableType = "binary",
) -> OptimizationProblem:
    """Convert the Parity Twine Optimizer ``problem`` input into an
    ``OptimizationProblem``.

    Args:
        problem: A dictionary {term: coefficient} where each term is a string
            version of a tuple of variable ids, for example
            {"()": 3, "(0,)": 1, "(0, 1)": 2}. An ``OptimizationProblem`` is
            returned unchanged.
        problem_type: The ``problem_type`` passed to the function, for
            example "mis".
        variable_type: Type of all variables, either "spin" or "binary".

    Returns:
        The parsed problem, as a minimization without constraints.
    """
    if isinstance(problem, OptimizationProblem):
        return problem

    if variable_type not in ("spin", "binary"):
        raise ValueError(
            f"Invalid variable type {variable_type!r}, expected 'spin' or 'binary'."
        )

    constant: float = 0
    linear_terms: dict[str, float] = {}
    quadratic_terms: dict[tuple[str, str], float] = {}
    variables: set[str] = set()

    for raw_term, coefficient in problem.items():
        try:
            parsed = ast.literal_eval(raw_term)
        except (ValueError, SyntaxError) as exc:
            raise ValueError(
                f"Invalid problem term {raw_term!r}: expected a tuple literal like '(0, 1)'."
            ) from exc
        if not isinstance(parsed, tuple):
            raise ValueError(
                f"Invalid problem term {raw_term!r}: expected a tuple literal like '(0, 1)'."
            )
        term = tuple(map(str, parsed))
        if len(term) == 0:
            constant = coefficient
        elif len(term) == 1:
            linear_terms[term[0]] = coefficient
        elif len(term) == 2:
            quadratic_terms[term] = coefficient
        else:
            raise ValueError(
                "Invalid problem term, only quadratic problems are "
                f"supported, higher-order term: {term}"
            )
        variables.update(term)

    model = OptimizationProblem()
    model.name = problem_type
    for variable in sorted(variables):
        if variable_type == "spin":
            model.spin_var(variable)
        else:
            model.binary_var(variable)

    model.minimize(
        constant=constant, linear=linear_terms, quadratic=quadratic_terms
    )
    return model

def _measure(
    problem: dict[str, float] | OptimizationProblem, **kwargs: Any
) -> dict[str, float]:
    """Return the number of variables and the interaction density."""
    model = to_optimization_problem(
        problem,
        problem_type=kwargs.get("problem_type", ""),
        variable_type=kwargs.get("variable_type", "binary"),
    )
    num_vars = model.get_num_vars()

    pairs = set()
    for term in _interactions(model):
        pairs.update(frozenset(pair) for pair in combinations(set(term), 2))

    max_pairs = num_vars * (num_vars - 1) // 2
    return {
        "num_vars": num_vars,
        "density": len(pairs) / max_pairs if max_pairs else 0.0,
    }

def _interactions(problem: OptimizationProblem) -> Iterator[tuple[int, ...]]:
    """Yield the variables of every term that couples two or more of them.

    A constraint contributes every variable in it, because on hardware it becomes
    a penalty whose square couples them all.
    """
    objective = problem.objective
    yield from objective.quadratic.to_dict()
    for expression in objective.higher_order.values():
        yield from expression.to_dict()

    for constraint in problem.linear_constraints:
        yield _constraint_support(constraint)
    for constraint in problem.quadratic_constraints:
        yield _constraint_support(constraint)
    for constraint in problem.higher_order_constraints:
        yield _constraint_support(constraint)

def _constraint_support(constraint: Any) -> tuple[int, ...]:
    """Return every variable appearing in a constraint's left-hand side."""
    variables = set(constraint.linear.to_dict())
    if hasattr(constraint, "quadratic"):
        for term in constraint.quadratic.to_dict():
            variables.update(term)
    if hasattr(constraint, "higher_order"):
        for expression in constraint.higher_order.values():
            for term in expression.to_dict():
                variables.update(term)
    return tuple(variables)

def _is_small(metrics: dict[str, float]) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return (
        metrics["num_vars"] <= _SMALL_NUMVARS
        and metrics["density"] <= _SMALL_DENSITY
    )

def _is_medium(metrics: dict[str, float]) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return (
        metrics["num_vars"] <= _MEDIUM_NUMVARS
        and metrics["density"] <= _MEDIUM_DENSITY
    )

Ang solution dictionary ay tumutugma sa mga qubit na tinukoy sa problema (s0,s1s_0, s_1s0​,s1​, s2s_2s2​, s3s_3s3​ at s4s_4s4​) at ibinibigay ang kanilang optimized spin values.

Bukod pa rito, nagbibigay ang metadata ng pasilip sa panloob na takbo ng algorithm. Makikita mo ang optimized variational parameters (beta at gamma) at masusuri kung paano bumuti ang distribution ng measured bitstrings matapos ilapat ang classical post-processing sa raw quantum results.
