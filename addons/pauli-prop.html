Pauli propagation

Ang pauli-prop package ay nagbibigay ng Rust-accelerated na Python interface para magsagawa ng Pauli propagation.

Ang Pauli propagation ay isang framework para tantiyahin ang ebolusyon ng mga operator sa Pauli basis sa ilalim ng aksyon ng iba pang operator, gaya ng mga gate ng quantum circuit at mga noise channel. Maaaring maging epektibo ang pamamaraang ito kapag inaasahang mananatiling sparse sa Pauli basis ang mga operator na kasangkot.

Maaaring gamitin ang mga subroutine sa package na ito para magpatupad ng mga error mitigation technique gaya ng lightcone shading [6] at propagated noise absorption [7], operator backpropagation [8] para sa pagbabawas ng circuit depth, at classical na simulation ng mga expectation value [1-5].

Pagsisimula​

Mayroong simpleng gabay para matulungan kang magsimula agad sa package na ito sa quickstart guide.

Mga halimbawa ng use case​

Maaaring gamitin ang Pauli propagation bilang mas mababang antas na engine para magpatupad ng iba't ibang technique. Ilan sa mga halimbawa kung saan ito ginamit ay:

  • Lightcone shading para bawasan ang sampling overhead ng probabilistic error cancellation (PEC) para sa pag-mitigate ng mga expectation value sa 1- at 2D na transverse field Ising model [6] [qiskit-addon-slc docs]

  • Pagsipsip ng impormasyon ng noise model sa isang target na observable para i-mitigate ang mga expectation value sa 2D na transverse field Ising model [7] [qiskit-addon-pna docs]

  • Pag-trim ng mga trailing gate para makabuo ng mga Trotter circuit na mas mababa ang depth para sa time-evolution ng 2D na spin model [8] [qiskit-addon-obp docs]

Teknikal na talakayan​

Mga detalye ng software​

  • Rust-accelerated na Python interface

  • Suporta para sa mga noisy na simulation [guide]

  • Kakayahang mag-truncate ng mga term habang nag-e-evolve batay sa absolute na coefficient tolerance, nakapirming bilang ng mga term sa nag-e-evolve na operator, o kombinasyon ng dalawa

  • Kakayahang magsagawa ng Pauli propagation sa parehong Schrödinger at Heisenberg framework

  • Bagong technique para tantiyahin ang conjugation ng isang Pauli-sum operator ng isa pang Pauli operator. Ang heuristic na implementasyong ito ay greedy na gumagawa ng mga kontribusyon sa product na inaasahang pinakamahalaga. Tingnan ang Appendix B ng [7] para sa karagdagang impormasyon.

  • Isang thread lang

Mga kinakailangan sa computation​

Ang gastos sa memory at oras ng mga Pauli propagation routine ay karaniwang tumataas ayon sa laki kung saan pinapayagang lumaki ang evolved na operator.

propagate_through_rotation_gates(): Habang pina-propagate ang Pauli operator sa Pauli basis sa ilalim ng aksyon ng sunud-sunod na NNN Pauli rotation gate ng isang MMM-qubit na circuit, tataas ang bilang ng mga term bilang O(2N)\mathcal{O}(2^N)O(2N) papunta sa maximum na 4M4^M4M natatanging Pauli component. Para makontrol ang paggamit ng memory, tina-truncate ang operator pagkatapos ilapat ang bawat gate, na nagdudulot ng kaunting error na proporsyonal sa laki ng mga coefficient ng mga na-truncate na term. Linear sa laki ng evolved na operator ang pangangailangan sa memory, at linear din ang pagtaas ng runtime sa parehong laki ng operator at bilang ng mga gate.

propagate_through_operator(): Kino-conjugate ang isang operator sa Pauli basis ng isa pa sa pamamagitan ng greedy na pag-ipon ng mga term sa sum, ∑i,j,kGi†OjGk\sum_{i,j,k}G^{\dagger}_iO_jG_k∑i,j,k​Gi†​Oj​Gk​, kung saan ang i,j,ki,j,ki,j,k ay mga sparse index sa Pauli basis. Sina-sort ng implementasyong ito ang mga coefficient sa bawat operator ayon sa pababang magnitude, pagkatapos ay hinahanap sa 3D index space ang mga term na may pinakamalalaking coefficient, simula sa origin (0,0,0)(0,0,0)(0,0,0), at iniipon ang mga triplet na (i,j,k)(i,j,k)(i,j,k) hanggang sa isang tinukoy na cutoff. Madalas na magagawang bale-wala ang oras na ginugugol sa paghahanap sa pamamagitan ng pagtaas ng search step size sa (i,j,k)(i,j,k)(i,j,k) space, na nagbibigay ng cubic na speedup para sa subroutine na ito. Sa aming profiling, malaking oras ang maaaring magugol sa pag-sort ng mga operator at pagsasagawa ng Pauli multiplication para buuin ang mga term sa bagong operator.

Patakaran sa Deprecation​

Sumusunod kami sa semantic versioning. Paminsan-minsan, maaari kaming gumawa ng mga breaking change para mapabuti ang karanasan ng user. Kung posible, itatago namin ang mga lumang interface at mamarkahan ang mga ito bilang deprecated, hangga't maaari silang magsabay sa mga bago. Idodokumento sa release notes ang bawat malaking pagpapabuti, breaking change, o deprecation.
